# 약해진 자리 판정 로직 (weak-slot-verdict, 2026-10-15)

홈 "오늘의 시청률" 카드의 진단·근거 문장이 수치와 서로 어긋나던 문제(ENA Play 수 9시 '나는SOLO그후사랑은계속된다' 사례)를 고치면서 만든 판정 규칙이다.
계산은 서버의 결정적 순수 함수(`src/lib/dashboard/weakSlotVerdict.ts`)가 하고, 문장은 그 결과만 쓴다. LLM·마트·마이그레이션은 쓰지 않는다.

## 1. 재현 사례와 실제 원인

2026-10-14 ENA Play 수 9시 방영(수도권 2049, 시청률 0.000):

| 같은 자리 직전 8회(최신순) | 값 | 프로그램 |
| --- | --- | --- |
| 10-07 | 0.02475 | 나는SOLO그후사랑은계속된다 |
| 09-30 | 0.05521 | 나는SOLO그후사랑은계속된다 |
| 09-23 | 0.00159 | 무한도전 |
| 09-16 | 0.03045 | 신병4사보타주 |
| 09-09 | 0.02041 | 신병4사보타주 |
| 09-02 | 0.04418 | 신병4사보타주 |
| 08-19 | 0.00085 | 무한도전 |
| 08-05 | 0.03183 | 풍향GO2사전모임 |

* 중앙값 0.0276, 기준선(중앙값×0.8) 0.0221 → 직전 8회 중 **3회**가 이미 기준선 아래.
* 이 프로그램의 같은 자리 방영은 2회뿐이라(3회 미만) 비교 대상이 "그 시간대의 모든 프로그램 8회"로 넓어져 있었다(기존 설계, 문구가 밝히지 않았음).

옛 문구의 결함 4가지:

1. **"중앙값의 0% 수준"** — 계산(0 ÷ 0.0276)은 맞지만 오늘·중앙값 숫자가 없고 비교 대상 구성(다른 프로그램 6회 포함)을 밝히지 않았다.
2. **"최근 8회 중 이번 한 번만 낮은 일시적 하락"** — 판정이 아니라 기본값(else)이었다. 직전 1회만 기준선 위이면 단발로 출력했고, 위 데이터처럼 8회 중 3회가 낮아도, 오늘이 중앙값보다 높아도 같은 문장이 나올 수 있었다.
3. **"최근 2주 같은 요일도 목표의 73% 수준이라 오늘만의 문제가 아닙니다"** — 프로그램이 아니라 **채널 전체** 시청률(전주·전전주 중 높은 쪽)인데 프로그램 문장 바로 뒤에 붙어 프로그램 얘기로 읽히고, 위 "일시적"과 충돌했다.
4. **"목표의 46% 달성 — … 가장 부진"** — 이 프로그램은 "같은 자리 중앙값 대비 손실(시청률 × 방영 분)이 가장 큰 자리"일 뿐 목표 미달 기여도는 계산된 적이 없는데 인과처럼 연결됐다.

## 2. 판정 (한 입력 → 한 판정)

`judgeWeakSlot(오늘, 직전 방영 시청률[최신순])` — 결측(null·NaN)은 비교에서 빼고 수를 따로 센다. 실제 시청률 0은 유효한 값이다.

| 상태 | 조건 |
| --- | --- |
| 판단 보류 | 오늘 값 없음 / 비교 3회 미만 / 중앙값 0 / 오늘은 낮은데 직전 방영 중 낮은 회차가 섞여 있고 직전 방영은 정상 |
| 기준선 위 | 오늘 > 중앙값 × 0.8 |
| 지속적 부진 가능성 | 비교 8회가 채워졌고, 최근 4회의 과반이 "그 이전 4회 중앙값×0.8" 아래이며 오늘도 그 아래 |
| 단기 부진 지속 | 직전 방영도 기준선(중앙값×0.8) 아래 |
| 일시적 하락 가능성 | 직전 방영이 모두 기준선 이상(낮은 회차 0) |

우선순위: 판단 보류(데이터 부족) → 기준선 위 → 지속적 → 단기 지속 → 일시적 → 그 밖(낮은 회차가 섞임)은 판단 보류.
공휴일·재방 자리·앞 프로그램 동반 하락·채널 전체 동반 하락·유지율 누수 같은 원인 후보는 기존 순서 그대로 위 판정보다 먼저 설명한다.

### 임계값 출처

새로 만든 값은 없다. 모두 `weakSlotRemedy`에 있던 값이다.

| 상수 | 값 | 기존 출처 |
| --- | --- | --- |
| `dropRatio` | 0.8 | 기존 `dropLine = 중앙값 × 0.8` |
| `lowDeviation` | −20% | 기존 `dev <= -0.2` (부동소수 오차를 피하려고 곱한 값끼리 비교) |
| `minSample` | 3 | 기존 `prior.length >= 3` |
| `persistentMinSample` | 8 | 기존 최근 8회 창 |
| `persistentLowShare` | 0.5(과반 초과) | 기존 `channelWide` 규칙의 과반 |
| `persistentRecent` | 4 | 위 8회 창의 절반(**유일한 파생 값**) |

### 왜 "그 이전 4회" 기준인가

같은 자리 8회 전체 중앙값은 부진이 길어지면 그 부진을 따라 내려가므로, 전체 중앙값 기준으로는 과반이 기준선 아래일 수 없다(수학적으로 불가능). 그래서 "지속적 부진"은 최근 구간이 이전 구간 수준 아래로 내려앉아 유지될 때만 올린다. 8회 내내 같은 낮은 수준이면 '낮아졌다'가 아니라 그 자리의 평소 수준으로 보며 부진을 단정하지 않는다(확인 사항 참고).

## 3. 문구

* ① 핵심 결과(헤드라인): `목표의 46% 달성 — 같은 자리 중앙값 대비 하락이 가장 큰 곳은 9시 '나솔사계'` — 목표 미달 기여도는 계산하지 않았으므로 인과를 쓰지 않는다.
* ② 객관적 근거: `오늘 0.0000, 같은 요일·시간대 최근 8회 중앙값 0.028.` + 판정 문장(비교 구성 포함) + 채널 전체 근거(`채널 전체는 전주·전전주 같은 요일도 목표의 73% 이하여서 목표 미달이 오늘만의 일은 아닙니다.`).
* ③ 조치: 기존 조치 분기(오늘이 기준선 위이면 "추가 관찰"만 추가).
* 오늘이 0이면 "0%"를 쓰지 않고 숫자로 보여 준다. 중앙값이 0이거나 표본이 부족하면 비율을 만들지 않는다.
* 제목은 헤드라인에만 두고 근거 문장에서 되풀이하지 않는다.
* 표시용 약칭: `나는SOLO그후사랑은계속된다` → `나솔사계`(`src/lib/programAlias.ts`). DB의 프로그램명·집계 키는 바꾸지 않는다.

## 4. 검증

`npm run test:weak-verdict` — 재현 사례, 10개 요구 시나리오(이번만 낮음·2주 낮음·다수 낮음·중앙값 0·결측·표본 8회 미만·중앙값 양호/2주 낮음·목표 낮음/중앙값 정상·기여도 미확인·반복 일관성), 경계(−20%·절반), 약칭.

## 5. 확인이 필요한 사항 (임의로 정하지 않음)

1. 위 기준(0.8배·8회·과반·4회)이 편성 PD의 "부진" 기준과 맞는지. 기존 값을 그대로 썼다.
2. ENA Play처럼 시청률이 0.0x대인 채널은 0.000과 0.02의 차이가 측정 잡음일 수 있다. 채널별 최소 유효 시청률 기준이 없어 판정에 넣지 않았다.
3. 프로그램의 목표 미달 기여도(시청률 × 방영 분 ÷ 채널 격차)는 정의가 없어 계산하지 않았다. 정의가 정해지면 "기여했다"는 표현을 쓸 수 있다.
4. 채널 전체 근거는 전주·전전주 중 높은 쪽(기존 정의)이다. 2주 평균으로 바꿀지는 업무 정의 확인이 필요하다.
5. 8회 내내 낮은 수준인 자리는 '기준선 위(평소 수준)'로 나온다. 절대 기준(예: 채널 평균 대비)을 둘지는 별도 요구사항이다.
