## 0. 요약

1. IPTV 셋톱 값은 **닐슨을 대신하지 않는 두 번째 잣대**다. 닐슨 판정 공식은 그대로 두고, 그 판정이 맞는지 확인하고 확신의 정도를 매기는 데 쓴다.
2. 자료는 묶음으로 오고 12월 말에 끊길 수 있다. 그래서 **매주 새로 봐야 의미가 있는 기능보다, 12월까지 배워서 끝난 뒤에도 남는 것**을 먼저 만든다. 남는 것은 보정 계수, 잡음 폭, 수명 곡선, 작품별 이력, 경쟁 충격 경험치다.
3. 닐슨에 없고 IPTV에만 있는 것은 네 가지다.
   - 표본이 커서 시청률이 낮은 채널도 안정적으로 잰다.
   - 경쟁 프로그램의 도달자와 1분 시청자가 있다.
   - 2024년 8월~12월 이력이 더 있다.
   - Asia UHD·SBS NEX·UXN이 있다.
4. 일정은 다섯 단계다.
   - 0단계 정비: 11월 둘째 주
   - 1단계 DB 기반: 11월 말
   - 2단계 검증 연구: 12월 중순
   - 3단계 화면 반영: 검증을 통과한 것만, 12월 하순
   - 4단계 마감·고정: 1월 초

## 3. 목표별 활용안

각 항목은 무엇을 묻는지, 어떻게 보는지, 무엇이 나오는지, 12월 이후에 무엇이 남는지로 정리했다.

### 3.1 편성 결과를 더 정확히 판단하기

**A1. 닐슨 잡음 폭 측정** (최우선)

- **질문**: 같은 프로그램이 같은 자리에서 연속 방영될 때 닐슨이 보이는 흔들림 가운데, 실제 변화는 얼마이고 패널 잡음은 얼마인가?
- **방법**:
  - 같은 방영 건을 닐슨과 IPTV로 짝지어 회차 간 변화 폭을 비교한다.
  - IPTV는 거의 움직이지 않았는데 닐슨만 크게 움직였다면, 그 차이를 잡음으로 본다.
  - 채널별, 타깃별, 시청률 구간별로 "이 정도 변화까지는 잡음" 폭을 낸다.
- **산출**: 채널별 잡음 폭 표를 만들고, 약한 자리 판정의 채널별 기준선(헛경보 억제)을 보강하는 근거로 쓴다.
- **남는 것**: 잡음 폭 계수. 닐슨만 있어도 계속 쓴다.

**A2. 판정 교차 확인**

- **질문**: 콘텐츠 적합도(STRENGTHEN/KEEP/WATCH/REPLACE/MOVE)와 약한 자리 판정을 IPTV 값에 똑같이 적용하면 같은 판정이 나오는가?
- **방법**: 같은 순수 함수(`src/lib/contentFit`, `judgeWeakSlot`)에 IPTV 방영 행을 넣어 판정을 따로 낸 뒤 비교한다. 서버 쪽 비교 함수로 만든다.
- **산출**:
  - 판정 옆에 "IPTV에서도 같은 방향 / 반대 방향 / IPTV 자료 없음" 표시를 붙인다. 점수는 바꾸지 않는다.
  - 채널별 일치율을 낸다. 반대 방향이 많은 채널은 판정 확신도를 낮게 표시하는 근거로 쓴다.
- **남는 것**: 채널별 일치율. 어느 채널에서 닐슨 판정을 덜 믿어야 하는지 알 수 있다.

**A3. 편성 변경 사후 검증**

- **질문**: 과거의 이동·교체가 실제로 그 자리를 좋게 만들었는가?
- **방법**: 편성 변경 전후 4주를 IPTV로 다시 잰다. 기존 「편성이동 사후결과」 자료와 대조한다. 2024-08부터 이력이 있어 사례 수가 늘어난다.
- **산출**: 교체·이동 유형별 실제 효과 분포를 낸다. 예상 효과(+3~30%)를 현실적인 범위로 고치는 근거가 된다.
- **남는 것**: 교체·이동 효과 경험치.

### 3.2 프로그램 예측

**B1. 예측 오차 분해**

- **질문**: 예측 모델의 한 편당 상대 오차(현재 36~131%)는 모델이 틀려서 생기는가, 닐슨 값이 흔들려서 생기는가?
- **방법**: 같은 예측을 IPTV 실적과 비교했을 때의 오차를 닐슨 실적과 비교한 오차와 나란히 놓는다.
- **산출**: 채널별 "개선 가능한 오차"와 "줄일 수 없는 오차"를 나눈다. 예측 화면의 오차 범위 표기를 현실화하고, 개선 목표를 정하는 근거가 된다.
- **남는 것**: 채널별 오차 하한.

**B2. 수명 곡선 사전**

- **질문**: 장르·채널·시간대별로 회차가 진행될 때 시청률이 어떻게 오르내리는가?
- **방법**: 표본이 큰 IPTV로 회차 진행 곡선을 추정한다. 이를 닐슨 예측의 사전값으로 넣고, 넣은 예측과 넣지 않은 예측을 비교한다.
- **산출**: 예측 모델의 회차 보정 계수를 낸다. 단, 검증을 통과했을 때만 채택한다.
- **남는 것**: 곡선 계수 표.

**B3. 초반 신호**

- **질문**: 1~2회의 도달률과 체류율로 이후 평균을 미리 알 수 있는가?
- **방법**:
  - IPTV에서 관계를 찾는다.
  - 같은 관계가 닐슨 자사 reach(`ratings.reach`)로도 재현되는지 확인한다.
  - 닐슨으로 재현되는 규칙만 채택한다. 1월 이후에도 쓰려면 닐슨으로 재현되어야 하기 때문이다.
- **산출**: 신작 첫 주 조기 경보, 즉 "초반 이탈형" 또는 "입소문형" 표시.
- **남는 것**: 닐슨 reach로 쓰는 규칙.

**B4. 구매 작품 예상치**

- **질문**: 구매 검토 중인 작품이 다른 채널에서 방영될 때 성적이 어땠는가?
- **방법**:
  - 프로그램 키로 경쟁채널 방영 이력(2024-08~)을 찾는다.
  - 본방 채널과 재방 채널의 시청률, 도달, 체류를 모은다.
- **산출**: 구매 검토 화면에 "다른 채널 IPTV 성적" 블록을 둔다. 가격과 ROI는 계산하지 않는다.
- **남는 것**: 작품별 이력 사전. 이력 자체가 남는다.

### 3.3 프로그램 평가

**C1. 도달과 체류 지표**

- **정의**: 체류율 = 1분 시청자수 ÷ 도달자. 들어온 사람이 평균적으로 프로그램의 몇 %를 보았는지를 나타낸다.
- **해석 틀(2×2)**:

| | 체류율 높음 | 체류율 낮음 |
|---|---|---|
| 도달 많음 | 많이 오고 오래 봄 (확장 후보) | 많이 오지만 금방 나감 (초반 이탈, 구성·전개 점검) |
| 도달 적음 | 적게 오지만 충성 (알리기 문제, 홍보·편성 노출) | 둘 다 약함 (교체 검토) |

- **산출**: 주요 콘텐츠 리뷰 카드와 프로그램 성과 화면에 IPTV 보조 지표 블록을 둔다. 경쟁작과 같은 잣대로 비교할 수 있는 것은 IPTV뿐이다.
- **남는 것**: 장르별 체류율 기준값. 이후 닐슨 reach로 비슷한 틀을 쓸 수 있는지는 B3에서 확인한다.

**C2. 동급 비교**

- 같은 시간대·같은 유형의 경쟁 프로그램 가운데 우리 프로그램이 몇 번째 분위인지 본다.
- 경쟁 프로그램에는 장르 정보가 없다. 처음에는 시간대와 채널군 기준으로 비교한다.

**C3. 재방 효율**

- `<재>` 회차의 도달과 체류로 재방 자리의 가치를 잰다.
- `<재>` 표기는 TV INDEX 표기 그대로다. 본방·재방의 최종 판단은 기존 규칙(채널 첫 방송 = 본방)을 따른다.

### 3.4 경쟁 채널 대비 전략

**D1. 시간대 경쟁 지도**

- 요일×시간대마다 관측 채널별 IPTV 시청 규모를 보고, 그 자리의 주 경쟁자를 찾는다.
- 비중은 "관측 채널 합계 대비 비중"으로만 표기한다. 점유율이 아니라고 명시한다.

**D2. 경쟁 편성 충격**

- 경쟁 채널이 우리와 같은 시간대에 신작을 넣었을 때 우리 자리가 얼마나 빠지는지 본다.
- 2024-08 이후 이력에서 사례를 모은다.
- 사례가 30건 이상인 유형만 경험치로 쓴다.
- 이 경험치는 맞편성과 회피 편성 판단에 쓴다.

**D3. UHD 벤치마크**

- skyUHD와 UHD 5개 채널을 같은 기준으로 순위화하고 시간대별로 비교한다.
- 요일×시간대 평균(`iptv_tvindex_daypart_avg`)을 skyUHD 시간대 평가의 기준선으로 쓴다.

**D4. 빈자리 탐색** (조건부)

- 경쟁 시청 규모는 작은데 우리 장르가 강한 시간대를 찾는다.
- 경쟁 프로그램 장르 분류가 먼저 필요하다. 이번 계획에서는 뒤로 미룬다.

## 4. 단계별 실행 계획

일정은 겹쳐도 된다. 각 단계의 끝은 "다음 단계로 가도 되는가" 점검이다.

### 0단계 · 정비 (11/11 ~ 11/14)

| 할 일 | 산출 | 완료 기준 |
|---|---|---|
| 종료일이 다른 자사 파일 보완 요청 | 자료 요청서(§5) | 자사 7채널이 같은 날짜에 끝남 |
| 채널명 대응표: IPTV ↔ 닐슨 경쟁채널명(예: Dramacube ↔ DRAMAcube, KBS Joy ↔ KBS JOY) | 대응 테이블 1개 | 23개 전부 대응 |
| 닐슨 방영 건과 짝짓기: 날짜 + 시작 ±3분 + 프로그램 키 | DB 뷰 `iptv_nielsen_match` | 채널별 매칭률 보고, 자사 90% 이상 목표 |
| 자료 범위 표: 채널×타깃별 시작일·종료일 | DB 뷰 | 화면이 "자료 마지막 날짜"를 여기서 읽음 |
| 묶음 적재 절차 | 기존 스크립트로 주 1회 적재 + 적재 후 점검 쿼리 | 다시 넣어도 중복 없음 확인 |

적재 방식은 업로드 화면을 따로 만들지 않고 기존 스크립트를 쓴다. 받는 기간이 7주 정도뿐이라 화면을 만드는 비용이 더 크다.

### 1단계 · 측정 기반 DB (11/17 ~ 11/28)

모두 기존 테이블은 건드리지 않고 새로 추가한다.

| 객체 | 내용 |
|---|---|
| `iptv_airing_metrics`(뷰) | 방영 건별 체류율, 방영 길이, 회차 순번(프로그램 키 기준), 본방·재방 표기 |
| `iptv_program_summary`(함수) | 기간을 받아 프로그램×채널×타깃 요약(평균 시청률, 평균 도달, 체류율, 추세) |
| `iptv_slot_competition`(함수) | 기간을 받아 요일×시간대×채널 시청 규모와 관측 채널 대비 비중 |
| `iptv_calibration`(테이블, 버전 있음) | 채널×타깃×시간대별 닐슨 대비 비율과 잡음 폭. 12월 말에 최종본을 고정 |
| 점검 쿼리 | 매칭률, 결측, 종료일, 비율이 튀는 채널 |

### 2단계 · 검증 연구 (11/24 ~ 12/12)

화면에 올리기 전에 아래 질문에 데이터로 답한다. 과적합을 막기 위해 학습 기간(2024-08 ~ 2025-12)과 검증 기간(2026-01 ~)을 나눈다.

| 질문 | 채택 기준(넘으면 3단계로) |
|---|---|
| A1 잡음 폭 | IPTV의 회차 간 흔들림이 닐슨보다 뚜렷이 작은 채널에서만 잡음 폭을 기준선 근거로 씀 |
| A2 판정 일치 | 채널별 일치율을 산출함. 불일치 사례 10건을 뽑아 PD 검토용으로 제시함 |
| A3 사후 검증 | 유형별 사례 20건 이상일 때만 효과 범위를 제시함 |
| B1 오차 분해 | 결과를 보고만 하고 모델은 바꾸지 않음 |
| B2 수명 곡선 | 검증 기간에서 사전값을 넣은 예측의 오차 중앙값이 넣지 않은 예측보다 작을 때만 채택 |
| B3 초반 신호 | IPTV와 닐슨 reach 두 쪽에서 같은 방향으로 재현될 때만 채택 |
| D2 경쟁 충격 | 유형별 30건 이상일 때만 채택 |

산출은 연구 결과 문서 한 편(`docs/iptv/IPTV_RESEARCH_RESULTS.md`)이고 화면 변경은 없다. 원본 수치가 대외비이므로 Word 보고서가 필요하면 내부용으로만 만든다.

### 3단계 · 화면 반영 (12/1 ~ 12/23, 검증 통과 항목만)

우선순위는 다음과 같다(위에서부터). 모두 기존 화면에 작은 블록을 더하는 방식(delta-only)이다.

1. **프로그램 성과 화면과 주요 콘텐츠 리뷰에 IPTV 보조 블록(C1).** 도달, 체류율, 2×2 위치, 경쟁작 대비 분위를 보여 준다.
2. **콘텐츠 적합도·약한 자리에 "IPTV 교차 확인" 표시(A2).** 점수는 그대로 두고 표시만 붙인다.
3. **구매 검토에 "다른 채널 IPTV 성적"(B4).**
4. **skyUHD.**
   - 1페이지 IPTV 열을 6/1~ 기간 전체로 넓힌다.
   - UHD 벤치마크(D3)를 붙인다.
5. **경쟁채널 섹션에 시간대 경쟁 지도(D1).**
6. **주간·월간 보고서 템플릿에 IPTV 요약 한 단락.** 수치는 DB 값을 그대로 쓰고 LLM은 해석만 한다.

자연어 질의(`/api/ask`)에 IPTV 질의 유형을 추가하는 것은 1월 이후 자료가 끊길 가능성이 커서 보류한다.

### 4단계 · 마감·고정 (12/15 ~ 2027-01-09)

| 할 일 | 내용 |
|---|---|
| 마지막 묶음 수령 | 12/31까지의 자료 |
| 마감 전 일괄 확보 | 끊기기 전에 이력을 넓힌다(§5.3) |
| 계수 고정 | `iptv_calibration`, 잡음 폭, 수명 곡선, 경쟁 충격 경험치를 최종 버전으로 고정하고 출처 기간을 적는다 |
| 화면 종료 처리 | 자료 마지막 날짜 이후에는 IPTV 칸을 숨긴다. 이력 기반 블록(B4, C1 과거 회차)은 계속 보인다 |
| 회고 | 무엇이 쓸모 있었는지, 1월 이후 무엇이 남는지 문서화한다 |

## 5. 자료 요청 명세

### 5.1 정기 묶음

- 주기는 **주 1회(월~일 1주)를 권장**한다. 어려우면 2주 묶음도 된다. 월 단위로 받으면 12월까지 검증 기회가 두 번뿐이다.
- 형식은 이번과 같은 TV INDEX "프로그램 방영 성과" CSV이고, 파일명 규칙도 그대로 둔다. 스크립트가 파일명에서 채널을 읽는다.
- 범위가 줄어들면 아래 순서대로 줄인다(위가 필수).
  1. 자사 7채널 × 가구·2049
  2. ENA 직접 경쟁: tvN, JTBC, SBS Plus, MBC every1, E채널, tvN Story, SBS FunE, Dramax, Dramacube
  3. UHD 5개(가구)
  4. 나머지 지상파와 일반 경쟁
- skyUHD 주간 편성표와 편성 성과 인사이트는 월 1회면 충분하다.

### 5.2 1회성 보완

- ENA·ENA Drama·ENA Play 가구 11/1~, ENA·ENA Drama 2049 11/6~, ENA Play 2049 11/1~
- 가능하다면 경쟁채널 추가: TV CHOSUN, MBN, 채널A, tvN SHOW, JTBC2. 닐슨 경쟁채널 자료에는 있으나 IPTV에는 없다.
- TV INDEX에서 확인 부탁할 메뉴(있다면 우선순위가 올라감):
  1. 분 단위 시청률. 초반 이탈 시점을 볼 수 있다.
  2. 점유율
  3. 성·연령 세부 타깃
  4. 채널 간 유입·이탈의 집계값. 개인 단위 추적이 아닌 채널 합계만 받는다.

### 5.3 12월 마지막 묶음(끊기기 전 확보)

- 12/31까지의 정기 묶음
- 가능하면 2024-01 ~ 2024-07 이력. 수명 곡선과 계절성 표본이 늘어난다.
- 2049가 없는 경쟁 9곳의 2049
