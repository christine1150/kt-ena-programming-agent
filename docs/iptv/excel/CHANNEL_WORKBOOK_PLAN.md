# 채널별 종합 엑셀 계획 (2026-11-12 확정)

사용자 지시(2026-11-12): DB에 있는 자료로 채널 하나에 탭 하나씩 만든 종합 엑셀. 각 채널 탭에서 "어떤 타이틀이 얼마나 있는지"를 보는 것이 목적이다.

## 0. 확정된 결정

| 항목 | 결정 |
|---|---|
| 지상파·종편 | 자료가 있는 채널은 넣는다(UHD 뒤 "지상파·종편") |
| 엑셀 글꼴 | 맑은 고딕 |
| 에피소드 수 | DB에서 먼저 찾고, 모자란 것만 네이버 조회 |
| 네이버 조회 범위 | 종영했거나 전부 재방으로 표시된 타이틀 중 올해 방영 5회 이상만. 나머지는 DB 추정값에 "추정" 표시 |
| "ONE" | ONCE로 본다 |

## 2. 탭 순서

1. **종합** — 모든 채널 탭을 만든 뒤 맨 앞에 넣는다.
2. **자사 7개**: ENA → ENA Play → ENA Drama → ENA Story → OLIFE → ONCE → skyUHD
3. **국내드라마**(12개) → **예능**(15개) → **교양/취미레저**(CMC TV, ONT) → **UHD**(5개) → **지상파·종편**(10개)
   - 장르 안에서는 2049 중심 채널 먼저, 가구 중심 채널 나중. 같은 묶음 안에서는 닐슨 순위 순.
   - 가구 중심: D-ONE, 하이라이트TV, EDGE TV, CNTV, MBC ON, 교양/취미레저·UHD 전체.
   - 탭 이름 = 채널명(엑셀 금지 문자 `\ / ? * [ ] :`는 바꾸고 31자 이내).

## 3. 채널 탭 구성

| 행 | 내용 |
|---|---|
| 1 | 채널명 |
| 2 | 닐슨 수도권 2049·가구 누적 시청률과 216개 채널 중 순위, IPTV 2049·가구 평균과 순위, 장르 안 순위(가구) — 아는 것만 |
| 3 | 올해 방영 타이틀 수, 본방 기준 에피소드 수, 주요 본방 시간대(요일·시각), 전체 방영 시간 대비 본방 비율(%) |
| 4 | (빈 줄) |
| 5~ | 장르별 요약: 장르 / 타이틀 수 / 에피소드 수 / 방영 시간 비중 |
| (빈 줄) | |
| 이후 | 프로그램 표 |

**프로그램 표** — 채널 KPI 시청률 내림차순(2049 중심 채널은 2049, 가구 중심은 가구, 닐슨 없으면 IPTV). 열:

- 순위 · 프로그램명 · 장르 · 첫 방영일 · 마지막 방영일
- 올해 에피소드 수 · 총 회차(네이버) · 회차 근거(DB 본방 / 네이버 / 추정)
- 본방 시간 · 방영 횟수(전체 / 본방 / 재방) · 총 방영 시간(분)
- 닐슨: 2049 평균 · 가구 평균 · 2049 점유율 · 가구 점유율 · 세 번째 타깃 평균
- IPTV: 2049 평균 · 가구 평균 · 평균 도달률
- 합산 누적 시청률(방영 1회 시청률의 합, KPI 타깃·KPI 출처 기준)

닐슨과 IPTV 값은 열을 나누고 섞지 않는다. 값이 없으면 빈 셀(0과 구분).

## 4. 계산 규칙 (모두 스크립트가 계산)

- **방영 1회**: 26:00 경계에서 쪼개진 방영은 `src/lib/broadcastTime/boundarySplit.ts`의 공통 함수로 합친다.
- **같은 프로그램**: 닐슨 `norm_program_name`과 IPTV `program_key`를 같은 정규화 규칙으로 맞춘다. 맞지 않은 이름은 목록으로 뽑아 확인한다.
- **본방·재방**: 본방 = 각 채널의 첫 방송. `<재>` 표시·자사 `<본>` 표시를 쓰고, 표시가 없는 채널은 `program_naver_schedule` 본방 편성으로 보완한다. 다른 채널에서 먼저 방송했다고 재방으로 단정하지 않는다.
- **에피소드 수**(DB 우선):
  1. 자사는 `program_episode_counters` seed와 본방 방영 횟수.
  2. 경쟁은 본방 방영 횟수(같은 날 같은 프로그램 연속 방영은 1회로).
  3. 전부 재방 표시이거나 종영 타이틀 + 방영 5회 이상 → 네이버 총 회차 조회(예: 왕가네 식구들 → 50회). 조회 결과는 `program_naver_schedule`에 저장.
  4. 방영 횟수가 총 회차보다 많으면 총 회차를 넘지 않게 맞춘다.
  5. 나머지는 DB 추정값 + "추정" 표시.
- **평균 시청률**: 방영 1회 값의 단순 평균.
- **본방 비율**: 본방 방영 분 ÷ 전체 방영 분.
- **본방 시간**: 본방 방영이 가장 많은 요일·시작 시각(2개까지).
- **프로그램명**: 전체 이름, 띄어쓰기 있는 IPTV 표기 우선(없으면 닐슨 표기). ? ! 와 채널 접두어 제거.

## 5. 서식

- 글꼴 맑은 고딕. 줄바꿈 끔, 열 너비는 글자 수 기준, 긴 값은 "셀에 맞춤"으로 축소.
- 정렬: 글자(프로그램명·장르) 왼쪽, 수치 오른쪽, 순위·날짜·시간대·근거 가운데.
- 머리글 색: 닐슨 열 남색 계열(R60 G50 B225), IPTV 열 민트 계열.
- 프로그램 표 머리글 행과 프로그램명 열 틀 고정.
- **종합 탭**: 장르별 채널 × 보유 자료(닐슨 프로그램 단위 2049·가구·점유율, IPTV 2049·가구, 장르 분류, 네이버 회차)를 ●(있음) ◐(일부 기간) ✕(없음)으로, 옆에 타이틀 수·에피소드 수·KPI 순위.

## 7. 실행 순서

1. DB 집계 → 중간 JSON. 이름 불일치 목록·네이버 조회 대상 수를 확인한다.
2. 네이버 총 회차 조회(기존 `src/lib/broadcastPattern` 조회 기능 사용, 결과 DB 저장).
3. 엑셀 생성 → 줄바꿈·글자 잘림·탭 순서·정렬 점검.
4. 종합 탭 추가 → 파일 전달 → 전체 tsc 오류 0 확인 후 커밋·푸시.
