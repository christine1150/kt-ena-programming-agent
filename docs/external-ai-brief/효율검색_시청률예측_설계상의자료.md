작성: 2026-10-22 · 용도: ChatGPT·Gemini 등 외부 AI와 설계를 먼저 논의하기 위한 설명 자료

## 0. 이 문서를 받은 AI에게 (첫 메시지로 그대로 붙여 넣기)

> 아래 문서는 한국 케이블 방송사(KT ENA) 편성팀이 쓰는 사내 분석 웹앱의 현재 구조와, 새로 만들고 싶은 기능 2개에 대한 설명이야.
> 너는 **설계 검토자** 역할을 해 줘. 코드를 짜는 것보다 다음을 먼저 해 줘.
> 1. 기능 1(프로그램 효율 검색)과 기능 2(편성표 기반 시청률 예측·사후 리뷰·학습)의 **화면·데이터·계산 로직 설계안**을 제안해 줘.
> 2. 문서 6장·7장의 **열린 질문**마다 선택지와 추천안, 그 이유를 적어 줘.
> 3. 이미 있는 기능(4장)과 겹치거나 재사용할 수 있는 부분을 짚어 줘. 새로 만들기보다 기존 것을 확장하는 쪽을 선호해.
> 4. 2장의 **고정 원칙**을 어기는 제안은 하지 마. 어겨야 한다고 판단하면 그 이유를 따로 적어 줘.
> 5. 예측 방법을 제안할 때는 **데이터가 1~2년 분량이고 신규 프로그램이 많다**는 점을 감안해, 과적합 위험과 검증 방법(시간 순서 백테스트)을 같이 적어 줘.
> 답은 한국어로, 표를 적극적으로 써서 정리해 줘.

## 1. 배경

### 1-1. 회사와 사용자
- KT ENA는 케이블·IPTV 채널 7개를 운영한다. 사용자는 **편성 PD**(어떤 프로그램을 어느 요일·시간에 넣을지 정하는 사람)와 관리자다.
- 시청률 원천은 **닐슨코리아 일별 파일**(엑셀). 매일 아침 메일로 들어오며 자동 수집된다.

### 1-2. 채널과 핵심 지표(KPI)

| 그룹 | 채널 | 핵심 타깃(KPI) |
|---|---|---|
| A (2049 중심) | ENA, ENA Drama, ENA Play | 수도권 개인 20~49세 시청률 |
| B (가구 중심) | OLIFE, ONCE, ENA Story, skyUHD | 전국 유료방송가입가구 시청률 |

- 같은 프로그램이라도 채널 그룹에 따라 보는 지표가 다르다.
- 같은 프로그램이 **여러 채널에 동시에/순차로 방영**된다(예: ENA 본방 → ENA Play·ENA Drama 재방). 한 프로그램의 "채널별 성적"을 보는 수요가 여기서 나온다.

### 1-3. 방송 도메인 용어
- **본방**(첫 방송, 원본 파일 `<본>` 표시) / **재방**(`<재>`). 본방과 재방은 성과 기대치가 전혀 다르다.
- **슬롯**: 요일 × 시간대. 같은 프로그램도 슬롯에 따라 시청률이 크게 달라진다.
- 시청률(rating, %), 점유율(share, %), 도달률(reach), 시청시간(초), 시청시간 점유율, 일별 순위(rank)가 기본 지표다.
- 닐슨 일별 파일에는 **채널 단위 하루 시청률**과 **프로그램(방영) 단위 시청률**이 함께 있다.

## 2. 현재 시스템과 고정 원칙

### 2-1. 기술 스택
- Next.js 16(App Router, TypeScript) + Supabase(PostgreSQL) + Vercel 배포.
- LLM: OpenAI `gpt-4o` / `gpt-4o-mini`. 모든 응답은 JSON Schema 구조화 출력. 규칙 기반 대체 경로가 있다.
- 자연어 질의(`/api/ask`): 의도 분류(규칙 → 실패 시 LLM) → 승인된 DB 함수(RPC) 실행 → 근거 표 + 차트.

### 2-2. 고정 원칙 (설계 제안이 지켜야 함)
1. **숫자는 DB/서버 계산이 정답이다.** 시청률·점유율·지표 계산은 DB(SQL·RPC·마트) 또는 서버의 결정적 순수 함수가 한다. **LLM과 프런트엔드는 숫자를 계산하지 않는다.**
2. **LLM은 해석자다.** 검증된 숫자를 받아 해석·요약·의사결정 보조만 한다.
3. **환각 금지·임의 SQL 금지.** DB에 없는 수치를 추정하지 않는다. LLM이 SQL을 만들어 실행하지 않는다(승인된 API/RPC만).
4. **시간 표현은 KST 기준 오늘 날짜를 주입해 해석**한다("지난주", "최근 4주").
5. **기존 정상 동작 로직은 보존**하고 바꿀 부분만 정밀 수정한다.
6. 범위 밖: **ROI(비용·매출) 직접 계산**, 개인 패널 이동 추적, 외부 편성 시스템과의 실제 확정 연동.

### 2-3. 데이터 처리상 주의점
- **프로그램명 정규화**: 공백·쉼표·문장부호·회차 태그(`<본>`, `<재>`)를 제거한 정규화 이름(canonical name)으로 회차를 묶는다.
- **약칭/별칭**: 같은 콘텐츠가 긴 제목·짧은 제목으로 따로 들어오는 경우가 있어 별칭 사전(`programAlias`)으로 묶는다. 반대로 시즌이 다른 작품(예: 시즌3과 시즌4)은 별개로 취급하고, 필요한 경우만 수동 연결 목록으로 잇는다.
- **NULL과 0은 다르다.** 0은 유효한 측정값(새벽 시간대에 흔함), NULL은 측정 없음.
- **타깃 명칭이 시트마다 다르다**("수도권 개인2049" / "수도권 2049" / "개인2049") → 동의어 매핑으로 처리.
- **ENA Story**는 일부 기간 프로그램 단위 자료가 없다(채널 단위만 있음).
- **skyUHD**는 별도 수기 파일, 단위·소수 자릿수가 다르다.
- 공휴일은 학습·비교에서 따로 다룬다.

## 4. 이미 있는 관련 기능 (재사용 후보)

### 4-1. 콘텐츠 적합도 엔진 (`content-fit-v1`, 2026-10-14 재설계)
- 최근 12주 방영 행으로 프로그램별 판정 태그를 낸다: **STRENGTHEN / KEEP / WATCH / MOVE / REPLACE / TEST**.
- 점수 = ① **슬롯 대비 성과**(같은 요일·시간대 다른 프로그램 평균 대비 배율) 50% + ② **시청 규모**(채널 평균 방영 시청률 대비) 50%. 표본이 적으면 평균 쪽으로 보정. 몰입도·최근 추세는 −15~+10점 보정만.
- 판정 기준: 방영 3일 미만 보류, 8일 미만 TEST, 이후 슬롯 대비 성과 배율로 STRENGTHEN(≥1.5) / KEEP(≥0.85) / WATCH(≥0.55) / REPLACE(그 미만), 더 나은 시간대가 있으면 MOVE.
- 계산은 서버의 결정적 순수 함수(DB 원본 행을 읽음).
- 교훈: 예전 버전의 "타깃 선호도" 점수가 실제로는 30대 비중의 역수였던 사례가 있다 → **지표 정의가 의도와 맞는지 검증하는 절차가 중요**.

→ 기능 1의 "효율" 계산에 직접 재사용할 수 있는 후보.

### 4-2. AI 편성표 뽑기 ("시청률 자판기", `/ideal-schedule`)
- 채널·대상 주를 고르면, 최근 91일 자사 방영 기록으로 **슬롯별 기대 시청률**을 예측하고, 제약(필수 편성·잠금·직후 재방 규칙·반복 한도·방영권) 안에서 주간 편성안을 최적화해 제안한다.
- 모드: 기존 틀 유지(지난 편성 골격에 후보 배정) / AI 시간 최적화(5분 단위 격자).
- **기대 시청률 모델(현행)**: `기대값 = 지수(idx) × 슬롯 기준값(baseline)`
  - baseline: 채널 평균 → 시간 평균 → 요일×시간 평균으로 단계적 수축(k=4).
  - idx: 방영별 "실제 시청률 ÷ 그 슬롯 기준값" 비율의 가중합. 최근 28일 방영은 가중치 2.
  - 5단계 키(프로그램×본/재×요일×시 → 프로그램×시 → 프로그램 전체 → 장르×요일×시 → 장르×시)를 구체→일반으로 수축, 마지막은 채널 기준(지수 1).
  - 근거 등급 A/B/C(프로그램 자체 이력이 충분하면 A, 장르·채널 평균에 기대면 C).
  - 예상 범위(80%)는 과거 예측 오차의 분위수로 만든다(잔차 30건 미만이면 "검증 전").
- **이미 있는 검증 장치**
  - 백테스트: 지난 주를 그 시점에 알 수 있던 자료만으로 다시 예측해 실제와 비교.
  - 시간 순서 검증 하네스(rolling-origin, 튜닝/최종 holdout 분리, 데이터 마감 0/7/14일 민감도).
  - 모델 승격 판정 로직(합격선은 제안만 되어 있고 사용자 승인 대기).
- **알려진 한계**
  - 검증은 지금까지 **합성(가상) 데이터에서만** 했다. 실제 채널 데이터로는 아직 검증하지 않았다(승격 판정: "실제 자료 미검증").
  - 합성 검증에서 현행 모델은 단순 기준모델(같은 슬롯 최근 4주 평균 등)보다 MAE가 약 17% 낮았다. 단 **신규 프로그램·표본이 적은 프로그램은 어떤 방법도 개선되지 않았다.** 오차는 프라임 시간대(19~22시)에 몰린다.
  - "이번 안이 기존 대비 +N%"라는 개선율은 낙관적으로 부풀 수 있다(후보 중 최댓값을 고르는 선택 효과). 그래서 "같은 시간 기준" 비교로 바꾸고 경고를 띄운다.
  - 회차·시즌·계절·노출 간격 효과는 아직 검증하지 않았다.
  - 시즌이 바뀐 신작은 수동 "시리즈 연결" 목록으로 지난 시즌 첫 3회 평균 × 채널 수준 보정 비율에서 출발시킨다(근거 등급 C, "검증된 예측 아님" 표시).

→ 기능 2의 예측 엔진은 이걸 그대로 쓸지, 확장할지, 별도로 둘지가 핵심 질문이다.

### 4-3. 편성 비교 화면 (`/schedule-grid`)
- 주간 편성표 엑셀을 업로드하면 칸마다 실제 방영과 매칭(±60분)해 실제 시청률을 붙여 보여 준다. 요일별 시청률·순위 표시.
- → 기능 2의 "편성표 넣기" 입구로 재사용 가능.

### 4-4. 기타
- **구매 시뮬레이터**: 외부 프로그램을 사 왔을 때 슬롯별 예상치를 낸다(별도 모델 `purchase-v1.1`, 구간 포함).
- **시리즈 단위 예상 문서**: 지난 시즌 기준으로 새 시즌 예상치를 내는 1회성 스크립트가 있다(`forecast:series`).
- **프로그램 모멘텀 API**, **프로그램 정체성 검색 RPC**(`search_program_identity`, 별칭 포함).
- **판단 검토 기록**(`action_review_events`): 채택한 편성 판단에 "성과 평가일"을 걸어 둘 수 있다 → 사후 리뷰와 연결할 수 있는 고리.

## 5. 신규 기능 1 — 프로그램 효율 검색

### 5-1. 사용자 요구 (원문 취지)
> 예를 들어 "연애박사"를 검색하면, 시작한 이후 지금까지 또는 선택한 기간 안에서, 모든 채널 또는 선택한 채널에서 어떤 성적을 보이고 어떤 효율을 보이는지 **한눈에** 보이게 하는 검색 기반 효율 판단 기능.

### 5-2. 입력
- 프로그램명 검색(부분 일치·별칭·띄어쓰기 차이 허용, 시즌 구분)
- 기간: "첫 방송 이후 전체" 기본 + 직접 선택(최근 4주/12주/임의 기간)
- 채널: 전체 또는 선택(1개 이상)
- 타깃: 기본은 각 채널의 핵심 KPI, 바꿀 수 있음
- 본방/재방 필터

### 5-3. 보여 주고 싶은 것 (초안 — 확정 아님)
- **요약 카드**: 총 방영 횟수(본/재), 방영 채널 수, 평균 시청률, 최고·최저 회차, 현재 판정 태그(4-1)
- **채널별 비교 표**: 채널 × (방영 횟수, 평균 시청률, 슬롯 대비 성과 배율, 채널 평균 대비 배율, 점유율, 시청시간)
- **회차 추이 차트**: 회차(또는 방송일)별 시청률, 본방/재방 색 구분
- **슬롯 지도**: 요일×시간대별로 어디서 잘 됐는지
- **본방 → 재방 효율**: 재방이 본방의 몇 % 수준을 유지하는지, 몇 번째 재방부터 떨어지는지
- **비교 대상**: 같은 슬롯의 다른 프로그램, 같은 장르 평균, 직전 시즌

### 5-4. "효율"의 정의 — 가장 먼저 합의가 필요
비용(제작비·구매가)은 범위 밖이라 **비용 대비 효율은 계산하지 않는다.** 그렇다면 "효율"은 다음 중 무엇(또는 조합)인가:

| 후보 | 정의 | 장점 | 주의 |
|---|---|---|---|
| A. 슬롯 대비 성과 | 실제 ÷ 같은 요일·시간대 평균 | 시간대 유불리를 걸러 냄. 4-1에 이미 있음 | 슬롯 평균의 표본이 적으면 흔들림 |
| B. 채널 대비 규모 | 실제 ÷ 채널 평균 방영 시청률 | 직관적 | 프라임 시간대가 유리 |
| C. 편성 시간당 기여 | 시청률 × 방영 분 ÷ 채널 하루 총합 | 편성 시간 대비 채널 실적 기여 | 긴 편성이 유리해 보임 |
| D. 재방 효율 | 재방 평균 ÷ 본방 평균, 재방 횟수별 감쇠 | 재방 활용 판단에 직결 | 재방 슬롯이 대부분 비프라임이라 A와 함께 봐야 함 |
| E. 몰입도 | 시청시간 점유율, 도달 대비 시청시간 | 충성 시청층 판단 | 정의가 채널마다 다르게 읽힐 수 있음 |
| F. 목표 기여 | 채널 목표 시청률 대비 | 경영 지표와 연결 | 목표가 채널 단위라 프로그램 배분 규칙이 필요 |

### 5-5. 열린 질문 (기능 1)

## 6. 신규 기능 2 — 편성표 기반 시청률 예측 · 사후 리뷰 · 학습

### 6-1. 사용자 요구 (원문 취지)
> 편성표를 넣으면 그 주의 **일자별 및 주간 기대 시청률**을 예측하고, 나중에 그 예측이 맞았는지 **다시 리뷰**하며, 그걸 통해 기존 **AI 편성표 뽑기를 학습·고도화**하는 것이 목적.

### 6-2. 흐름 초안

```
① 편성표 업로드(다음 주 계획) ─→ ② 칸별 예측 + 일별·주간 집계
                                        │  (예측 시점·모델 버전·입력 지문과 함께 "고정 저장")
                                        ▼
③ 방송 후 실적 도착(닐슨 일별 자동 수집) ─→ ④ 예측 vs 실적 자동 대조(칸·일·주)
                                        │
                                        ▼
⑤ 오차 분석(어디서 왜 틀렸나) ─→ ⑥ 모델 보정 후보 → 검증 통과 시에만 승격
                                        │
                                        ▼
                    ⑦ AI 편성표 뽑기(4-2)가 개선된 모델을 사용
```

### 6-3. 세부 요구 (초안)
- **입력**: 기존 편성표 엑셀 양식(4-3과 같은 형식). 칸마다 프로그램명·시작 시각·본/재 태그.
- **칸별 예측**: 기대 시청률 + 예상 범위 + 근거 등급 + 근거 설명(어떤 과거 방영을 썼는지).
- **일별 예측**: 그날 채널 시청률 기대값. **주간 예측**: 그 주 채널 시청률 기대값, 가능하면 **예상 주간 순위**.
- **예측 고정 저장**: 나중에 모델이 바뀌어도 "그때 뭐라고 예측했는지"가 남아야 한다(수정 불가 기록, 모델 버전·데이터 마감일·입력 지문 포함).
- **사후 리뷰 화면**: 예측 vs 실적, 오차가 큰 칸 순위, 오차 원인 분류(신규 프로그램/편성 변경/특집·결방/경쟁 강세/공휴일/데이터 결측 등), 주별 정확도 추이.
- **학습·고도화**: 누적된 예측-실적 쌍으로 모델을 보정하되, 자동 반영이 아니라 **검증 통과 시 승격**.
