# 라인업 화면 UX 설계안 (정보 구조·상호작용·데이터 모델·확장성)

- 작성: 2026-11-24 (KST) · 작성 역할: UX 아키텍트 · 상태: **설계안(구현 전)**
- 대상 화면: 앱 안의 새 화면 `/lineup` ("라인업") — 지금 전역 메뉴의 외부 링크(편성센터 사이트)를 대신한다.
- 범위: 정보 구조, 보기 구성, 상호작용, 시각 규칙(모양·색의 뜻), 입력·갱신 흐름, 권한, 데이터 모델 초안, 인쇄·좁은 화면.
- 범위 밖: 실제 구현 코드, 최종 시각 디자인(색 값 확정·여백 수치 미세 조정은 디자이너), 마이그레이션 적용(사용자 승인 후).

> **대외비 규칙(이 문서 자체)**: 이 문서는 저장소에 커밋된다. 타사 미공개 작품의 제목·주연·제작사·로그라인은 쓰지 않았다.
> 예시는 모두 가명이다(`자사 드라마 A`, `타사 가 주말극 1` 등). 날짜도 설명용으로 지어낸 값이다.
> 원자료(`line-up/` 폴더)는 이미 `.gitignore`에 들어 있으며, 라인업 데이터는 git이 아니라 Supabase에만 저장한다.

## 0. 한눈에 보는 결론

1. 화면은 **보기 3개**(자사 라인업 · 경쟁 비교 · 목록) + 막대를 누르면 열리는 **상세 패널**로 만든다. 기본은 자사 라인업.
2. 행은 항상 **자리(요일+시각)** 가 최소 단위다. 자사는 `채널 묶음(A/B) > 채널 > 장르 자리 > 자리`, 타사는 `요일 묶음(월화/수목/주말) > 방송사 자리`.
3. 업계 종합본의 "구분 × 방송사" 틀을 경쟁 비교의 기본으로 쓰되, **토·일(금·토) 섹션에 두 번 나오는 같은 작품을 한 줄로 합치고**, 섹션마다 달랐던 주 날짜 머리를 **하나의 달력 축**으로 바꾼다.
4. 날짜를 아는 정도(정확일 / 주 단위 / 월 단위 / 첫 방송일만)를 **막대 모양으로 정직하게** 그린다. 모르는 날짜를 지어내지 않는다.
5. 편성 형태는 **모양으로** 구분한다: 연속 편성=막대, 월 1회=점 열, 단발·행사=마름모, 결방=빗금, 미정 자리=점선 빈 칸.
6. 잘린 글자는 "막대 안 → 막대 오른쪽 → 아래 줄 → 사람이 정한 줄임말" 순서로 자리를 찾고, 전체 이름은 상세·툴팁·화면 낭독기에서 항상 읽힌다.
7. 시간 축은 기본 **지난달 ~ 6개월 뒤(8개월)**, **화면 폭에 맞춤**(오른쪽 빈 공간 없음), 확대 4단계(주/월/분기/1년), 빨간 오늘선, 공휴일·행사 띠.
8. 입력은 **관리 화면(`/lineup/manage`)** 에서: 한 건 입력·수정·보관, 엑셀 업로드 4종(자사 양식·업계 종합본·방송사 단독 양식·표준 양식), 표 붙여넣기. 이미지 캡처는 사람이 붙여넣기 표에 옮겨 적는다(글자 인식·LLM 사용 안 함).
9. 모든 변경은 **변경 이력**에 남고, 업로드는 "미리보기 → 반영" 두 단계다(기존 경쟁 채널 편성 업로드와 같은 방식).
10. 데이터는 새 테이블 9개(`lineup_*`)로 분리하고 자사 채널은 기존 `channels.id`에 연결한다. RLS는 켜고 정책 없이 서버만 읽고 쓴다(기존 `competitor_airings`와 같은 방식).

## 1. 사용자가 이 화면으로 하는 일 (질문 목록과 우선순위)

사용자: 편성 PD(채널 담당), 편성센터(라인업 총괄), 보고 자료를 만드는 사람(인쇄).

| 순위 | 질문(사용자 말투) | 빈도 | 답하는 곳 |
|---|---|---|---|
| P1-1 | "지금 우리 자리마다 뭐가 방영 중이고 언제 끝나? 다음 작품은 언제 시작해?" | 매일·매주 | 자사 라인업(오늘선 기준) |
| P1-2 | "다음 분기 우리 월화 드라마 자리 비는 주는?" | 매주 | 자사 라인업의 **빈 주 표시** |
| P1-3 | "우리 신작 첫 방 주(와 방영 기간)에 타사 맞대결은?" | 작품마다 | 경쟁 비교 + **맞대결 초점** |
| P1-4 | "이번 달/다음 달 시작·종료 작품은?" | 매주(회의·홍보) | 목록 보기의 빠른 거르기 |
| P2-1 | "타사 상반기 주말극 흐름은?" | 월·분기 | 경쟁 비교(주말 묶음, 분기 확대) |
| P2-2 | "첫 방송·종영이 설·추석 연휴나 대형 중계와 겹치나?" | 작품마다 | 공휴일·행사 띠 + 세로 음영 |
| P2-3 | "이 작품 주연·연출·작가·제작사·회차 빨리 확인" | 수시 | 상세 패널 |
| P2-4 | "타사가 비우거나 미정인 주, 휴방하는 주는?" | 월 | 경쟁 비교(미정·휴방 모양) + 거르기 |
| P2-5 | "회의 자료로 출력" | 주·월 | 인쇄(A3 가로 / A4 가로) |
| P3-1 | "작년 같은 시기에 누가 어느 자리에 뭘 냈지?" | 분기 | 기간을 과거로(2025 상반기부터 이력) |
| P3-2 | "이 라인업 언제 기준이야? 지난번과 뭐가 바뀌었어?" | 수시 | 자료 기준 띠, 최근 변경 표시, 변경 이력 |
| P3-3 | "방영 중·끝난 작품 실제 성적은?" | 수시 | 상세 패널의 시청률 화면 링크(2단계: DB 값 표시) |
| P3-4 | "ENA Play·ENA Drama 등 다른 자사 채널 라인업도 같이" | 확장 시 | 자사 라인업의 채널 묶음 |

설계 판단: P1 네 가지를 **한 번의 클릭 안에서** 답할 수 있어야 한다. 그래서 기본 화면을 자사 라인업으로 두고, 빈 주를 기본으로 켜고, 막대마다 "맞대결 보기"를 바로 둔다. 목록 보기는 P1-4 전용 빠른 거르기를 맨 위에 둔다.

## 2. 화면 구성

### 2.1 경로와 전역 메뉴

| 항목 | 내용 |
|---|---|
| 보기 화면 | `src/app/lineup/page.tsx` + `layout.tsx`(시청률 표 `src/app/ratings/layout.tsx`처럼 `WorkspaceNav`를 위에 두는 표 중심 화면) |
| 관리 화면 | `src/app/lineup/manage/page.tsx` — `/admin` 아래에 두지 않는다. `proxy.ts`가 `/admin/*`을 관리자 세션 전용으로 막기 때문에, 나중에 편집 권한을 PD(편성자)에게 열 때 주소를 옮기지 않아도 되게 하려는 것이다. 권한 검사는 서버에서 `can(role, "lineup_edit")`로 한다. 관리(`/admin`) 화면에는 "라인업 자료 관리" 바로가기 카드만 둔다. |
| 전역 메뉴 | `GlobalNav.tsx`의 외부 링크(`lineupLink`, 보고서와 관리 사이, PD 계정에도 보임)를 내부 링크 `/lineup`으로 바꾼다. 위치·노출 규칙은 그대로. `nav.ts`의 `activeNavId`에 `/lineup` → 활성 표시, `COMPAT_ROUTES`에 경로 추가. |
| 외부 화면 | 전환 기간에는 라인업 화면 머리의 작은 글자 링크 "편성센터 화면(새 창)"으로 남긴다(사용자 결정 사항 D1). |
| 코드 위치 이름 | `src/lib/lineupPlan/` — 이미 있는 `src/lib/lineupHandoff.ts`(월간 리뷰의 "자리 이어받기" 분석)와 이름이 겹쳐 헷갈리지 않게 `lineupPlan`으로 한다. |

### 2.3 보기 3개 + 초점 모드

| 보기 | 목적 | 행 | 기본 범위 |
|---|---|---|---|
| **자사 라인업**(기본, `view=own`) | P1-1, P1-2, P3-4 | 채널 묶음 > 채널 > 장르 자리 > 자리 | 지난달~6개월 뒤 |
| **경쟁 비교**(`view=compare`) | P1-3, P2-1, P2-4 | 요일 묶음(월화/수목/주말/기타) > 방송사 자리. 각 묶음 맨 위에 자사 자리 고정 | 같음 |
| **목록**(`view=list`) | P1-4, P2-3, 화면 낭독기 대안, 휴대폰 기본 | 한 줄 = 편성 구간 하나(작품 × 자리 × 기간), 월별 묶음 | 같음 |
| **맞대결 초점**(모드, `focus=구간ID`) | P1-3 | 경쟁 비교 위에 겹쳐 켜지는 상태 | 선택 작품 기간 ± 2주로 자동 이동 |

```
 ◇ 미정   타사 다 금토 21:50 미정 자리                  1월 넷째 주부터       12회  -           업계 종합 11/17
──────────────────────────────────────────────────────────────────────────────────────────
```

- 상태(방영 중/예정/종영/미정)는 저장값이 아니라 오늘 날짜와 기간으로 서버가 정한다.
- 열 고르기(보이기/숨기기)와 정렬(시작일·종료일·채널)은 주소에 남긴다. 휴대폰에서는 표 대신 카드(§9.3).

### 2.5 주소(URL) 쿼리 — 공유 가능한 상태

앱의 관례대로 **화면 상태의 원본은 주소**다(프로그램 성과 화면과 같은 방식). 보기 전환은 기록을 남기고(`push`), 나머지 조작은 기록 없이 바꾼다(`replace`).

| 키 | 값 | 기본값(생략 시) | 비고 |
|---|---|---|---|
| `view` | `own` · `compare` · `list` | `own` | 휴대폰 폭에서 생략되면 `list` |

| `fit` | `1` · `0` | `1` | 1 = 화면 폭에 맞춤, 0 = 고정 눈금 + 가로 밀기 |
| `ch` | 자사 채널 코드 쉼표 목록(`ENA,ENA_PLAY`) | 라인업 자료가 있는 자사 채널 전부 | `channels.code`와 같은 값 |

## 3. 행 구조와 확장성

### 3.1 기본 단위: 자리(slot)

- **자리 = 방송사(채널) + 요일 묶음 + 시각.** 예: `ENA · 월화 · 22:00`, `타사 가 · 토일 · 토 22:40 / 일 22:30`.
- 장르는 작품의 속성이지 자리의 속성이 아니다. 다만 사람들은 "월화 드라마 자리"로 생각하므로 자리에 **기본 장르**(드라마 자리/예능 자리/기타)를 둬서 묶는 데만 쓴다. 한 자리에 예능 사이 행사가 들어와도 같은 줄에 그린다(지금 자사 양식이 그렇게 쓰고 있다).
- 시각이 바뀌어도(조기 시작, 반기마다 시각 이동) 같은 자리로 본다. 자리에는 대표 시각을, 편성 구간에는 그 구간의 실제 시각을 둔다(§8).
- 시각은 기존 `competitor_airings`와 같은 **방송일 기준 분**(00:30 = 1470)으로 저장해 자정 넘는 편성도 한 규칙으로 다룬다.

### 3.2 자사 라인업의 행 축

```
A 묶음 (2049 핵심)                     ← 1단: 채널 묶음. 기존 targetGroups.ts의 groupForChannel()로 정한다(값을 새로 정의하지 않음)
  ENA            [로고] 자리 9 · 방영 중 6     ← 2단: 채널(접기 가능). 머리에 channels.logo_path 로고
    드라마 자리                                ← 3단: 기본 장르(접기 없음, 작은 머리글)
      월화 22:00                              ← 4단: 자리 = 한 줄(겹치면 2칸까지 늘어남, §3.5)
    예능 자리
      화 17:40 / 화 23:20 / 수 22:30 …
    기타
  ENA Drama / ENA Play
B 묶음 (가구 핵심)
  OLIFE / ONCE / ENA Story / skyUHD
```

- 자리 순서: 요일(월→일) 다음 시각. 묶음 순서는 고정(A→B, 채널은 `channels` 순서).
- **자료 없는 채널은 기본으로 숨기고** 묶음 머리에 "라인업 자료가 없는 채널 4개 숨김 · 보이기"로 알린다. 7개 채널 중 자료가 있는 채널만 자리를 차지한다.
- 채널 고르기 빠른 단추: `ENA만` · `A 묶음` · `자사 전체`. PD 계정에 담당 채널 정보가 생기면 그 채널을 기본으로(지금은 없음, 결정 D11).

### 3.3 경쟁 비교의 행 축

업계 종합본의 틀(구분 섹션 × 방송사 행)을 따른다. 다만 섹션 다섯 개(월화 / 수목 / 주말 금 / 주말 토 / 주말 일)를 **네 묶음**으로 줄인다.

| 묶음 | 포함하는 자리(요일 집합) | 원자료 섹션 |
|---|---|---|
| 월화 | {월}, {화}, {월,화} | 월화 |
| 수목 | {수}, {목}, {수,목} | 수목 |
| 주말 | {금}, {토}, {일}, {금,토}, {토,일} | 주말 금 / 토 / 일 세 섹션을 **한 묶음으로 합침** |
| 기타 | 그 밖(띠 편성, 평일 매일 등) | — |

- 묶음 안 줄 순서: **자사 자리 맨 위 고정**(브랜드색 왼쪽 띠, ★) → 타사는 방송사 정렬 순서(원자료의 익숙한 순서: 지상파 → 종편 → 케이블, `lineup_outlets.sort_order`) → 같은 방송사 안에서는 시각 순.
- **토·일 섹션에 두 번 나오는 같은 작품은 한 줄 한 막대**로 합친다. 줄 머리는 `타사 가 · 토일 · 토 22:40 / 일 22:30`처럼 요일별 시각을 함께 쓴다. 금·토에 걸친 자리도 같은 방식(`금토 21:50`).
- 묶는 순서 바꾸기(`group=outlet`): 방송사 > 자리. "한 방송사의 1년 흐름"을 볼 때 쓴다.
- 자사 예능 자리도 요일이 맞는 묶음에 들어간다(예: 수 22:30 예능 → 수목 묶음). 다만 경쟁 비교 기본 장르 거르기가 `드라마`라서 기본 화면에서는 보이지 않는다. 타사 예능 라인업 자료가 생기면 같은 틀로 늘어난다.

### 3.4 줄이 많아져도 한 화면에서 읽히게

| 장치 | 내용 |
|---|---|
| 접기 | 채널·방송사·요일 묶음 단위로 접는다. 접힌 묶음은 **요약 줄 한 줄**로 남는다: 그 묶음의 모든 구간을 얇은 눈금(▪)으로 한 줄에 겹쳐 그려, 접어도 "언제 바쁘고 언제 비는지"가 보이게 한다. 요약 줄 끝에 "자리 3 · 방영 중 2". |
| 고정 열 | 왼쪽 행 머리(넉넉 184px / 촘촘 136px / 휴대폰 96px)는 가로로 밀어도 고정. 시간 축 머리 두 줄(월·주)과 공휴일·행사 띠는 세로로 밀어도 위에 고정. |
| 밀도 | 넉넉(줄 높이 44px, 막대 안 2줄: 제목 / 기간·회차·주연) · 촘촘(28px, 1줄: 제목만, 나머지는 툴팁). 인쇄는 별도 밀도(§9). |
| 빈 줄 숨기기 | 보이는 기간에 구간이 하나도 없는 자리는 "빈 자리 3개 숨김"으로 묶는다(타사 행이 많은 업계 자료에서 효과 큼: 원자료 한 반기 시트 47줄 중 상당수가 빈 줄). |
| 거르기 | 방송사·요일 묶음·장르·상태(방영 중/예정/미정·휴방만). "미정·휴방만"은 P2-4 전용. |
| 줄 수 예산 | 1440×900 화면에서 넉넉 약 14줄, 촘촘 약 24줄이 한 번에 보인다. 기본 펼침(ENA만)은 이 안에 들어오게 한다. |

### 3.5 한 자리 안에서 구간이 겹칠 때

- 같은 자리에 연속 편성 막대와 단발 행사가 겹치면(예: 토요일 예능 사이 이틀 시상식) **행사 마름모를 막대 위에 겹쳐 그리고**, 그 날짜는 막대에 결방 빗금 조각을 넣는다. 줄은 늘리지 않는다.
- 연속 편성끼리 겹치면(두 작품 동시 진행·자료 오류) 그 줄을 2칸으로 늘리고, 관리 화면 점검 목록에 "같은 자리에서 기간이 겹침"을 올린다.

## 4. 시간 축

### 4.1 기본 범위와 이동

- **기본: 지난달 1일 ~ 6개월 뒤 달 말일(8개월).** 오늘(2026-11-24) 기준 2026년 10월 ~ 2027년 5월.
  - 지난달을 넣는 이유: 지금 방영 중인 작품의 시작이 대개 지난달에 있다(미니시리즈 6~7주). 맞대결 비교에서도 타사 현재 작품 시작이 보여야 한다.
  - 휴대폰·좁은 화면(1280px 미만)에서 주소에 기간이 없으면 지난달 ~ 4개월 뒤(6개월)로 줄인다.
- 기간 고르기: `이번 달부터 6개월` · `지난달부터 8개월(기본)` · `올해` · `내년` · `상반기/하반기(연도 선택)` · `직접(시작 월~끝 월)`. 옛 화면의 "이번달부터"와 "전체"는 앞의 둘과 "자료 전체 기간"으로 이어 받는다.
- ◀ ▶: 확대 단위만큼 이동(월 확대면 1개월, 분기 확대면 3개월). `[오늘]`은 오늘선이 왼쪽에서 1/4 지점에 오게 맞춘다.
- 시간 축의 **월 머리를 누르면 그 달로 확대**(옛 화면의 월 칩 기능을 축 안으로 옮김).

### 4.2 확대 4단계와 화면 맞춤

| 확대 | 1주 폭(맞춤 끔 기준) | 보이는 머리 | 막대 글자 |
|---|---|---|---|
| 주 | 약 96px | 월 / 주(월요일 날짜) / 요일 눈금 | 막대 안 2줄 |
| 월(기본) | 화면 폭 ÷ 주 수(8개월 1440px에서 약 35px) | 월 / 주 | 대부분 막대 안 1~2줄 |
| 분기 | 약 18px | 월 / 2주마다 날짜 | 바깥·아래 줄 위주 |
| 1년 | 약 10px | 분기 / 월 | 아래 줄 또는 번호(인쇄와 같은 방식) |

- **맞춤(fit=1, 기본)**: 고른 기간을 화면 폭에 꽉 채운다 → 옛 화면의 "오른쪽 빈 공간" 문제가 없어진다. 맞춤을 끄면 고정 눈금으로 가로로 밀어 본다.
- 앱 전체 CSS가 가로 스크롤 막대를 숨기므로(`globals.css` 2026-10-14 규칙), 밀 수 있다는 표시로 축 양끝에 ◀ ▶ 그림자 단추를 두고 키보드(←→)·Shift+휠도 받는다.

### 4.3 눈금·오늘선·지난 기간

- 하나의 **달력 축**(하루 단위 연속 축). 주 경계선은 월요일, 월 경계선은 더 진하게.
- 업계 종합본은 섹션마다 주 머리 요일이 다르다(월화=월요일 날짜, 수목=수요일, 금=금요일, 토=토요일, 일=일요일). 화면은 이것을 따르지 않고 **막대를 실제 방송 요일 위치에 놓는다**. 그래서 서로 다른 섹션의 막대를 같은 축에서 비교할 수 있다.
- 오늘선: 빨간 세로선(`--chart-reference` #b91c1c, 2px), 축 머리에 "오늘 11/24(화)" 꼬리표.
- 오늘 이전 구간 바탕은 `--surface-subtle`(#fafafa)로 깔아 "지난 기간"을 표시한다(막대 자체를 흐리게 하지 않아 글자 대비가 유지됨).

### 4.4 공휴일·행사 띠

- 축 바로 아래 한 줄("공휴일·행사"). 표시 끄기 가능(`events=0`).
- **공휴일**은 기존 `public_holidays`(2024~2027 등록됨, 법정·대체·임시 구분)에서 읽는다. 공휴일 날짜는 그리드 전체에 아주 옅은 세로 음영을 깔아, 첫 방송·종영이 연휴와 겹치는지 바로 보이게 한다. 설·추석 연휴는 하나의 띠로 묶어 "설 연휴 2/6~9"처럼 쓴다(기존 `holiday/dayType.ts`의 연휴 묶음 규칙과 같은 판단).
- **행사**(공휴일이 아닌 것: 대형 스포츠 중계, 시상식, 선거, 기념일 등)는 새 `lineup_events`에서 읽는다. 업계 자료의 "올림픽 휴방", "아시안게임" 같은 셀이 여기와 연결된다. 특정 방송사만 영향받는 행사(중계 결방)는 그 방송사 줄에만 빗금이 생긴다.
- 자사 사업형 행사(시상식 중계 등)는 띠가 아니라 **그 행사가 편성된 자리 줄**에 마름모로 그린다(실제 편성 자리를 차지하므로).
- 표시하려는 기간에 공휴일 자료가 없으면(예: 2028년 미등록) 띠에 "이 기간 공휴일 자료 없음"을 쓴다. 지어내지 않는다.

### 4.5 날짜를 아는 정도를 정직하게 그리는 규칙

원자료마다 날짜 정밀도가 다르다: 자사 양식=정확한 날짜, 업계 종합본·방송사 단독 엑셀=주 칸, 방송사 이미지 캡처=월 단위("3~4월" 같은 표기) 또는 첫 방송일만(종료 없음).

| 정밀도(저장값) | 그리는 법 | 막대 아래·툴팁 문구(예) |
|---|---|---|
| 정확일 `day` | 꽉 찬 막대, 직각 끝 | "11월 16일(월) ~ 12월 22일(화) · 12회" |
| 주 단위 `week` | 꽉 찬 막대. 그 주의 블록 첫 요일 ~ 마지막 주의 블록 끝 요일. 끝선은 직각(오차가 하루 이틀이라 월 확대에서 눈에 안 보임) | "1월 둘째 주 ~ 2월 셋째 주 · 주 단위 자료라 실제 날짜는 하루 이틀 다를 수 있음" |
| 월 단위 `month` | **막대를 그리지 않는다.** 가능한 범위 전체에 얇은 **범위 괄호**(├────┤)를 긋고 위에 제목. 언제 시작하는지 모르기 때문에 막대처럼 보이면 안 된다 | "3~4월 중 방송 예정 · 월 단위 자료(정확한 날짜 없음) · 12회" |
| 첫 방송일만(시작 `day`, 끝 없음, 회차 있음) | 시작 끝은 직각, 몸통은 꽉 찬 막대, **추정한 끝 1주 구간은 같은 색 옅은 꼬리 + 점선 끝선(╌▸)** | "2월 5일(금) 첫 방송 예정 · 끝나는 날은 자료에 없음 · 12회를 주 2회로 나눠 3월 13일 무렵으로 추정" |
| 끝 미정·계속 방송 | 보이는 범위 오른쪽 끝까지 막대 + "→ 계속" | "12월 2일부터 계속 방송 · 끝나는 날 정해지지 않음" |
| 모름 `unknown` | 그리지 않고 목록·자리 머리의 "날짜 미정 1건" 꼬리표로만 | "날짜 미정" |

- 끝 날짜 추정은 **회차 수 ÷ (주당 방송 횟수 × 한 번에 나가는 회차)** 만 쓴다. 주당 횟수를 모르면 자리의 요일 수로 정하고, 둘 다 없으면 추정하지 않고 "끝 모름"으로 둔다. 추정은 서버 순수 함수(`src/lib/lineupPlan/dates.ts`)가 하고 저장하지 않는다(원본은 "끝 모름" 그대로).
- 같은 작품을 두 자료가 다르게 말하면(업계 종합본=주 단위, 방송사 캡처=첫 방송일) **더 정밀한 쪽을 화면에 쓰고**, 상세 패널 출처란에 두 자료를 모두 보여 주며 서로 다르면 "자료 간 차이"를 표시한다.

### 5.1 원칙: 모양 · 색 · 진하기가 각각 한 가지 뜻만 갖는다

## 6. 상세(호버·클릭)와 잘린 글자 해결

### 6.1 상호작용

| 동작 | 결과 |
|---|---|
| 마우스 올림(0.3초) | 가벼운 툴팁: 제목 전체, 기간(정밀도 문구 포함), 회차, 주연 1줄, 상태 |
| 누름 / Enter | 오른쪽 **상세 패널**(400px, 휴대폰은 아래에서 올라오는 시트). 주소에 `focus=` 추가 |
| Esc | 패널 닫기, 포커스는 누른 막대로 돌아감 |
| 키보드 | 그리드에 Tab으로 들어와 ←→ 같은 줄 이전·다음 구간, ↑↓ 위아래 줄, Home/End 줄 처음·끝 |
| 빈 주(점선) 누름 | "이 기간 비어 있음 · 5주(12/30~1/31)" + 편집 권한자에게 "여기에 구간 추가" |

- 옛 화면은 "막대 클릭 = 수정·삭제"였다. 새 화면은 **누르면 누구나 상세**, 수정은 상세 패널 안의 "수정" 단추(권한자만). 실수로 지우는 일을 막는다. 끌어서 날짜 바꾸기는 1단계에서 넣지 않는다.

### 6.3 실제 시청률 연결

- 1단계: **링크만** 준다. 방영 중·종영인 자사 작품은
  - 프로그램 성과: `/program-performance?q=<제목>&channel=<채널코드>&from=<시작일>&to=<종료일 또는 오늘>`
  - 시청률 표: `/ratings?tab=daily&code=<채널코드>&date=<마지막 방송일>`
  - 이 두 화면이 이미 읽는 쿼리 이름을 그대로 쓴다.
- 2단계(선택): 상세 패널에 DB에서 읽은 값만 그대로 표시(예: "방영 회차 평균 0.139 (수도권 개인2049, 닐슨)"). 절대 수치를 먼저, 지수는 괄호 참고. 화면·LLM이 계산하지 않고 기존 RPC·마트 값만 옮긴다(원칙 1).
- 작품 ↔ 프로그램 연결은 `lineup_works.program_id`(관리자가 확인한 연결)를 우선하고, 없으면 정규화 제목 키로 찾되 상세에 "자동 연결"이라고 쓴다.

### 6.4 잘린 글자 해결 규칙

옛 화면의 가장 눈에 띄는 문제. 아래 순서로 **자리를 찾고, 마지막에만 줄인다.**

1. **막대 안**: 제목이 막대 폭(좌우 여백 8px 제외)에 들어가면 막대 안. 넉넉 보기면 2줄째에 기간·회차(들어가는 만큼만: 기간 → 회차 → 주연 순으로 뺀다).
2. **막대 오른쪽 바깥**: 다음 구간까지 빈 공간이 제목보다 넓으면 막대 바로 오른쪽에 회색 글자로.
3. **아래 글자 줄**: 그 줄에 "글자 칸"(높이 16px)을 하나 늘려 막대 아래에 쓴다. 한 줄에 글자 칸은 하나만 늘린다.
4. **사람이 정한 줄임말**: `lineup_works.short_title`이 있으면 그걸 쓴다(프로그램명 풀네임 우선, 넘칠 때만 줄임 — 기존 규칙). 자동으로 글자 수를 잘라 줄임말을 만들지 않는다.
5. **그래도 안 되면** 끝을 "…"로 줄이되, 툴팁·상세 패널·화면 낭독기 이름(`aria-label`)에는 항상 전체 제목.

추가 장치:
- **따라붙는 제목**: 보이는 범위보다 먼저 시작한 막대는 제목이 화면 왼쪽 끝에 붙어 따라온다(가로로 밀어도 제목이 사라지지 않음).
- 글자 폭 판정은 그리기 전에 한 번 잰다(같은 글꼴로 측정). 글꼴은 화면 본문과 같은 Pretendard 계열, 13px(`--type-table`), 보조 12px(`--type-caption`)보다 작게 내리지 않는다.
- 인쇄에서는 툴팁이 없으므로 3~4단계 대신 **번호 각주**(①②…)를 막대에 달고 쪽 아래에 "① 이틀 행사 E 11/14~15 (토·일, 2회)"처럼 전체를 쓴다(§9.1).

| 한 건 입력·수정·보관 | 소식 하나 반영, 날짜 바뀜, 캡처 자료 몇 줄 | `/lineup/manage` 입력 양식 또는 상세 패널 "수정" |
| 엑셀 업로드 4종 | ① 자사 라인업 양식 ② 업계 드라마 라인업 종합본 ③ 방송사 단독 양식(주 칸 병합 막대) ④ 앱 표준 양식 | `/lineup/manage` 업로드 |
| 표 붙여넣기 | 메일 표·엑셀 일부·이미지 캡처를 사람이 옮겨 적을 때 | `/lineup/manage` 붙여넣기 |
| 행사 입력 | 대형 중계·시상식·기념일 | `/lineup/manage` 행사 탭 |

- **이미지 캡처는 사람이 옮겨 적는다.** 글자 인식이나 OpenAI 등 외부 LLM으로 보내지 않는다(대외비). 붙여넣기 표에 "제목 / 회차 / 일정 / 주연 / 비고"를 적고, 일정 열의 정밀도("3~4월" = 월 단위, "27.02.05" = 첫 방송일만)를 고른다.
- 원본 파일은 저장하지 않는다(파일 이름·해시·시트 요약만 남김). 셀 원문은 출처 추적을 위해 `lineup_source_cells`에 남긴다.

### 7.2 업로드 공통: 미리보기 → 반영 (두 단계)

기존 경쟁 채널 편성 업로드(`/api/competitor-airings`의 `mode=preview` → `mode=commit`)와 같은 방식.

```
[파일 고르기] → 양식 자동 판별 → 미리보기
┌────────────────────────────────────────────────────────────────────────┐
│ 업계 드라마 라인업 종합본 · 자료 기준일 [2026-11-17] (파일 이름에서 읽음, 고칠 수 있음) │
│ 시트: ☑ 2025 상반기(2024-12-30 주~2025-06-30 주)  ☑ 2026 상반기  ☑ 2026 하반기  ☑ 2027 │
│   ⚠ "2026 하반기" 시트의 제목 칸은 "상반기"로 적혀 있음 → 날짜 머리 기준으로 하반기로 읽음 │
│                                                                        │
│ 신규 46 · 바뀜 7 · 그대로 120 · 새 자료에 없음 3 · 확인 필요 9 · 건너뜀(자사 줄) 8    │
│ ─ 확인 필요 ──────────────────────────────────────────────────────────── │
│  처음 보는 방송사 표기 "KBS" → [KBS2 ▾] (한 번 묶으면 다음부터 기억)            │
│  병합 안 된 한 칸짜리 글자 4건 → 시작 주만 적힌 것? / 지난 시트에서 남은 글자? [보기]│
│  주 날짜 머리 범위 밖 글자 2건 → [무시] [보기]                                   │
│  토·일 묶기 후보: 「타사 나 주말극 1」 토 22:40 + 일 22:30 → [한 작품으로 묶기 ✓]   │
│  이름이 비슷한 기존 작품: 「…」 ↔ 「…」(띄어쓰기만 다름) → [같은 작품 ✓]            │
│  쉼표 뒤 큰 숫자(예: 160)는 회차 수인가 누적 회차인가 → [누적 회차 ▾]              │
│ ─ 바뀜 ──────────────────────────────────────────────────────────────── │
│  타사 다 수목 · 「…」 시작 1월 둘째 주 → 셋째 주, 회차 12 → 14                    │
│ ─ 새 자료에 없음 ─────────────────────────────────────────────────────── │
│  타사 가 월화 · 「…」 → [그대로 둠] [보관]   (자동으로 지우지 않음)                │
│                                                   [취소]  [반영하기]        │
└────────────────────────────────────────────────────────────────────────┘
```

- "확인 필요"가 남아 있으면 반영 단추를 막지는 않되, 남은 항목은 "확인 필요" 상태로 저장해 관리 화면 점검 목록에 계속 보인다.
- 반영하면 출처 1건(`lineup_sources`)이 생기고 바뀐 내용이 모두 변경 이력에 들어간다. 출처 단위 **되돌리기**(그 업로드로 바뀐 값을 이전 값으로)를 제공한다.

### 7.3 업계 드라마 라인업 종합본 읽기 규칙 (가장 중요한 경쟁 자료)

원자료 구조(실제 파일 확인): 시트 4개(2025 상반기 / 2026 상반기 / 2026 하반기 / 2027), 시트마다 "구분" 섹션 5개(월화 / 수목 / 주말 금 / 주말 토 / 주말 일), 섹션 머리 2줄(월 이름 줄 + 주 날짜 줄), 그 아래 방송사+시각 줄, **가로 병합 셀 = 방영 기간 막대**(시트당 병합 110~190개). 칸 채움색은 월 머리(노랑)와 일부 흰 칸뿐이라 **색으로 뜻을 읽지 않는다.**

| 단계 | 규칙 |
|---|---|
| 1. 시트 고르기 | 시트 목록과 각 시트의 실제 기간(첫·끝 주 날짜)을 보여 준다. 기간은 **시트 제목 칸이 아니라 시트 이름 + 날짜 머리**로 정한다(제목 칸이 잘못 복사된 시트가 있음). 과거 시트도 이력으로 넣는다(결정 D7). |
| 2. 섹션 찾기 | A열 "구분" 머리줄 → 다음 줄이 주 날짜 → A열 섹션 이름(세로 병합)으로 요일 묶음을 정한다: 월화={월,화}, 수목={수,목}, "금"={금}, "(토)"={토}, "(일)"={일}. |
| 3. 주 날짜 풀기 | 주 날짜 칸에는 "일"만 있다. 시트 연도 + 월 머리 + **7일 간격 검사**로 전체 날짜를 만든다. 월 사이 빈 구분 열은 건너뛴다. 첫 칸이 전년도 12월 말일 수 있다(예: 1월 머리 아래 "30" = 전년 12월 30일). 7일 간격이 깨지면 그 시트를 "확인 필요"로. |
| 4. 줄 머리 풀기 | "방송사 + 시각" 원문을 방송사·시각·요일 꼬리로 나눈다. 표기 예: `22:00`, `2250`, `21시`, `금23`, `금토23`, `1일2회`, `(수) 22:40`, `(목) 21:50`, `(주말)`. 방송사 표기 흔들림(`tvN`/`TVN`/`tvn`, `KBS`/`KBS2`)은 **공백 제거·대문자 비교 + 별칭 표**로 묶는다(기존 `competitorRegion.ts`의 `normChannel`과 같은 비교법). `KBS`처럼 뜻이 둘인 표기는 처음 한 번 사람이 고르고 별칭으로 기억한다. |
| 5. 셀 → 기간 | 병합 범위의 첫 날짜 열 = 시작 주, 끝 날짜 열 = 마지막 주. 시작일 = 첫 주의 그 섹션 요일, 종료일 = 마지막 주의 그 섹션 마지막 요일. 정밀도 = 주 단위. 병합 범위가 빈 구분 열을 가로질러도 날짜 열만 센다. |
| 6. 셀 글자 풀기 | 기본 형식: 1줄 `제목(회차) 제작사1,제작사2` / 2줄 `연출/작가/` / 3줄 `주연1,주연2`. 제목(회차)만 있는 칸, 2줄이 비어 있는 칸, 이름 뒤 괄호(대표작 메모), 슬래시가 4개 이상인 칸 등 변형이 많다. **해석이 애매하면 원문을 그대로 두고 "확인 필요"** — 이름을 추측해 연출·작가·주연 칸에 나눠 넣지 않는다. 회차 괄호는 `( )`와 `[ ]` 둘 다 받는다. |
| 7. 특수 칸 | `휴방`, `○○ 휴방`(예: 올림픽 휴방), 스포츠 대회 이름(예: 추석 아시안게임) → **결방·휴방 칸** + 사유. `OTT 수급`, `수급물 예정` → **수급물 칸**. `미정(12)` → **미정 자리** + 회차 12. 스포츠 대회는 행사 표(`lineup_events`)에 같은 기간 행사가 있으면 연결하고, 없으면 만들기를 제안한다. |
| 8. 한 작품으로 묶기 | 같은 방송사 + 같은 정규화 제목 + 기간이 겹치거나 맞닿음 → **한 작품 · 한 편성 구간**. 요일은 합집합(토+일 → 토일, 금+토 → 금토), 요일별 시각은 각 섹션 줄 머리에서 따로 보존. 시트 경계(하반기 → 다음 해 시트)에 걸친 작품도 같은 규칙으로 합친다. |
| 9. 자사 줄 | ENA 줄은 기본으로 **건너뛴다**(자사 라인업 자료가 기준). 다만 자사 자료와 다르면 미리보기에 "업계 자료와 자사 자료의 차이"로 보여 준다(결정 D8). |
| 10. 의심 칸 경고 | ① 병합 안 된 한 칸짜리 글자(시작 주만 적었는지, 지난 시트에서 복사하다 남은 글자인지 알 수 없음) ② 그 섹션 날짜 머리 범위 밖의 글자 ③ 이전 시트 같은 위치에 같은 글자(복사 잔재 의심) ④ 같은 자리에서 기간 겹침. 모두 "확인 필요"로 올리고 자동 반영하지 않는다. |
| 11. 새 판 다시 올리기 | 같은 종합본의 새 판(파일 이름의 날짜가 기준일)을 올리면 직전 반영분과 비교해 신규·바뀜(날짜·회차·제목)·새 자료에 없음을 보여 준다. 제목이 바뀐 작품(가제 → 확정 제목)은 같은 방송사·같은 자리·비슷한 기간이면 "제목 바뀜 후보"로 묶고, 옛 제목은 별칭으로 남긴다. |

### 7.4 그 밖의 양식

| 양식 | 판별 | 읽기 규칙 |
|---|---|---|
| ① 자사 라인업(편성센터 양식) | 1행 제목 "… 오리지널 라인업 …", 2~3행 월·주(월요일 날짜) 머리 | 줄 = 장르(A열) · 요일(B열) · 시각(C열). 칸 글자 `제목 시작~종료, 회차` 또는 `제목 날짜`(단발) 또는 `제목 시작~종료, 월1회·마지막주`. 드라마는 **다음 줄 = 주연**. 칸 채움색으로 장르를 정한다(분홍=드라마, 파랑=예능, 회색=사업형, 검정=기념일·행사 줄) — 원자료에서 색에 뜻이 있는 유일한 양식이라 색을 쓰되 미리보기에서 확인받는다. **날짜는 글자가 우선**이고, 병합 막대 길이와 글자 날짜가 다르면 경고(예: 장수 예능 막대가 시트 끝까지 이어져 있으나 글자는 한 달 범위 → "계속 방송으로 볼까요?"). 연도는 시트 제목의 기간과 칸이 놓인 주로 정한다(끝 < 시작이면 해를 넘김). 쉼표 뒤 숫자가 40을 넘으면 누적 회차로 보고 확인받는다. 토요일 줄에 있는 "토~일 이틀 행사"는 이틀 행사로 읽는다. |
| ③ 방송사 단독(주 칸 병합 막대) | 제목 "■ 20xx년 ○○ … 라인업", 월 머리 + 주 날짜 줄, 막대 줄 하나 | 업계 종합본 5~6단계와 같다. 주 날짜가 무슨 요일인지는 블록으로 정한다(실제 파일에서 토일극 양식의 주 날짜는 **토요일** 날짜였다 — 요일을 가정하지 말고 날짜로 확인). 칸 글자 `제목 [회차] 연출 / 작가 주연 <제작사> 로그라인`. 시트 아래 "※ 추후 변경 가능성 有" 같은 주석은 출처의 `change_note`로 저장. |
| ④ 앱 표준 양식 | 내려받은 양식의 숨은 표식 시트 | 한 줄 = 편성 구간 하나. 열: 방송사, 자리(요일·시각), 제목, 종류, 시작, 시작 정밀도, 종료, 종료 정밀도, 회차, 주당 횟수, 주연, 연출, 작가, 제작사, OTT, 상태, 메모. 예시 줄은 가명이며 올려도 무시(경쟁 채널 편성 양식과 같은 방식). **ENA Play 등 다른 자사 채널도 이 양식으로 시작**한다. |
| 붙여넣기 | 표를 복사해 붙여 넣은 탭 구분 글 | 첫 줄을 머리로 보고 열 짝짓기 화면(제목/회차/일정/첫 방송일/편수/주연/비고) → 방송사·자리·정밀도 기본값을 고르고 → 미리보기 → 반영. 비고의 "○○오리지널" 같은 표기는 OTT 칸으로 옮기고 제목에서 뗀다. |

### 7.5 변경 이력

- 작품·편성 구간·자리·방송사·행사의 **모든 변경**(만들기·고치기·보관·되살리기)을 `lineup_changes`에 남긴다: 누가, 언제, 무엇을, 전 값 → 새 값, 어떤 업로드로.
- 빠짐없이 남기려고 테이블 트리거로 쓴다. 바꾼 사람은 각 행의 `updated_by`에서 읽는다(서버가 쓸 때 항상 채움).
- 보이는 곳: 상세 패널(최근 5건), 관리 화면 "최근 바뀐 것"(전체, 거르기), 보기 화면의 "최근 바뀜" 점(7일).
- 지우기는 **보관**(숨김)이 기본이다. 완전 삭제는 관리자만, 확인 대화 후. 이력은 지우지 않는다.

### 7.6 권한

| 행동 | 최소 역할(제안) | 근거 |
|---|---|---|
| 보기(세 보기·상세·링크) | 로그인한 사람(PD 포함) | `proxy.ts`가 로그인 없는 요청을 막고, API는 `requireActorFor("view")` |
| 인쇄 | 보기와 같음 | 인쇄는 허용(브리프). 출력 쪽 아래 "대외비 · 출력자 · 출력 시각" |
| 엑셀 내보내기 | 1단계에서는 만들지 않음 | 대외비 자료가 파일로 퍼지는 길을 줄임(결정 D4) |
| 입력·수정·보관·업로드 | **관리자**(새 권한 `lineup_edit`) | 브리프. PD(편성자)에게 열지는 결정 D2 — 권한표(`permissions.ts`의 `MIN_ROLE`) 한 곳만 바꾸면 되게 설계 |
| 완전 삭제·되돌리기 | 관리자 | |

- 새 권한 `lineup_edit`를 `AdminAction`에 추가한다(지금 `upload`는 닐슨 원본 업로드 뜻이라 섞지 않는다).
- 메뉴 숨김은 보안이 아니므로 모든 API가 서버에서 권한을 다시 검사한다(기존 원칙).

### 7.7 대외비 처리 (화면·서버)

- 라인업 데이터는 **어떤 LLM 입력에도 넣지 않는다**: 자연어 질의(`/api/ask`) 의도 목록, 브리핑·뉴스 생성, 외부 검토 패키지에서 제외. 코드에 "라인업 테이블은 LLM 경로 금지" 주석과, 그 경로들에서 `lineup_` 테이블을 읽지 않는지 확인하는 테스트를 둔다.
- API 응답은 `Cache-Control: private, no-store`. 텔레메트리(`page_timing_log` 등)에 제목을 싣지 않는다. 서버 로그에 셀 원문을 찍지 않는다.
- 테스트용 엑셀은 실제 파일이 아니라 테스트 코드가 만드는 가명 통합문서로 한다(원자료를 저장소에 넣지 않음).
- 대외비 등급(작품·구간·출처마다): `public`(방영 중·발표됨) / `internal`(자사 미발표) / `restricted`(타사 공유·업계 자료). 1단계에서는 등급이 보기 범위를 바꾸지 않고 **표시·인쇄 머리말에만** 쓴다. 등급별로 PD에게 숨길 항목이 있는지는 결정 D3.

A/B 묶음은 테이블에 없고 코드(`src/lib/audienceReport/targetGroups.ts`의 `groupForChannel`)에 있으므로 새로 저장하지 않는다.

### 8.2 새 테이블 (초안 — 적용 전 사용자 승인, 새 마이그레이션 파일로만)

```sql
-- 라인업 화면(2026-11-24 설계안). 모든 테이블은 RLS를 켜고 정책을 두지 않는다(서버 service_role만 읽고 쓴다).
-- 데이터는 대외비라 시드(실제 제목)는 마이그레이션에 넣지 않는다. 방송사 기준표 몇 줄(코드·표기)만 넣는다.

-- 1) 방송사·채널. 자사는 channels와 연결한다.
create table lineup_outlets (
  id uuid primary key default gen_random_uuid(),
  code text not null unique,                 -- 자사: channels.code와 같게('ENA'…) / 타사: 'TVN','JTBC','MBC','SBS','KBS2'…
  display_name text not null,                -- 화면 표기('tvN')
  side text not null check (side in ('own', 'rival')),
  channel_id uuid references channels(id) on delete restrict,
  outlet_kind text check (outlet_kind in ('own', 'terrestrial', 'general', 'cable', 'ott')),  -- 정렬·묶음(지상파·종편·케이블)
  aliases text[] not null default '{}',      -- 원자료 표기('TVN','tvn') — 비교는 공백 제거·대문자
  ratings_name text,                         -- 경쟁 시청률 자료의 채널 표기(2단계 연결)
  sort_order int not null default 100,
  active boolean not null default true,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  updated_by text,
  check (side <> 'own' or channel_id is not null)
);

-- 2) 자리(요일 묶음 + 시각). 시각은 방송일 기준 분(00:30 = 1470) — competitor_airings와 같은 규칙.
create table lineup_slots (
  id uuid primary key default gen_random_uuid(),
  outlet_id uuid not null references lineup_outlets(id) on delete restrict,
  name text not null,                        -- '월화 드라마', '토 예능 1'
  days smallint[] not null check (cardinality(days) between 1 and 7 and days <@ array[1,2,3,4,5,6,7]::smallint[]),
  start_minute int check (start_minute between 0 and 1799),
  day_minutes jsonb,                         -- 요일마다 시각이 다를 때 {"6":1360,"7":1350}
  time_note text,                            -- '1일 2회' 같은 원문
  compare_block text not null check (compare_block in ('mon_tue', 'wed_thu', 'weekend', 'other')),
  default_genre text not null check (default_genre in ('drama', 'variety', 'business', 'other')),
  track_gaps boolean not null default false, -- 빈 주 표시(드라마 자리 기본 true)
  sort_order int not null default 100,
  archived_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  updated_by text,
  unique (outlet_id, name)
);

-- 3) 작품. 한 작품이 여러 편성 구간(파트1·2, 자리 이동)을 가질 수 있다.
create table lineup_works (
  id uuid primary key default gen_random_uuid(),
  outlet_id uuid not null references lineup_outlets(id) on delete restrict,
  title text not null,                       -- 풀네임(띄어쓰기 있는 표기 우선)
  title_key text not null,                   -- 정규화 키(공백·문장부호·회차 꼬리표 제거, 기존 프로그램명 정규화 규칙)
  title_tentative boolean not null default false,   -- 가제
  short_title text,                          -- 넘칠 때만 쓰는 줄임말(사람이 정함)
  genre text not null check (genre in ('drama', 'variety', 'business', 'event', 'other')),
  is_original boolean,                       -- 자사 오리지널 여부
  total_episodes int check (total_episodes > 0),
  cast_main text[] not null default '{}',
  directors text[] not null default '{}',
  writers text[] not null default '{}',
  producers text[] not null default '{}',    -- 제작사
  logline text,
  ott_platform text,                         -- '티빙' 등
  ott_relation text check (ott_relation in ('simulcast', 'ahead', 'label_only')),  -- 동시 공개·선공개·표기만
  program_id uuid references programs(id) on delete set null,  -- 자사 방영 후 시청률 연결(관리자 확인)
  confidentiality text not null default 'restricted' check (confidentiality in ('public', 'internal', 'restricted')),
  note text,
  archived_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  updated_by text
);
create unique index lineup_works_outlet_title_uq on lineup_works (outlet_id, title_key) where archived_at is null;

-- 4) 작품 별칭(가제 → 확정 제목, 띄어쓰기 다른 표기). 옛 판 자료를 다시 올려도 같은 작품으로 찾는다.
create table lineup_work_aliases (
  work_id uuid not null references lineup_works(id) on delete cascade,
  alias_key text not null,
  alias_title text not null,
  primary key (work_id, alias_key)
);

-- 5) 자료 출처(업로드·입력 한 번 = 한 건). 원본 파일 자체는 저장하지 않는다.
create table lineup_sources (
  id uuid primary key default gen_random_uuid(),
  source_kind text not null check (source_kind in ('own_xlsx', 'industry_xlsx', 'outlet_xlsx', 'standard_xlsx', 'paste', 'manual')),
  title text not null,                       -- '업계 드라마 라인업 종합본' 등
  outlet_id uuid references lineup_outlets(id),
  as_of date not null,                       -- 자료 기준일
  file_name text,
  file_hash text,
  change_note text,                          -- '추후 변경 가능' 같은 원문 주석
  sheet_summary jsonb not null default '[]'::jsonb,
  status text not null default 'applied' check (status in ('applied', 'rolled_back')),
  confidentiality text not null default 'restricted' check (confidentiality in ('public', 'internal', 'restricted')),
  applied_by text not null,
  applied_at timestamptz not null default now()
);

-- 6) 편성 구간 = 화면의 막대·점·마름모·칸 하나.
create table lineup_runs (
  id uuid primary key default gen_random_uuid(),
  slot_id uuid not null references lineup_slots(id) on delete restrict,
  work_id uuid references lineup_works(id) on delete restrict,
  run_kind text not null check (run_kind in ('series', 'monthly', 'single', 'multi_day', 'tbd', 'hiatus', 'filler')),
    -- series 연속 편성 / monthly 월 1회 / single 단발 / multi_day 이틀 이상 행사 / tbd 미정 자리 / hiatus 결방·휴방 / filler 수급물
  status text not null default 'planned' check (status in ('confirmed', 'planned', 'tentative')),  -- 확정·예정·가안
  start_date date,
  start_precision text not null check (start_precision in ('day', 'week', 'month', 'quarter', 'half', 'unknown')),
  end_date date,                             -- 없으면 '끝 모름'(추정은 저장하지 않고 서버 함수가 계산)
  end_precision text not null check (end_precision in ('day', 'week', 'month', 'quarter', 'half', 'open', 'unknown')),  -- open = 계속 방송
  start_text text,                           -- 원문('3~4월', '27.02.05')
  end_text text,
  episodes int check (episodes > 0),         -- 이 구간 회차 수
  episode_from int,                          -- 누적 회차 표기(장수 예능)
  episode_to int,
  airings_per_week numeric(3, 1),            -- 없으면 자리 요일 수
  episodes_per_airing smallint not null default 1,  -- '하루 2회'
  recurrence text,                           -- 월 1회 규칙('monthly:last:2' = 매달 마지막 화요일)
  air_dates date[],                          -- 단발·이틀 행사·월 1회의 명시 날짜
  day_minutes jsonb,                         -- 이 구간만 시각이 다를 때
  label text,                                -- 작품 없는 칸의 글자('미정', 'OTT 수급', '휴방')
  reason text,                               -- 결방·휴방 사유
  event_id uuid,                             -- 결방 원인 행사(lineup_events, 아래에서 FK)
  source_id uuid references lineup_sources(id) on delete set null,
  needs_review boolean not null default false,   -- 업로드 미리보기에서 남은 '확인 필요'
  confidentiality text not null default 'restricted' check (confidentiality in ('public', 'internal', 'restricted')),
  note text,
  archived_at timestamptz,
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  updated_by text,
  check ((run_kind in ('tbd', 'hiatus', 'filler')) = (work_id is null)),
  check (start_date is null or end_date is null or end_date >= start_date),
  check (start_precision = 'unknown' or start_date is not null),
  check (end_precision in ('unknown', 'open') or end_date is not null),
  check (run_kind <> 'monthly' or recurrence is not null or air_dates is not null),
  check (run_kind not in ('single', 'multi_day') or start_date is not null)
);
create index lineup_runs_slot_idx on lineup_runs (slot_id, start_date);
create index lineup_runs_work_idx on lineup_runs (work_id);
create index lineup_runs_range_idx on lineup_runs (start_date, end_date) where archived_at is null;

-- 7) 행사(공휴일이 아닌 것: 대형 중계·시상식·선거·기념일). 공휴일은 public_holidays를 읽는다.
create table lineup_events (
  id uuid primary key default gen_random_uuid(),
  name text not null,
  event_kind text not null check (event_kind in ('sports', 'awards', 'election', 'anniversary', 'industry', 'other')),
  start_date date not null,
  end_date date not null check (end_date >= start_date),
  precision text not null default 'day' check (precision in ('day', 'week', 'month')),
  outlet_ids uuid[],                         -- 특정 방송사만 영향(중계 결방). 비면 전체
  note text,
  source_id uuid references lineup_sources(id) on delete set null,
  confidentiality text not null default 'internal' check (confidentiality in ('public', 'internal', 'restricted')),
  created_at timestamptz not null default now(),
  updated_at timestamptz not null default now(),
  updated_by text
);
alter table lineup_runs add constraint lineup_runs_event_fk foreign key (event_id) references lineup_events(id) on delete set null;

-- 8) 출처 셀 원문(출처 추적·다시 올릴 때 비교). 관리자 화면에서만 보인다.
create table lineup_source_cells (
  id bigserial primary key,
  source_id uuid not null references lineup_sources(id) on delete cascade,
  run_id uuid references lineup_runs(id) on delete set null,
  sheet text,
  cell_range text,                           -- 'G37:M37' 같은 셀 범위
  row_label text,                            -- '방송사 22:40' 같은 줄 머리 원문
  raw_text text not null,                    -- 셀 원문(줄바꿈 보존)
  parsed jsonb not null,                     -- 해석 결과
  issues text[] not null default '{}'        -- '병합 안 된 한 칸', '머리 범위 밖' 등
);
create index lineup_source_cells_run_idx on lineup_source_cells (run_id);

-- 9) 변경 이력(트리거가 씀, 바꾼 사람 = NEW.updated_by).
create table lineup_changes (
  id bigserial primary key,
  entity text not null check (entity in ('outlet', 'slot', 'work', 'run', 'event')),
  entity_id uuid not null,
  action text not null check (action in ('create', 'update', 'archive', 'restore', 'delete')),
  diff jsonb not null,                       -- {"start_date":{"before":"…","after":"…"}}
  source_id uuid references lineup_sources(id) on delete set null,
  actor text not null,
  at timestamptz not null default now()
);
create index lineup_changes_entity_idx on lineup_changes (entity, entity_id, at desc);
create index lineup_changes_recent_idx on lineup_changes (at desc);
```

모델 메모:
- 막대 하나 = `lineup_runs` 한 줄. 작품 정보는 `lineup_works`에 한 번만 두고, 업계 자료의 토·일 두 줄은 **구간 하나**(자리의 요일 = 토일)로 합친다.
- 주·월 정밀도 날짜는 대표값으로 저장한다: 주 단위 = 그 주의 블록 첫 요일 / 마지막 주의 블록 끝 요일, 월 단위 = 그 달 1일 / 끝 달 말일. 화면은 정밀도 값을 보고 그리는 법을 바꾼다.
- 같은 자리에서 구간 겹침은 제약으로 막지 않는다(행사가 연속 편성 위에 겹치는 게 정상). 겹침 검사는 서버 함수가 경고로 낸다.
- 구간 안 결방은 따로 표를 만들지 않고 같은 자리의 `hiatus` 구간이 겹치는 것으로 표현한다(한 개념으로 통일). 끝 추정 계산은 겹친 결방 주만큼 뒤로 민다.
- 시청률은 저장하지 않는다. 표시가 필요하면 기존 `ratings`·경쟁 시청률 테이블에서 읽는다.

## 9. 인쇄와 좁은 화면

### 9.1 인쇄

| 항목 | A3 가로(기본) | A4 가로 |
|---|---|---|
| 권장 범위 | 12개월까지 | 6개월까지(넘으면 "A3를 권장" 안내) |
| 밀도 | 인쇄 전용: 줄 높이 9mm, 제목 9pt, 보조 7.5pt(그 아래로 내리지 않음) | 같음, 넘치면 1줄만 |
| 쪽 나눔 | 묶음(채널·요일 묶음) 단위로 쪽을 넘긴다. 묶음이 한 쪽보다 길면 자리 단위 | 같음 |
| 머리 반복 | 모든 쪽에 시간 축 머리(월·주)와 공휴일·행사 띠를 반복(표의 머리줄 반복 기능을 쓰도록 인쇄용 구조를 표로 만든다) | 같음 |
| 잘린 글자 | 툴팁이 없으므로 막대에 번호(①②…), 쪽 아래 각주에 전체 제목·기간·회차 | 같음 |
| 쪽 아래 | 범례 · 자료 기준일(출처별) · "대외비 · 출력자 이름 · 출력 시각" · 쪽 번호 | 같음 |
| 색 | 색 그대로 인쇄(`print-color-adjust: exact`). 흑백 인쇄에서도 모양(점·마름모·빗금·점선)과 글자로 구분됨 | |
| 숨김 | 전역 메뉴(이미 `print:hidden`), 도구줄, 상세 패널, 오늘 이전 회색 바탕 | |

- "인쇄" 단추는 작은 대화상자를 연다: 용지(A3 가로/A4 가로), 범위(지금 화면 그대로/직접), 포함(공휴일·행사 띠, 범례, 출처, 접힌 묶음 펼쳐서 인쇄 여부). 고른 용지에 맞는 `@page` 크기를 넣고 브라우저 인쇄를 연다.
- 인쇄 기록: 기존 `login_log`의 내려받기 기록처럼 인쇄 시작을 남길지는 결정 D4.

## 11. 접근성·품질 점검표 (구현 완료 기준)

- [ ] 모든 막대·점·마름모·칸은 `<button>`이고 `aria-label`에 방송사·자리·전체 제목·기간(정밀도 문구)·회차·상태가 들어 있다.
- [ ] 그리드 키보드 이동(←→↑↓ Home End Enter Esc)과 포커스 링(`--focus-ring`)이 보인다.
- [ ] 색만으로 구분하는 곳이 없다(흑백 인쇄 확인).
- [ ] 막대 글자 대비 4.5:1 이상(`ensureTextContrast`로 보정), 비텍스트(테두리·점선) 3:1 이상.
- [ ] 모션 줄이기 설정을 따른다(맞대결 띠 등장·스크롤 이동).
- [ ] 목록 보기만으로 모든 정보를 얻을 수 있다(타임라인의 대안).
- [ ] 화면 문구에 내부 이름(테이블·영문 코드)이 없다 — 기존 `src/lib/ui/glossary.ts` 문구 검사에 라인업 화면을 넣는다.
- [ ] 1440×900에서 기본 화면이 가로 스크롤 없이 기간 전체를 보여 준다. 휴대폰 375px에서 페이지가 옆으로 밀리지 않는다.
- [ ] LLM 경로에서 `lineup_` 테이블을 읽지 않는다는 테스트가 통과한다.

## 13. 디자이너에게 넘길 확인 질문

- **Q1. 드라마 색**: 앱 토큰 중 가장 가까운 `--chart-4`(#a21caf, 자홍)를 제안했다. 사용자들이 익숙한 원자료의 분홍에 더 가깝게 하려면 새 토큰이 필요하다. 어느 쪽으로 갈지, 새 토큰이면 흰 글자 대비 4.5:1을 지키는 값으로.
- **Q2. 추정 끝 표현**: "같은 색 옅은 꼬리 + 점선 끝선(╌▸)"이 흑백 인쇄·저대비 화면에서도 "확정 끝"과 구분되는지 시안 확인.
- **Q3. 월 단위 범위 괄호(├────┤)**: 막대가 아니라는 게 한눈에 읽히는지, 제목을 괄호 위에 둘지 안에 둘지.
- **Q4. 막대 안 2줄 순서**: 넉넉 보기 2줄째를 "기간 · 회차 · 주연" 순으로 넣고 넘치면 뒤에서부터 뺀다. 순서와 구분 기호(·) 확인.
- **Q5. 경쟁 비교의 자사 줄 강조**: 브랜드색 채움 + 왼쪽 굵은 띠 + ★ 중 무엇을 쓸지(세 가지 다 쓰면 과함).
- **Q6. 맞대결 초점**: 선택 작품 기간 세로 띠 + 겹치지 않는 줄 흐리게. 흐린 정도와 띠 색(브랜드색 옅게?) 확인.
- **Q7. 접힌 묶음 요약 줄**: 얇은 눈금(▪)을 장르 색으로 칠할지 회색 하나로 할지.
- **Q8. 범례 위치**: 도구줄 아래 한 줄 고정(접기 가능)을 제안. 첫 방문에만 펼쳐 둘지.
- **Q9. 줄 높이·글자 크기**: 넉넉 44px/촘촘 28px, 막대 제목 13px, 보조 12px. 단계 15 기준(실무 표 12~14px)을 지키는지, 1년 확대에서 12px 아래가 필요한지.
- **Q10. 월 1회 점 열**: 점 지름과 연결선 굵기 — 촘촘 보기 28px 줄에서도 점이 누르기 쉬운 크기(24px 터치 영역)인지.
- **Q11. 인쇄 각주 번호**: 동그라미 숫자(①) 대신 작은 숫자 꼬리표가 나은지, 각주를 쪽 아래 몇 단으로 둘지.
- **Q12. 상세 패널 폭**: 400px가 1280px 노트북에서 그리드를 너무 가리는지(가리면 그리드를 줄일지, 패널을 덮개로 할지).

## 14. 사용자 결정이 필요한 사항

- **D1. 전역 메뉴**: "라인업"을 새 앱 화면으로 바꾸고, 외부 편성센터 화면은 라인업 화면 머리의 작은 링크로만 남길까? 남긴다면 언제까지?
- **D2. 편집 권한**: 입력·수정·업로드를 관리자만 할까, PD(편성자)도 할까? (설계는 권한표 한 줄만 바꾸면 되게 해 둠)
- **D3. 대외비 보기 범위**: 타사 로그라인·연출·작가·제작사를 PD 계정에도 보여 줄까? 업계 자료(대외비 등급) 전체를 PD에게 보여도 되나?
- **D4. 밖으로 나가는 길**: 인쇄 쪽 아래에 출력자 이름·시각을 넣을까? 인쇄 시작을 로그인 이력처럼 기록할까? 엑셀 내보내기는 1단계에서 빼는 것으로 괜찮은가?
- **D5. 기획안·대본 PDF**: 라인업에 연결하지 않음(1단계 권장) / 보관 위치 메모만 / 비공개 저장소에 올리고 관리자만 내려받기(기록 남김) 중 무엇?
- **D6. 기본 화면**: 기본 보기를 자사 라인업으로 할까, 경쟁 비교로 할까? 기본 기간(지난달 ~ 6개월 뒤, 8개월)이 맞나?
- **D7. 이력 범위**: 업계 종합본의 과거 시트(2025 상반기부터)까지 넣을까, 2026 하반기 이후만 넣을까?
- **D8. 업계 종합본의 ENA 줄**: 자사 라인업 자료를 기준으로 하고 업계 자료의 ENA 줄은 건너뛰되 차이만 알려 주는 방식이 맞나?
- **D9. 실제 편성과 다를 때**: 방영이 시작된 뒤 실제 첫 방송일(편성표·닐슨)이 라인업과 다르면, 화면에 "실제 첫 방송 ○/○"만 표시하고 라인업 값은 사람이 고치게 할까(권장), 자동으로 실제 날짜로 바꿀까?
- **D10. 맞대결 기준**: "시간이 겹친다"를 같은 요일 + 시작 시각 ±90분으로 볼까, 방송 시간대가 실제로 겹칠 때만으로 볼까?
- **D11. 다른 자사 채널**: ENA Play·ENA Drama 라인업은 언제, 어떤 자료(표준 양식?)로 받을까? PD 계정별 담당 채널을 기본 거르기로 쓸지?
- **D12. 타사 예능 라인업**: 받을 자료가 있나? 있으면 경쟁 비교에 예능 묶음을 함께 연다.
- **D13. 자료 기준일 경고**: 자료 기준일이 며칠 지나면 "오래된 자료" 표시를 할까(제안 30일)?
- **D14. 시청률 표시(2단계)**: 상세 패널에 DB 시청률 값을 직접 보여 줄까, 링크만 둘까? 보여 준다면 타깃은 채널 기본 타깃(A 묶음 수도권 2049, B 묶음 유료방송가구)으로.
- **D15. 마이그레이션 적용 승인**: §8.2 테이블 9개(새 파일 하나)를 적용해도 되는지(적용 전 최종 SQL 검토 요청 예정).
