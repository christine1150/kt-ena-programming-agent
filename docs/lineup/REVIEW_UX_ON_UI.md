## 2. 디자이너 확인 질문(§13) 16개에 대한 답

| # | 질문 요지 | 답 | 이유 |
|---|---|---|---|
| 1 | 외부 편성센터 링크를 남길까 | 전역 메뉴는 내부 `/lineup`으로 바꾸고, 외부 링크는 화면 머리 오른쪽에 작은 글자 `기존 편성센터 ↗`로 **전환 기간에만** 남긴다. 없애는 시점은 사용자 결정(UX_PLAN D1). | 이 화면이 같은 정보를 다 보여 주기 전까지 비교 수단이 필요하다. 메뉴에 둘 다 두면 어느 쪽이 기준인지 헷갈린다. |
| 2 | 첫 화면은 자사인가 경쟁인가, 계정마다 다르게? | **자사 라인업(ENA)**, PD·관리자 같게. | 매일 묻는 질문(지금 방영 중·다음 작품·빈 주)은 자사 화면에서 풀린다. 맞대결은 자사 막대의 상세 패널에서 한 번에 넘어간다. 역할마다 첫 화면이 다르면 같은 링크가 사람마다 다르게 열린다(주소가 상태의 원본이라는 앱 관례와 어긋남). |
| 3 | 블록을 월화·수목·금토·토일·그 밖으로 바꿔도 되나, "원자료 그대로" 전환이 필요하나 | **월화 · 수목 · 주말(금·토·일) · 그 밖 4묶음**을 권한다. 금토/토일로 나누지 않는다. "원자료 그대로" 전환은 만들지 않는다. | F2: 업계 사람들은 토 섹션에서 금토극·토일극을 함께 본다. 금토와 토일을 다른 묶음으로 떼면 "토요일 밤 맞대결"이 두 묶음으로 갈라지고, UI 초안의 맞대결 강조("같은 블록")도 금토극 경쟁작을 놓친다. 같은 작품 두 번 그리기는 주말 한 묶음 + 작품 하나 = 막대 하나로 이미 해결된다. 줄 머리에 `금토 21:50` · `토 22:40 · 일 22:30`처럼 요일을 적으면 금토/토일 구분도 읽힌다. |
| 4 | 주 칸 맞춤으로 충분한가 | **일 단위 위치 + 주 격자선**, 그리고 **같은 자리에서 이어지는 작품은 끝을 다음 방송 주기 직전까지 늘려 붙인다**(아래 §3 C1). | F1·F9: 첫 방송 요일과 연휴 겹침은 PD가 실제로 묻는 질문이다. 주 칸 맞춤은 오늘선과도 어긋난다(§4 P1). 디자이너가 걱정한 "이어지는 작품 사이 가짜 틈"은 '이어 붙이기' 규칙으로 없앤다. |
| 5 | 기타에 무엇이, 단막극·OTT 수급작은 드라마인가 | 장르 4종 동의. **기타 = 교양·다큐·스포츠 중계 편성·특선 영화 등**. 음악 프로그램은 예능, 시상식·페스티벌 중계·협찬형은 사업형·행사. **단막극 = 드라마**, **OTT 수급작 = 드라마 채움 + `OTT 수급작` 글자**(UI 초안 그대로). 스포츠 중계로 정규 편성이 쉬는 것은 장르가 아니라 결방(빗금)이다. | OTT 수급작은 실제로 드라마가 나가는 자리라 "정보 없음 회색"으로 두면 사실과 다르다. UX_PLAN의 회색 점선 표현은 철회한다. 다만 데이터 모델에서 작품 없는 칸에도 장르를 둘 칸이 필요하다(§5). |
| 6 | 확정/예정은 누가 정하나, 자사 미래 작품 기본은 | **표시는 두 가지만**: 실선(기본) / 점선(가안). 점선은 **그 항목에 가안 표시가 있을 때만**(관리자가 표시하거나 셀에 `가제`·`예정`·`?`가 적혀 있을 때). 자사 공식 라인업에서 온 미래 작품은 실선. 파일 단위 "변경 가능" 주석은 막대를 점선으로 바꾸지 않고 **머리의 자료 기준 띠와 상세 패널**에 쓴다. | F5: 그런 주석은 방송사 단독 엑셀에만 있다. 그 파일의 막대만 점선이 되면, 같은 작품이 어느 자료가 이겼느냐에 따라 실선·점선을 오가 뜻이 흔들린다. 타사 미래 작품은 전부 "바뀔 수 있음"이라 다 점선으로 칠하면 정보가 없다. |
| 7 | 종료 추정을 블록으로 해도 되나, 첫방 ◆만 찍는 선택지 | 주당 횟수는 **자리의 요일 수**(월화·수목·금토·토일 = 2, 주 1회 자리 = 1, `1일 2회` = 하루 2회)로 정하고 관리자가 덮어쓸 수 있게 한다. 둘 다 모르면 추정하지 않고 **첫 방송 표시(▶) + `끝 모름`**. 추정은 결방이 없다고 보고 계산하며 툴팁에 그렇게 쓴다. | 회차만 있고 끝이 없는 자료(방송사 캡처)가 실제로 있다. 블록 요일 수는 원자료 줄 머리에서 이미 알 수 있는 사실이라 지어낸 값이 아니다. |
| 8 | 바뀜 점 기본으로 켜나, 비교 기준은 | 기본 켬. 기준은 **최근 14일 안에 바뀐 것**(업로드·수동 입력 모두). 바뀐 것만 모아 보기는 목록 보기의 빠른 거르기 `최근 바뀐 것`. "고른 날짜 기준 비교"는 2단계(그때 알던 라인업 보기). | 출처가 여럿(자사·업계·방송사 단독·수동)이라 "직전 자료"가 하나로 정해지지 않는다. UX_PLAN의 7일은 업계 자료가 2주~한 달 간격으로 오는 것에 비해 짧아 14일로 고친다. |
| 9 | 기획안 첨부를 보여 줄까 | **1단계는 연결하지 않는다**(UX_PLAN D5 권장안). 2단계에서 한다면: 비공개 저장소, 관리자만 내려받기, 내려받기 기록, 인쇄에서 제외, 화면에는 "기획안 있음" 표시만. | 원자료 자체가 공유 메일에서 엄격한 보안 유지를 요구한 자료다. 화면에 띄우는 순간 퍼지는 길이 하나 늘어난다. |
| 10 | 시청률 겹쳐 보기 타깃·위치 | **1단계는 상세 패널의 링크만**(프로그램 성과·시청률 표). 2단계에서 패널에 DB 값 그대로: 자사 = 채널 기본 타깃(A 묶음 수도권 2049, B 묶음 유료방송가구), 타사 = 경쟁 시청률 자료의 같은 타깃(지상파 가구 값의 지역 예외 주의, `competitorRegion.ts`). **막대 끝 숫자는 넣지 않는다.** | 막대 끝 숫자는 글자 자리를 빼앗고(잘림 문제 재발), 인쇄물에 시청률이 라인업과 섞여 나간다. 회차별 표는 회차 번호 대응 자료가 있을 때만(화면에서 평균·증감 계산 금지). |
| 11 | 방송사를 모두 기본 표시할까 | **모두 표시 + 빈 행 숨김 켬**(동의). 방송사 순서는 모든 묶음에서 고정. 줄이려면 방송사 거르기 칩. 경쟁 비교의 기본 밀도는 **촘촘**. | 자주 맞붙는 곳은 작품마다 달라 고정 목록이 맞지 않는다. 빈 행 숨김만으로 한 반기 시트 47줄 중 상당수가 빠진다. 경쟁 비교는 제목이 핵심이라 보조줄 없이도 된다. |
| 12 | 자사 전체 보기의 블록 기준 통일? | **한 화면 한 기준으로 통일**(동의). | 위아래 채널 비교가 기준이 같을 때만 성립한다. |
| 13 | 행사 띠는 누가 입력, 스포츠 결방 자동 연결? | 관리자가 관리 화면의 행사 탭에서 입력. 업로드 중 `올림픽`·`아시안게임` 같은 사유 셀을 만나면 **행사 만들기를 제안**하고, 확인하면 결방 칸과 연결한다. 자동으로 만들지는 않는다. 공휴일은 기존 표 그대로. | 셀 글자만으로 대회 기간을 알 수 없다(지어내기 금지). 한 번 입력한 대회는 여러 방송사 결방 칸에 다시 쓴다. |
| 14 | 인쇄 대외비 문구·출력자·상세 빼기 | `대외비 · 외부 반출 금지` + **출력자 이름 + 출력 시각 + 출처별 자료 기준일**. 인쇄 각주에는 제목·기간·회차만, **줄거리 소개는 어떤 인쇄에도 넣지 않는다**. 주연·제작사는 기본 밀도 인쇄에서만 나온다(촘촘 인쇄 기본이면 자연히 빠짐). | 종이는 화면보다 통제가 어렵다. 출력자를 찍어야 유출 경로를 거꾸로 찾을 수 있다. |
| 15 | 휴대폰은 목록 기본, 경쟁 비교 필요? | 동의. 경쟁 비교도 휴대폰에서는 **묶음별 목록**(월화·수목·주말)으로, `격자로 보기` 전환 가능. | 휴대폰에서 방송사 9곳 × 6개월 격자는 읽히지 않는다. 회의 중 "이번 주말 타사 뭐 해?" 확인은 목록으로 충분하다. |
| 16 | 밝은 화면만? | 동의. | 앱의 다른 화면과 ENA 브랜드 규칙(콘텐츠 면 흰색)에 맞춘다. |

## 3. 두 초안의 충돌과 권고

### 3.1 한눈 표

| # | 주제 | UI 초안 | UX 초안 | 권고 | 결정 근거(요약) |
|---|---|---|---|---|---|
| C1 | 시간 축 | 막대를 월요일 시작 주 칸에 맞춤 | 하루 단위 축, 막대는 실제 방송일 | **일 단위 위치 + 주 격자선 + '이어 붙이기'**(아래) | F1·F9, 오늘선 불일치(§4 P1) |
| C2 | 확대 | 길이 3단계(3개월·6개월·1년) | 확대 4단계(주·월·분기·1년) + 기간 따로 | **UI 3단계 채택**. 주소 `zoom` 대신 `len=3|6|12` + `from` | 화면 폭 맞춤에서는 길이가 곧 확대다. 조작 두 개는 같은 일을 한다 |
| C3 | 비교 묶음 | 월화·수목·금토·토일·그 밖 | 월화·수목·주말(금·토·일)·기타 | **UX 4묶음 채택**, 줄 머리에 요일 표기 | F2·F3 |

### 3.2 큰 충돌 다섯 개의 자세한 판단

**C1. 시간 축 — 일 단위 위치 + 주 격자선 + '이어 붙이기'**

- UI 초안의 장점은 정당하다: 같은 자리에서 월화극이 화요일에 끝나고 다음 작품이 다음 월요일에 시작하면, 일 단위 축에서는 수~일 5일(6개월 보기에서 약 32px)이 빈 틈처럼 보인다. PD가 "자리가 빈다"로 잘못 읽을 수 있다.
- 그러나 주 칸 맞춤에는 더 큰 비용이 있다.
  1. **오늘선과 어긋난다**: UI 초안은 오늘선을 요일 비례로 그리면서 막대는 주 칸 전체를 채운다. 화요일에 끝난 월화극은 그 주 수~일에 "방영 중"처럼 보이고, 금토·토일 신작은 시작 주 월~목에 이미 시작한 것처럼 보인다. PD는 평일에 이 화면을 본다.
  2. **첫 방송 요일과 연휴**(F9): 주말극 둘째 날과 월화극 첫 주가 한 연휴에 걸치는지 주 칸에서는 보이지 않는다.
  3. **단발·이틀 행사**: 토·일 이틀 행사가 주 칸 하나에 묻힌다.
- 권고 규칙:
  - 막대 **시작 = 실제 첫 방송일**(주 단위 자료는 그 주의 그 묶음 첫 요일 — 원자료 섹션이 알려 주는 사실, F1).
  - 막대 **끝 = 마지막 방송일**. 단, **같은 자리의 다음 작품이 바로 다음 방송 주기에 시작하면** 끝을 다음 작품 시작 전날까지 늘려 붙인다(이어 붙이기, 사이 2px 틈은 UI 초안대로). 그래서 가짜 틈은 생기지 않고, 정말 한 주기 이상 비면 틈이 보이고 `비어 있음 N주`가 붙는다.
  - 상태(방영 중·종영)는 그림이 아니라 서버가 날짜로 정해 툴팁·패널·목록에 쓴다.
- "블록마다 들쭉날쭉" 걱정: 한 묶음 안의 줄은 요일이 같아(월화는 모두 월요일 시작) 줄끼리 맞는다. 묶음 사이의 하루 이틀 차이는 실제 사실이다.
- 1년 보기(주 22px, 하루 3px)에서는 두 방식의 차이가 거의 안 보이므로 비용도 거의 없다.

**C3. 비교 묶음 — 주말 한 묶음**

- F2가 결정적이다. 업계 종이에서 토 섹션은 금토극(지상파)과 토일극(지상파·종편·케이블)을 함께 놓는다. PD가 묻는 "우리 주말 작품의 경쟁 상대"는 토요일 밤 전체다.
- 금토/토일로 나누면: ① 토요일 밤 비교가 두 묶음으로 갈라지고 ② 맞대결 강조가 "같은 블록"만 보므로 금토 경쟁작이 흐려지며 ③ ENA 줄이 금토·토일 두 묶음에 각각 고정돼 줄만 늘어난다.
- F3에 따라 묶음 소속은 **요일 부분집합 규칙**으로 정한다: {수}·{목}·{수,목} → 수목, {금}·{토}·{일}·{금,토}·{토,일} → 주말. UI 초안대로라면 수요일만·목요일만 줄이 "그 밖"으로 빠지는데, 원자료는 이들을 수목 섹션에 둔다.
- 주말 묶음 안 줄 순서는 UI 초안의 **방송사 고정 순서**를 그대로 쓰고, 줄 머리에 요일을 적는다(`MBC 금토 21:50`처럼 방송사 이름은 공개 정보).

**C4. 월 단위 날짜 — 범위 괄호**

- F8: 월 단위 범위는 실제 방영 기간보다 길고, 이어지는 작품끼리 한 달씩 겹친다.
- UI 초안의 "양 끝 흐린 막대"는 흐림 폭이 주 하나(약 45px)뿐이라 가운데 대부분이 꽉 찬 막대로 보인다 → "이 기간에 방송한다"로 읽힌다(실제보다 70% 이상 긴 기간). 범위가 겹치는 앞뒤 작품은 UI 초안의 줄 추가 규칙 때문에 두 줄로 쌓여 "두 작품을 동시에 방송"처럼 보인다.
- 권고: 그 줄 아래쪽 8px 보조 띠에 **얇은 범위 괄호**(├────┤, 장르 진한 색 2px)와 그 위 제목 + `월 단위` 칩 + 원문 기간(`3~4월 중`). 괄호끼리 겹치면 보조 띠 안에서만 한 칸 더 쓴다(행 높이 +8px). "막대 = 방송 기간"이라는 뜻을 지킨다.
- 실제로는 같은 작품이 업계 종합본(주 단위)에도 있으면 더 정밀한 쪽이 이기므로(UX_PLAN §4.5), 월 단위만 남는 경우는 드물다. 드문 경우를 막대처럼 보이게 할 이유가 없다.

**C2·C5. 확대와 기본 기간 — UI 채택**

- 화면 폭 맞춤이 기본인 이상 "기간 길이"가 곧 확대 정도다. UX 초안의 확대 4단계 + 기간 고르기는 같은 것을 두 번 조작하게 한다. UI 초안의 3단계(3·6·12개월) + ‹ › + 월 이동 띠가 더 단순하다.
- 기본 6개월(이번 달부터)은 자사 원자료 범위·옛 화면의 "이번달부터" 습관과 같다. 지난달에 시작해 방영 중인 작품은 왼쪽 끝에 `◂` + 따라붙는 제목으로 여전히 읽힌다. 8개월로 넓히면 주 폭이 45px → 35px로 줄어 글자 자리가 준다.
- 보완: 도구줄에 `지난달부터` 빠른 단추(현재 방영작의 시작·맞대결을 볼 때). 주소는 `from=YYYY-MM&len=6`.

## 6. 핵심 충돌과 권고 — 10줄 요약

1. **시간 축**: 주 칸 맞춤(UI) 대신 **일 단위 위치 + 주 격자선**, 같은 자리의 연속 작품은 끝을 다음 작품 시작 전까지 **이어 붙여** 가짜 틈을 없앤다 — 오늘선 오판과 연휴·첫 방송 요일 문제를 함께 푼다.
2. **확대·기본 기간**: UI 안을 받는다 — 길이 3단계(3·6·12개월), 기본은 **이번 달부터 6개월**, `지난달부터` 빠른 단추만 더한다.
3. **비교 묶음**: 금토/토일 분리(UI) 대신 **월화·수목·주말·그 밖 4묶음** — 업계 종이의 토 섹션처럼 토요일 밤 경쟁을 한곳에 두고, 수·목·금 단독 줄도 원자료 섹션대로 넣는다.
4. **월 단위 날짜**: 흐린 막대(UI) 대신 **얇은 범위 괄호 + `월 단위` 칩 + 원문 기간** — 범위가 실제 방영보다 길고 서로 겹쳐서 막대로 그리면 방송 기간으로 오독된다.
5. **확정/예정**: 표시는 실선/점선 두 가지, **점선은 그 항목에 가안 표시가 있을 때만**. 파일 단위 "변경 가능" 주석은 머리 띠·패널로 옮긴다(종합본에는 그런 주석이 없다).
6. **색·채움**: UI 안을 받는다 — 옅은 채움 + 진한 글자, 예능 청록, 기타 초록, 타사도 장르색, 회색은 "정보 없음" 전용.
7. **겹침**: 단발·이틀 행사가 정규 편성 위에 오면 **겹쳐 그리고 결방 조각**을 넣는다. 줄 추가는 연속 편성끼리 겹칠 때만.
8. **보기·편집 경로**: 탭은 자사 라인업·경쟁 비교·**목록**, 편집은 **`/lineup/manage`**(관리자 화면 아래가 아님), 지우기는 **보관 + 이력**.
9. **대외비**: 줄임말을 코드 별칭(`programAlias.ts`)에 넣지 않고 DB에 둔다. 인쇄에는 출력자·출처별 기준일을 찍고 줄거리는 빼며, 툴팁 대신 번호 각주를 단다.
10. **고쳐야 할 UI 세부**: 맞대결 흐림은 글자 말고 장식만, 공휴일 빨강은 오늘선과 분리, 월 이동 띠에 해 표시, 비교 보기 기본은 촘촘, 원자료 주 날짜 요일 서술(토요일) 바로잡기.
