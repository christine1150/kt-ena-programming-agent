# 데이터 품질 문제 대응

출발점은 **관리자 › 자료 수신·반영 현황**이다. 채널×자료 종류 칸마다 상태가 나온다.

| 상태 | 뜻 | 먼저 할 일 |
|---|---|---|
| 정상 | 반영됐고 사전 계산(마트)도 최신 | 없음 |
| 미수신 | 어제까지 기준 빠진 날이 있다 | 메일 자동 수집 상태 확인 → 안 왔으면 파일을 받아 직접 업로드. skyUHD는 일정이 불규칙해 미수신을 세지 않는다 |
| 수집됨·미반영 | 파일은 받았으나 적재가 끝나지 않았다 | 업로드 결과의 오류 문구(파일·시트·행·열·원인·수정 예시)를 보고 고쳐 다시 올린다 |
| 실패 | 적재가 실패했고 이전 반영본이 그대로 유지됐다 | 오류 문구 확인 후 같은 파일을 다시 올린다(실패한 파일은 정상 재시도된다) |
| 재계산 대기 | 반영은 됐지만 마트가 이전 계산이다 | 화면 숫자가 이전 값일 수 있다. 재계산이 끝나면 정상으로 바뀐다 |
| 지연 | 주간 자료가 10일을 넘겼다 | 주간 파일을 받아 올린다 |

## 문제별

**잘못된 양식(시트가 없다, 날짜가 다르다)**: 필수 시트 이름이 오류에 나온다. 파일명 날짜와 시트 안 분석기간이 다르면 적재하지 않는다(다른 날을 덮어쓰지 않도록). 파일을 확인하고 다시 올린다.

**수정본이 왔다**: 같은 날짜를 다시 올리면 '개정 2'로 반영되고 바뀐 채널·타깃·값 차이가 경고로 나온다. 차이를 확인한 뒤 보고서는 새로 만든다(옛 보고서 스냅샷은 그대로 남는다).

**이전 값으로 되돌리고 싶다**: 이전 파일을 다시 올리면 새 개정으로 반영된다(개정 번호를 되돌리는 기능은 없다).

**메일이 두 번 왔다**: 같은 파일은 '변경 없음'으로 건너뛴다. 자동 수집은 실패하면 10분 뒤·30분 뒤 재시도하고 3회가 넘으면 멈춘다(dead-letter) — 상태 패널에 남는다.

**일부만 반영됐다**: 경쟁 채널 표처럼 핵심이 아닌 표가 실패하면 '부분 성공'으로 표시되고 핵심 ratings는 반영된다. ratings 쓰기가 실패하면 되돌렸다는 문구가 나오고 이전 값이 유지된다.

**목표가 덮였다/덮이지 않았다**: 수동으로 입력한 목표는 잠겨서 Channel Master 재업로드가 덮지 않고 이력에 '건너뜀'이 남는다. 잠금은 목표 관리에서 풀 수 있다(해제 이력이 남는다). 잠금 저장소(마이그레이션 20261012)가 적용되기 전에는 이 보호가 작동하지 않는다.

**EPG 미매칭**: 업로드 결과의 미매칭·모호 후보 목록을 본다. 시작시간이 ±60분 안이고 이름이 같으면 맞춘다. 모호하면 가장 가까운 후보로 채우되 모호하다고 표시한다.

**장르 분류율**: 반올림해 100%로 보이지 않는다(내림, 미분류 건수 병기). 미분류가 남았으면 장르 분류 보완에서 채운다.

## 원본과 저장값이 맞는지 의심될 때 (읽기 전용)

```bash
npm run dryrun:engine -- "Nielsen Data/2026/10"
```

로컬 닐슨 일간 원본을 지금 파서로 읽은 값과 DB의 채널 집계를 견주고, 다르면 채널·날짜·필드와 다시 반영할 때의 영향 범위·rollback을 보고한다. **DB에는 읽기만 하고 아무것도 바꾸지 않는다.** 다름이 나오면 원인을 확인하기 전에는 보고서를 다시 만들거나 다시 반영하지 않는다.

주간 파일의 공식 순위와 일별 파생값 비교는 `node --env-file=.env scripts/verify-against-nielsen-aggregate.mjs`(읽기 전용)가 한다.
