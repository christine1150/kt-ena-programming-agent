# Avail 매칭과 예약 복원

Avail(권리)은 콘텐츠·채널별로 '가능 / 불가 / 조건부 / 미확인' 네 가지로 판정된다. **빈칸은 무제한이 아니라 '미확인'** 이다. 실제 Avail 파일 양식은 아직 실제 샘플로 확인하지 못했으므로(출시 보류 H2) 반영 전 미리보기에서 열 매핑을 반드시 확인한다.

## 올리기

1. **관리자 › Avail 관리**에서 파일을 올리면 시트별 양식 감지와 **열 매핑 미리보기**가 나온다. 읽을 수 없는 조각이 있으면 그 행은 '미확인'으로 남는다.
2. 미리보기가 맞으면 **확정 반영**을 누른다. (저장소 마이그레이션 20261013은 적용되어 있다.)
3. 같은 파일·행을 다시 올려도 권리나 횟수가 중복되지 않는다. 일부 행만 담은 파일에서 빠진 행은 철회가 아니다. 전체 스냅샷을 올릴 때는 대상 범위를 지정해야 하고, 범위 안에서 빠진 행은 삭제가 아니라 **철회 후보**(확인 전 '조건부')로 표시된다.
4. 파일 없이 **직접 입력**도 가능하다(제목·채널별 편성 가능 시작일/시각만 입력, 비운 칸은 '미확인').

## 콘텐츠 연결(매칭)

- 이름이 정확히 같고 시즌 표지 충돌이 없으면 자동 연결(공백·문장부호 무시).
- **시즌이 다르거나 편집판·스페셜, 괄호 별칭**은 자동 연결하지 않는다. 후보로만 보이며 운영자가 **연결을 확인**해야 연결된다. 확인하기 전에는 '미확인'이다.
- 같은 계약의 두 표현(콘텐츠별·채널별 파일)이 겹치면 '중복 후보'로 표시되고 확인 전에는 합산하지 않는다. 같은 권리로 확인하면 하나로 통합, 별개로 확인하면 해소된다.

## 개정과 영향

- 계약이 개정되어 만료가 당겨지면 그 권리를 근거로 만든 편성안·슬롯이 **'재검증 필요'** 로 바뀌고 영향 슬롯이 목록으로 나온다. 과거 편성안의 당시 판정은 얼려져 그대로고 현재 효력은 따로 표시된다.
- **확정 직전**에는 최신 권리로 다시 검사해 막는다(확정 준비 검사).
- 별도 승인이 필요한 조건은 승인 증빙(내용 있는 확인)이 없으면 확정할 수 없고, 권리 행이 바뀌면 이전 승인은 인정되지 않는다.

## 예약·취소·복원

- 권리 사용은 **예약 → 소진 → 해제·취소·복원** 이벤트로 원장(`/api/admin/avail/ledger`, 관리자 전용)에 쌓인다(삭제하지 않고 이벤트만 쌓는다). 예약은 편성안이 '확정 대기'로 저장될 때 쓰도록 만들어졌지만, **현재 화면에는 예약을 만드는 버튼이 없고** 확정 준비 검사는 읽기 전용이다.
- **해제(취소)** 하면 횟수가 돌아오고, **실행 취소(undo)** 하면 다시 잡힌다. 그 사이 잔여가 찼으면 복원하지 않는다.
- 실제 방송 실적이 들어오면 예약이 **소진**으로 바뀐다. 같은 실적을 다시 받아도 중복 반영되지 않는다. 방송이 불발되면 소진이 되돌아간다.
- ENA·ENA Play가 한 풀을 공유할 때 마지막 1회를 두 사람이 동시에 잡으면 한 건만 성공한다(메모리 원장으로 시험). DB의 SQL 함수는 풀 단위 잠금으로 같은 일을 하도록 작성돼 있지만 DB에서 동시 실행으로 시험하지는 못했다(출시 보류 H5).
- 예약 없이 방송된 실적은 한도를 넘어도 사실로 기록하고 초과를 표시한다.

## 권리가 없을 때

Avail이 하나도 없어도 성과 분석과 탐색은 작동하고, 후보는 '권리 미확인'으로 표시되며 실행 가능 판정은 보류된다. 권리 부족으로 해가 없으면 위반 조건을 보여 주고 임의로 완화하지 않는다.
