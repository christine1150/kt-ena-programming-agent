# 보고서 재발행

보고서는 **스냅샷(`rs-…` ID)** 으로 한 번 만들어 저장하고, 웹·Word·PPT·PDF가 같은 스냅샷을 읽는다. 같은 보고서는 어느 형식으로 열어도 숫자·판단·문장이 같다.

## 이름과 ID

- 이름: `일간 보고서 · ENA · 2026-10-04(일)`, `주간 보고서 · ENA · 2026-09-28(월) ~ 2026-10-04(일)`, `월간 보고서 · …`. 하루=일간, 7일=주간, 28~31일=월간으로 구분되고 같은 날짜의 일간·주간은 이름·파일명·ID가 서로 다르다.
- ID는 **내용 지문**이다. 내용(AI 문장 포함)이 같으면 같은 ID, 하나라도 바뀌면 다른 ID가 된다. 저장된 ID는 덮어쓰이지 않는다.
- 분석일(분석 종료일)과 생성일은 따로 적힌다. 파일 바닥글·화면의 스냅샷 줄에 ID·분석일·생성 시각·데이터 기준일·수신 일수가 있다.

## 언제 다시 만드나

| 상황 | 할 일 |
|---|---|
| 자료가 수정본으로 바뀌었다(개정 반영) | 보고서 화면에서 **'최신 데이터로 다시 생성'** → 새 ID로 저장된다. 옛 보고서(옛 ID)는 그대로 남아 이전 숫자를 보존한다 |
| 일간 잠정 값 뒤에 공식 주간·월간 파일이 왔다 | 새로 만든다. 잠정 표시(수신 N/M일)가 없어지고 '확정'으로 표기된다 |
| AI 문장이 마음에 안 든다 | 같은 기간을 다시 만들면 문장이 달라질 수 있다 — 스냅샷이 보장하는 것은 **만든 뒤의 형식 간 일치**이지 재생성 때의 문장 동일이 아니다 |
| 권리·구매 검토가 바뀌었다 | 월간 보고서를 새로 만든다(권리·구매는 읽기만 하고 권리를 소진하지 않는다) |

## 이전 보고서 찾기·열기

- 보고서 화면 스냅샷 줄의 링크 **문서 보기·PDF**가 `/audience-report/view/<ID>`다. ID를 알면 그 주소로 같은 보고서를 다시 연다.
- ID가 저장소에 없으면(캐시를 비운 경우) **다른 내용을 몰래 만들지 않고** "다시 생성" 안내가 나온다.
- 저장에 실패했다고 안내가 뜨면 PDF 버튼이 막히고 다운로드는 파일을 만들 때 다시 계산한다 — 이때 화면과 숫자가 달라질 수 있으니 저장 실패를 먼저 해결한다.

## PDF

서버가 PDF 파일을 만들지 않는다. **문서 보기** 화면에서 인쇄 창의 대상을 'PDF로 저장'으로 고르고 '배경 그래픽'을 켜면 A4 PDF가 된다.

## 다운로드가 오래 걸릴 때

처음 만들 때는 계산·AI 문장 때문에 30초~1분 걸릴 수 있고 경과 초가 보인다. 실패하면 사유와 '다시 시도'가 나온다. 같은 요청을 10분 안에 다시 하면 저장된 스냅샷을 그대로 쓴다(약 2초).

## 보관에 대한 주의

스냅샷은 별도 보관 테이블이 아니라 기존 캐시 테이블을 빌려 저장한다. **캐시를 비우면 보고서 원본이 사라진다** — 반드시 남겨야 하는 보고서는 Word·PPT·PDF 파일로 따로 보관한다(전용 `report_snapshots` 테이블은 승인 대기).

## 문제가 생기면

- 저장을 잠시 끄고 싶으면 `FEATURE_REPORT_SNAPSHOT_STORE=off` 후 재배포(단계 14 이전 동작: 저장 없이 만들고 PDF 버튼 막힘). 자세한 것은 `docs/agent-improvement/RELEASE_READINESS.md` 7절.
- Word·PPT 모양이 이상하면 실제 Word·PowerPoint로 열어 확인한다(자동 검사는 구조까지만 본다).
