# 모델 승격과 회귀

편성 예측·탐색 모델을 바꾸거나, 지금 모델이 나빠졌는지 볼 때의 절차다. **합격선은 아직 승인 전(출시 보류 H7)** 이라 어떤 모델에도 PASS를 내리지 않는다.

## 모델을 바꾸기 전에

1. **버전이 남는지 확인**: 편성안 요약에 모델·특징·장르·제약·설정 버전과 입력 지문이 기록된다(`test:opt02`). 같은 입력이면 같은 지문·같은 결과여야 한다.
2. **시간 순서**: 예측은 목표 주 전날까지의 자료만 쓴다(누수 방지 테스트). 학습 cutoff를 바꾸면 반드시 `npm run test:opt02`를 돌린다.
3. **기준모델 대비**: `npm run opt02:eval`(예측)·`npm run opt05:bench`(검증 A·B)로 같은 holdout·같은 마감에서 MAE·편향·구간 적중을 기준모델(같은 슬롯 평균·같은 프로그램 최근 평균·채널 최근 평균 등)과 견준다. 신규 프로그램(학습 이력 없음)은 기준모델보다 낫지 않으므로 '근거 부족'을 표시한다.
4. **탐색을 바꿀 때**: `npm run opt04:bench`(속도·결과 동일성), `opt04:methods`(탐색 방법 비교). 결과 지문이 같아야 하고 하드 제약 위반은 0이어야 하며, 시간 마감·취소 때도 유효한 최선안을 돌려줘야 한다.

## 승격 판정(`src/lib/idealSchedule/promotion.ts`)

판정은 PASS / LIMITED(일부 집단만 제한) / HOLD(보류) 세 가지로만 나온다.

- 합성 세계 수치만으로는 PASS가 되지 않는다(UNVERIFIED 표시). **실제 자료로 같은 기준을 통과해야 PASS**다.
- 필수 기준: 모델이 기준모델보다 MAE가 낮을 것 · 편향 과다 아님 · 구간 적중이 기준 이상 · 하드 제약 유효해율 100% · 시간 마감 정지 비율 · 선택 편향(낙관) 범위. **측정하지 못한 필수 항목이 있으면 PASS가 될 수 없다.**
- 한 집단만 기준모델보다 뚜렷이 나쁘면(건수 100 이상) 전체 보류가 아니라 그 집단만 제한한다. 건수가 적은 집단(100 미만)의 나쁜 값은 제한 사유로 쓰지 않는다.
- '+20% 달성' 같은 목표 수치는 승격 기준에 두지 않는다.

## 회귀(성능이 떨어졌는지) 보는 법

1. `npm run retrospective` — 저장된 백테스트 결과로 방송이 끝난 주의 예측 대 실적을 채널·타깃별로 낸다. MAE·편향·상대 MAE·범위 적중을 **이전 실행의 표와 나란히** 본다(RETROSPECTIVE.md가 현재 기준선: 2049 MAE 0.034%p·편향 0.002, 가구 MAE 0.036%p·편향 0.008, 범위 적중 86%/77%).
2. 새 모델로 같은 주를 다시 백테스트(편성 화면의 모델 검증 패널)하고, 같은 표를 만들어 비교한다. 같은 타깃끼리만 비교한다.
3. 편향이 한쪽으로 커지거나(예: 가구 편향 0.008 → 0.02) 범위 적중이 크게 떨어지면(예: 70% 아래 — 승인된 기준이 아니라 이 문서의 제안) 승격을 멈추고 이전 버전으로 되돌린다(아래).
4. 개선율은 **같은 모델 기준 기대값 차이**일 뿐 실제 시청률 개선이 아니다. 화면·엑셀·검증 문구에 '실제 개선·검증된 개선·보장'을 쓰지 않는다(`test:opt03` T12).

## 되돌리기

- 모델 코드는 버전 문자열로 구분되고 저장된 편성안은 **저장 당시의 값을 그대로 보존**한다. 새 모델이 나빠 보이면 이전 커밋으로 되돌려 배포한다(DB 변경 없음). 이미 저장된 편성안·보고서 스냅샷은 바뀌지 않는다.
- 저장된 편성안을 현재 모델로 다시 평가하면 값이 달라질 수 있다 — 이때 화면은 '저장 값'과 '재평가 값'을 따로 보여 주고 차이는 수정이 아니라 **모델·자료 버전 차이**라고 안내한다.
