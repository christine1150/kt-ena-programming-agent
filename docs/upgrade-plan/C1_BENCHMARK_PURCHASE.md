# C1. 벤치마크 채널 구매 리스트 — 결과와 구현 명세 (F-2)

- 작성: 2026-11-13 (고도화 계획 F-2, 설계: Claude Fable)
- 스크립트: `scripts/upgrade-plan/c1-benchmark-purchase.mts` (읽기 전용) → `docs/upgrade-plan/c1-benchmark-purchase.json`
- 자료: 닐슨 연간 누적 순위 `market_ytd_rank_snapshot`(2026-01-01~11-10, 216채널), 경쟁 프로그램 `competitor_program_target_ratings`(2025-01~2026-11-09, 개인2049·유료방송가구), 자사 `ratings`(KPI 타깃).
- 배수 정의: 방영 시청률 ÷ 그 채널 같은 자리(평일/주말 × 8대 시간대) **다른 프로그램** 중앙값. 프로그램 배수는 방영별 배수의 중앙값. 자리 평소가 20회 미만이거나 하한(2049 0.005%, 가구 0.01%) 미만이면 그 자리는 계산에서 뺀다.

---

## 0. 결론 한 장

1. **"같은 군 + 순위 ±15위 + 같은 타깃" 규칙은 2049 채널에서는 맞고 가구 채널에서는 빈다.** ENA Drama 4곳·ENA Play 8곳은 잘 잡히지만, ONCE(가구 63위)는 KBS Story 1곳, OLIFE 1곳, ENA Story 2곳, ENA 2곳뿐이다. 순위 간격이 아래쪽으로 갈수록 촘촘해져 ±15위가 시청률로는 0.3~0.5배 폭밖에 안 되기 때문이다. **시청률 0.5~2배 규칙**으로 바꾸면 ONCE 6곳·ENA Story 4곳이 되고 2049 채널은 ±15위와 같은 결과가 나온다. → 구현은 "같은 군 + KPI 타깃 시청률 0.5~2배(2곳 미만이면 4곳이 될 때까지 순위 범위를 넓힘)"로 한다. 사용자 결정(±15위)의 취지("비슷한 순위")를 지키면서 빈 채널을 없애는 수정이며, 관리자 화면에서 채널별 수동 덮어쓰기를 둔다.
2. **벤치마크 채널로 피어를 제한해도 예측이 더 정확해지지 않는다.** 2025-07 이후 자사 신규 투입작 27건(벤치마크 피어 실적이 있는 11건) 백테스트에서 벤치마크 피어 중앙값의 로그 오차 중앙값은 0.50, 모든 케이블 피어 0.47, **"1.0배 고정" 0.36**으로 고정값이 가장 정확하다. 표본이 작아 우열을 단정할 수는 없지만, 벤치마크 제한이 낫다는 근거는 없다. → **예측값은 기존 구매 시뮬레이터 엔진(모든 적격 피어 + 피어 수·방영 수 수축) 그대로 두고, 벤치마크는 후보 풀과 근거 표시에만 쓴다.** 신규작이 "자리 평소 수준"으로 수렴한다는 결과는 F-3(A1 신작 사전값)의 수축 강도를 세게 잡아야 한다는 뜻이기도 하다.
3. **벤치마크 후보 리스트는 PD가 읽을 만한 결과를 낸다.** 자리 평소 하한과 피어당 20회 하한을 넣기 전에는 MBC ON·EDGETV·CNTV의 2049 값(대부분 0)이 47배·31배 같은 배수를 만들었다. 하한을 넣은 뒤 상위 후보는 ENA Drama 전원일기(MBC ON 2.7배·726회)·응답하라 1988(2곳 2.5배)·쓸쓸하고 찬란하神 도깨비·태양의 후예·나의 아저씨, ONCE 사랑이 뭐길래·복희 누나·철인왕후(CNTV)·한국인의 밥상(EDGETV 1.9배·702회), ENA Story 이제 만나러 갑니다(CH view 1.46배·1,349회)·식객 허영만의 백반기행 등이다.
4. **다른 자사 채널이 이미 트는 작품도 후보에 남긴다.** 지상파 예능 판권은 대부분 채널 단위라 이 채널에서 틀려면 추가 구매가 필요하다(사용자 정정 2026-11-13). "다른 자사 채널(ENA Play) 방영 중 · 추가 구매 필요"로 표시하고, 그 채널의 자사 실적 배수를 근거 열에 같이 보인다(자사 실적은 경쟁 1곳보다 강한 근거). 고도화 계획 C3 "자사 간 이동(구매 비용 없음)"은 **Avail 권리가 그 채널에 있을 때만**으로 고친다.
5. **1곳 근거 후보가 많다.** 벤치마크 후보의 절반 이상이 피어 1곳이다(근거 "약함"). 2곳 이상·48회 이상(보통)과 3곳(충분)은 ENA Play·ONCE에서만 여럿 나온다. 근거 수준 표기(`recoEvidence.ts` 기준)는 그대로 쓰고, 정렬은 수축 배수 순을 유지한다.
6. **장르 필터가 없으면 ENA Play 후보가 Mnet 음악 예능(스트릿 우먼 파이터·쇼미더머니)으로 채워진다.** 경쟁 작품 장르 채움(F2)이 끝나면 채널 성격에 맞지 않는 장르를 기본 숨김(펼치면 보임)으로 둔다.

- 프로그램 자료가 없는 채널(KBS드라마·tvN DRAMA·하이라이트TV·EBS)은 선정 결과에 넣되 "자료 없음"으로 표시한다. 닐슨 경쟁 프로그램 시트에 추가되면 자동으로 살아난다.

## 3. 구현 명세 (Sonnet 구간 S-3)

### 3.1 DB

**신규 마이그레이션 1 — 벤치마크 채널**

- 함수 `benchmark_channels(p_own_channel_code text)` → (snap_name, competitor_name, group_key, rank, rating, ratio_to_own, rule text['ratio'|'widen'|'manual'], has_program_data boolean). 입력: `market_ytd_rank_snapshot` 최신 `date_to`, 군 정의 테이블 `channel_groups`(신규, 아래), 허브 목록, `competitor_program_target_ratings`에 최근 52주 행이 있는지.
- 테이블 `channel_groups(snap_name text pk, group_key text, competitor_name text null, iptv_name text null, is_hub boolean, note text)` — 지금 스크립트 상수(`competitor-channel-profiles.mts`·`c1-benchmark-purchase.mts`의 GROUP)를 옮긴다. 관리자 화면에서 편집.
- 테이블 `benchmark_overrides(own_channel_code text, snap_name text, action text check in ('add','remove'), updated_by, updated_at, pk(own_channel_code, snap_name))`.

**신규 마이그레이션 2 — 벤치마크 근거 열**

- `purchase_recommendations`에 열 추가: `benchmark_peers jsonb`(채널별 {name, mult, airings}), `benchmark_mult numeric`(벤치마크 피어 배수 중앙값, 없으면 null), `benchmark_peer_count int`, `other_own_channels text[]`(이 작품을 트는 다른 자사 채널 코드), `other_own_mult numeric`(그 채널의 자리 평소 대비 배수).
- 기존 열·정렬(`shrunkVsAvg`)은 그대로. 화면 정렬은 "벤치마크 피어 있음 → 수축 배수" 순.

### 3.2 서버

- `src/lib/purchaseSim/benchmark.ts`(신규, 순수 함수): `selectBenchmark(own: {rank, rating}, candidates: {...}[], overrides)` — 0.5~2배 규칙 → 2곳 미만이면 ±15위부터 5위씩 넓혀 4곳 → 수동 덮어쓰기 적용. 테스트는 §1.1 표 6행을 고정값으로.
- `recommend.ts` `computeRecommendations`: 피어 인덱스 계산 후 벤치마크 집합을 받아 `benchmark_peers`·`benchmark_mult`·`other_own_*`를 채운다. **예측값·진입 기준·정렬 로직은 바꾸지 않는다.** 자리 평소 하한은 엔진 `PARAMS.minBaselineN` 경로를 따르며, 벤치마크 열 계산에는 `BASE_FLOOR`(2049 0.005, 가구 0.01)를 추가한다.
- `scripts/refresh-purchase-recommendations.ts`: 벤치마크 열 포함 갱신. 728일 창 시간 초과는 `get_purchase_sim_inputs_multi` 호출을 채널×분기로 나눠 실행(별도 커밋).
- `/api/scheduling/purchase-sim/benchmark`(신규, 읽기): 채널의 벤치마크 채널 목록 + 선정 이유 한 줄("드라마군, 가구 0.096%로 ONCE의 1.6배").

### 3.3 화면 (`src/app/ideal-schedule/purchase/`)

- 탭 "벤치마크 후보"(기존 추천 탭 옆): 상단에 벤치마크 채널 칩(이유 툴팁, 관리자면 추가·제외) → 표: 작품(풀네임) · 장르 · 벤치마크 배수(채널별 "SBS Plus 1.76배·213회") · 전체 피어 배수·곳수·횟수 · 근거 수준 · 예상 시청률(기존 엔진 값, 범위) · 다른 자사 채널 방영 중(추가 구매 필요, 자사 배수) · 재방 내성(자사 실적 있을 때만).
- 장르가 채널 성격과 다른 후보는 기본 접힘("장르 다른 후보 N개 보기") — F2 뒤.
- 홈 "풀 밖 대안"은 이 표의 상위 2건(벤치마크 피어 있는 후보 우선).
