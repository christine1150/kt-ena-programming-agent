- 작성: 2026-11-13 (설계: Claude Fable, 구현 예정: Claude Sonnet)
- 목적: 지금까지 쌓인 DB·연구 결과를 바탕으로, 편성 PD의 업무 효율을 실제로 높이는 다음 단계를 정한다.
- 읽는 순서: §0 한 장 요약 → §1 가진 것 → §3 과제 → §4 로드맵 → §5 결정 필요 항목. 구현자는 §3의 각 과제에 있는 "구현 지시"만 읽어도 착수할 수 있게 썼다.

## 0. 한 장 요약

지난 석 달 동안 자료는 크게 늘었다(닐슨 자사·경쟁 36채널, IPTV 셋톱 41채널 116만 행, 분당 시청률, skyUHD 셋톱, Avail 권리, 네이버 편성 패턴, 장르 맵, 공휴일, OLIFE 지역 분류). 그런데 **화면은 아직 "자사 자료만으로 자사 편성을 다듬는" 구조**다. 경쟁 채널 자료는 "비교 표"로만 쓰이고, 제언·예측·구매 추천의 근거로는 거의 들어가지 않는다. 또 예측은 신작에서 약하고, 제언의 "기대 효과(+3~30%)"는 실측 근거가 없으며, 홈·채널 심층은 한 파일 6천~8천 줄짜리 클라이언트 컴포넌트라 느리고 고치기 어렵다.

그래서 이번 고도화의 축은 여섯 가지다.

| 축 | 한 줄 목표 | 대표 과제 |
|---|---|---|
| A. 예측 | 신작·공휴일에서 틀리는 폭을 줄이고, 틀리는 폭을 숨기지 않는다 | A1 신작 사전값, A2 공휴일 계수, A3 예측 적중 카드 |
| B. 편성 제언 | "자사 풀 안의 교체"에서 "실측 효과 + 비교군 우수 사례" 기반 처방으로 | B1 편성 변경 사후검증, B2 우수 사례 라이브러리, B3 제언 성적표 |
| C. 구매 후보 | 비슷한 군·순위 채널에서 잘 되는 작품을 자동으로 골라 근거와 함께 | C1 벤치마크 구매 리스트, C2 권리·소진 연동 |
| D. 레이아웃 | PD의 3분 루틴에 맞춰 "오늘 결정할 것" 중심으로 | D1 결정 큐, D2 채널 심층 분할 |
| E. 속도 | 측정 → 사전 계산 확장 → 지연 로딩 | E1 계측, E2 분할·지연 로딩, E3 사전 계산 |
| F. 운영 | IPTV가 끊겨도(1월) 닐슨만으로 계속 도는 구조 | F1 IPTV 마감, F2 경쟁 장르 분류, F3 데이터 품질 경보 |

권장 순서는 **0단계(기반·계측, 1주) → 1단계(효과 실측·구매 리스트·채널 심층 분할, 3주) → 2단계(우수 사례·결정 큐·공휴일, 4주) → 3단계(IPTV 마감·장기 연구, 12월 말~1월)** 다. 상세는 §4.

### 1.2 검증된 사실 (설계의 전제)

연구 문서에서 이미 데이터로 확인된 것들이다. 새 기능은 이 사실과 어긋나지 않아야 한다.

1. 예측 엔진은 PD식 단순 규칙보다 한 편 오차가 16~24% 작다. 그러나 **신작은 "그 자리 4주 평균" 대비 2~11%밖에 낫지 않고**, 신작 자리 244개가 가장 큰 약점이다. (SKILL_BASELINE, D3)
2. 닐슨은 회차 단위로 가구 2~5배, 2049 4~10배 흔들린다. ENA Drama·ENA Play 2049는 회차 비교가 불가능하고 4주 평균으로만 판단해야 한다. (IPTV A1)
3. 1~2회 시청률을 알면 3~10회 평균은 80%가 0.70~1.41배 안이다. 회차가 진행되며 크게 오르내리는 평균 곡선은 없다. (IPTV B2)
4. 경쟁 신작 첫 회와 겹쳐도 우리 시청률 변화는 2~4% 이내였다. **"경쟁 회피"는 편성 근거가 못 된다.** (IPTV D2)
5. 적합도 판정이 IPTV에서도 같은 방향인 비율은 49~82%, 엇갈림은 대부분 닐슨 "교체"→IPTV "관찰"이다. 교체 판정은 보수적으로 다뤄야 한다. (IPTV A2)
6. 과거 이동 73건 중 상승 37·비슷 9·하락 27. **"교체·이동하면 +3~30%"라는 기대 효과는 실측 근거가 없다.** (gap-playbook 3단계)
7. 자사 채널끼리 같은 작품을 같은 날 겹쳐 재방하는 구조를 풀어도 분산 효과는 작다(ENA Drama만 2~6%). (OWN_OVERLAP_P6)
8. 득점 집중도: OLIFE 상위 3작품 82%, ENA Story 인간극장 46%, ENA Play 타사 예능 재방 3개 41%. 대표작이 흔들리면 채널이 흔들린다. (ALL_CHANNELS_SUMMARY)
9. 재방 내성이 확인된 작품이 있다(벌거벗은 세계사·모범택시 3·김부장·야인시대·왕가네 식구들·유 퀴즈·나 혼자 산다 등). 본방은 강하지만 재방에서 약한 작품도 있다(허수아비·신병4·옥중화). (HIDDEN_TITLES_OWN)
10. 광고주 청약 기준은 닐슨 수도권 2049다. IPTV는 보조이며 값을 섞지 않는다. IPTV는 12월 말 이후 보장되지 않는다.

## 2. 설계 원칙 (바뀌지 않는 것)

1. **숫자는 DB(또는 서버 순수 함수)가 만들고 LLM·화면은 읽는다.** 새 지표는 DB 함수나 `src/lib/*`의 순수 함수로 만들고 테스트를 붙인다.
2. **닐슨이 공식, IPTV는 보조.** IPTV 값은 "IPTV 셋톱" 표기를 붙여 따로 두고 한 표에서 순위를 섞지 않는다. IPTV가 없어도(1월 이후) 모든 신규 기능이 동작해야 한다 — 각 기능에 "IPTV 없음" 테스트 케이스를 둔다.
3. **검증 통과 항목만 화면에.** 예측·판정 로직을 바꾸는 과제는 학습/검증 기간을 나눈 백테스트에서 현재보다 낫다는 결과(95% 구간이 1 미만)가 있어야 운영에 넣는다. 과장 금지("몰입도보다 정확하다"처럼 구분 안 되는 개선을 개선이라 쓰지 않는다).
4. **Delta-only.** 기존 판정 공식·점수는 그대로 두고 표시·근거·후보 풀을 더한다. 바꿀 때는 캐시 버전을 올린다(제안 캐시 v7 등).
5. **기대 효과는 실측 분포로만 말한다.** "+3~30%"처럼 근거 없는 범위를 쓰지 않는다. 사례 수 하한(유형별 20~30건)을 둔다.
6. **문구 원칙**: 절대 수치 먼저, 지수는 괄호. 풀네임 우선. 추상어 단독 금지, 3초 안에 현황·원인·조치가 읽히게. 본방=각 채널 첫 방송.
7. **범위 밖**: ROI·가격 계산, 개인 패널 추적, 외부 편성 시스템 확정 연동.

## 3. 과제 상세

각 과제는 **왜 / 무엇을 / 근거 자료 / 채택 기준 / 구현 지시(Sonnet용) / 난이도** 순이다. 난이도는 S(1~2일)·M(3~5일)·L(1~2주).

### A. 예측 정확도

#### A1. 신작 사전값(prior) — 다른 채널 실적으로 신작 예측을 보강 (L, 연구 → **기각, 2026-11-13**)

> F-3 결과(`A1_NEWTITLE_PRIOR.md`): 검증 구간에서 모든 변형이 현행보다 8~13% 나쁨(과적합). "자리 평소만"도 현행보다 4~5% 나쁨. 엔진·화면 변경 없음. 대신 시리즈 연결 확대와 "첫 회 뒤 빠른 갱신"을 후보로 남긴다.

- **왜**: 신작은 모델의 이득이 거의 없다(사실 1). 그런데 "신작"의 대부분은 자사에 처음일 뿐 **다른 채널에서 이미 방영된 작품**(구매 드라마·타사 예능 재방)이다. 그 작품의 타채널 실적은 DB에 있다(닐슨 경쟁 36채널, IPTV 41채널).
- **무엇을**: 신작 자리의 기대값을 `자리 평소 수준`만이 아니라 `작품의 타채널 실적을 자사 채널 규모로 환산한 값`과 섞는다(수축 평균). 환산 배수 = (그 작품이 그 채널에서 같은 시간대 다른 프로그램 평균 대비 몇 배였나) × (우리 채널 그 자리 평소 수준). 이미 구매 시뮬레이터 `purchaseSim/engine.ts`가 같은 논리로 "피어 배수"를 만들므로 이를 예측 경로에 연결한다.
- **근거 자료**: `competitor_program_ratings`(닐슨, 자사 환산의 공식 근거), `iptv_peer_record`(보조·참고 표시만), `iptv_series_lifecycle`(폭 0.70~1.41은 신작 예상 범위의 폭으로 사용), `program_genre_map`.
- **채택 기준**: `scripts/d3-plan-forecast-backtest.mts`와 같은 방식으로 **신작 자리만** 떼어 홀드아웃(2026-07~10). 사전값을 넣은 예측의 MAE ÷ 넣지 않은 예측의 MAE가 95% 구간 전체 1 미만일 때만 채택. 피어 1~2곳뿐인 작품은 사전값 가중을 낮춘다(2026-10-02 백테스트: 피어 1~2곳은 슬롯 평균보다 나을 게 없음).
- **구현 지시**:
  1. `scripts/skill-baseline/` 아래에 `newtitle-prior-backtest.mts` 작성(읽기 전용). 신작 자리 244개 목록은 D3 스크립트의 C 분류를 재사용.
  2. 통과하면 `src/lib/idealSchedule/`의 기대값 계산(`buildFeatureSet` 경로)에 `priorFromPeers(programKey, channel, slot)` 순수 함수를 추가하고 설정 플래그로 켠다(기본 off → 백테스트 문서 첨부 후 on).
  3. 화면: 사전 예측 패널의 신작 행에 "타채널 실적 근거: X채널 N회 평소 대비 1.3배"를 한 줄로. 피어 수·근거 수준(충분/보통/약함)은 `purchaseSim/recoEvidence.ts` 기준 재사용.
  4. 테스트: `npm run test:ideal` + 골든 9개 바이트 동일(플래그 off일 때).
- **결과 문서**: `docs/ena-features/D4_NEWTITLE_PRIOR.md`.

#### A2. 공휴일·연휴 효과 계수 (M) — **F-4 결과(2026-11-13, `A2_HOLIDAY_FACTOR.md`)**: 효과 표(낮 1.4~1.7배, 저녁 효과 없음, 전날·다음 날 효과 없음)는 보고서·홈 표시로 채택, 예측 보정은 0.979 [0.947, 1.012]로 기준 미달 → 플래그 기본 off, 2027 설 뒤 재판정. 2027 공휴일은 이미 시드됨, 관리자 검수 화면이 없어 신설.

- **왜**: 사용자 지시(2026-08-20) "공휴일·명절·황금연휴 영향을 보고서에 반영"이 아직 미착수. `public_holidays` 테이블은 이미 있고 프라임 판정에만 쓴다. 예측 백테스트는 공휴일을 평가에서 제외해 왔다 — 즉 공휴일 날의 예측 품질은 측정조차 안 됐다.
- **무엇을**: 채널 × 시간대 × 공휴일 유형(단일 공휴일 / 연휴 중간 / 연휴 전날·마지막 날 / 명절 당일)별로 **평소 같은 요일 대비 배수의 분포**를 낸다. 예측에는 곱셈 보정으로만 넣고(사례 20건 미만 유형은 1.0), 보고서·홈에는 "공휴일 효과: 평소 대비 ×1.2(사례 14건, 참고)"로 표시. 경쟁 채널의 공휴일 편성 변화는 IPTV·닐슨 경쟁 자료에서 "특집·영화 편성 비율 변화"만 참고 정보로.
- **채택 기준**: 공휴일 날만 모은 홀드아웃에서 보정 후 MAE가 작아질 때만 예측에 반영. 보고서 표시는 검증 없이도 가능(상관 참고 정보로 톤 유지).
- **구현 지시**: DB 함수 `holiday_effect_factors(channel, from, to)` 신규 마이그레이션(기존 파일 수정 금지) → `src/lib/forecast/holidayFactor.ts` 순수 함수 → 주간·월간 보고서 템플릿 "공휴일 영향" 단락(스냅샷 extras에 저장, 웹·Word·PPT 동일 값) → 사전 예측 보정 플래그. 테스트 `test:holiday-factor` 신설. 음력 명절·대체공휴일 행은 2027년분을 미리 채워 두고 관리자 화면 검수 항목에 추가.

#### A3. 예측 적중 카드 — 신뢰를 숫자로 (S)

- **왜**: `schedule_forecast_snapshots`가 매일 쌓이는데 PD는 "이 예측을 얼마나 믿을지" 볼 곳이 없다. 적중률이 보이면 제언 수용도가 오르고, 틀리는 채널·구간이 바로 드러난다.
- **무엇을**: 지난 4주·12주 동안 "예측 범위 안에 실적이 들어온 비율", 채널·근거 등급별 상대 오차, 가장 크게 빗나간 5건(작품·자리·원인 후보: 신작/공휴일/편성 변경/잡음 범위 안). 홈 "데이터 상태" 옆과 사전 예측 패널 상단, 주간 보고서에 넣는다.
- **구현 지시**: DB 함수 `forecast_accuracy_summary(channel, weeks)` → `/api/schedule-forecast/accuracy` → `src/components/ForecastAccuracyCard.tsx`. 상대 오차 50% 초과 구간은 수치 대신 "범위"로 보이게(SKILL_BASELINE 제안 2와 같은 규칙). 테스트 `test:forecast-accuracy`.

#### A4. 가구 채널(OLIFE) 주간 평균 구조 원인 연구 (M, 3단계)

- **왜**: OLIFE 주간 평균은 설정 튜닝만으로 안 풀렸다(4주 자리 평균이 더 정확). 구조 원인 후보: 재방 회차 배치, 세계테마기행 회차 소진, 편성 비중 변화.
- **무엇을**: OLIFE 회차 카탈로그(`olife_episode_catalog`)·지역 분류·수명 곡선을 특징으로 넣은 주간 평균 백테스트. 결과가 좋아도 OLIFE만 적용.
- **채택 기준**: A1과 동일(95% 구간).

#### A5. 초반 신호 배지 (S, 조건부)

- 닐슨 도달(시청률÷도달률)로 재현되는 범위에서만 "초반 이탈형 / 입소문형 참고 신호"를 주요 콘텐츠 리뷰 신작 첫 주 카드에 붙인다(IPTV B3: +9% 대 +2%로 약함 → "참고"로만). `program_minute_ratings`가 있는 작품은 이탈 시점(분)을 함께.

### B. 편성 제언 품질

#### B1. 편성 변경 사후검증 — 효과 분포를 실측으로 (L, 1단계 핵심)

- **왜**: 홈 조치의 "기대 효과"에 실측 근거가 없다(사실 6). IPTV 계획의 A3도 "이벤트 목록이 먼저"라며 미뤄졌다. 이 분포가 있어야 B2·C1·D1 모두 "얼마나 기대할 수 있나"를 말할 수 있다.
- **무엇을**:
  1. **편성 변경 이벤트 테이블** `schedule_change_events`: 자사 7채널 + 경쟁 36채널(닐슨) + IPTV 41채널(2024-08~)에서 이동(주간 자리 기준)·교체·신규 투입·종료를 자동 추출. 순수 함수 `src/lib/dashboard/changeHistory.ts`가 이미 자사용으로 있으니 입력을 일반화한다.
  2. **효과 분포**: 변경 전 4주 vs 후 4주(공휴일 제외, 잡음 폭 안이면 "비슷"), 유형(이동/교체/신규)·채널군·시간대·장르별 상승/비슷/하락 비율과 중앙값 변화율(기준이 작은 자리는 제외). 경쟁 사례를 포함하면 사례 수가 수백 건으로 늘어 유형별 30건 하한을 채울 수 있다.
  3. **화면**: 홈 조치 근거 한 줄을 "같은 유형 N건 중 M건 상승(중앙값 +x%)"으로 교체. 제언 상세에 "비슷한 사례 3건"(작품·채널·전후 값) 표시. 주간 보고서 편성 제언 앞에 "이 유형의 과거 효과" 한 단락.
- **채택 기준**: 자사 이동 73건 결과(상승 37·비슷 9·하락 27)와 자동 추출 결과가 ±10% 안에서 맞아야 한다(검증 테스트로 고정).
- **구현 지시**: 마이그레이션 `schedule_change_events` + 함수 `compute_schedule_change_events(source, from, to)`·`schedule_change_effect(type, group, daypart)` → 주 1회 크론(`/api/cron/forecast-maintenance`에 묶지 말고 별도 라우트) → `src/lib/dashboard/changeEffect.ts`(읽기) → `homeCopy.ts` 문구 교체(판정 로직은 건드리지 않음) → 제안 캐시 버전 올림. 테스트 `test:change-events`(자사 73건 회귀 포함).

#### B2. 비교군 우수 사례 라이브러리 — "벤치마크 처방" (L, 2단계)

- **왜**: 사용자 요청의 핵심("타사의 우수 사례를 가져와 편성 제언"). 지금 처방 라이브러리는 자사 풀 안의 교체·이동·재방 위치·보유작·구매 검토뿐이다. 군 1위 채널이 **같은 자리에서 무엇을 어떻게 트는지**는 연구 문서에만 있고 화면 제언에는 없다.
- **무엇을**: 군(드라마·예능·라이프·지상파종편·UHD)별로 다음 패턴을 자동 추출해 `benchmark_patterns`에 저장한다.
  - 요일×시간대별 **장르·본재 구성**(군 상위 3채널 vs 우리): "일 17~20시 군 1위 MBC드라마넷은 본방 드라마 60%·재방 40%, 우리는 재방 100%".
  - **재방 리듬**: 본방 후 첫 재방까지 시간, 주당 반복 횟수, 띠 편성 길이(연속 회차 수). 재방 내성이 확인된 작품(사실 9)과 결합해 "재방 내성 작품은 군 1위가 주 3회 띠로 튼다" 같은 사례.
  - **신작 투입 자리**: 군 상위 채널이 신작을 처음 넣는 요일·시간대와 그 뒤 4주 성과(B1 분포 재사용).
  - **집중도**: 상위 5개 작품 비중(사실 8)의 군 평균 — 우리가 지나치게 몰려 있으면 "두 번째 득점원 확보"를 처방으로.
  - 각 사례에는 반드시 **평소 대비 배수·사례 수·기간**을 붙이고, 닐슨 근거와 IPTV 근거를 따로 표기한다.
- **처방 연결**: 처방 라이브러리(`weakSlotRemedy`/`aiLine.ts`)에 `BENCHMARK` 유형을 추가. 자사 풀 최적화와 섞지 않고 별도 "비교군 사례" 줄로만(사용자 원칙 2026-09-30). 채널 심층 경쟁 섹션에 "같은 자리 비교군 사례" 블록.
- **전제**: 경쟁 작품 장르 채움(F2). 장르가 "미분류"인 작품 비율이 20%를 넘는 군은 장르 패턴을 숨기고 본재·리듬 패턴만 보인다.
- **채택 기준**: 패턴 자체는 집계라 검증 대상이 아니다. 단 "이 사례를 따르면 오른다"는 말은 B1 분포가 뒷받침할 때만 쓴다.
- **구현 지시**: 함수 `benchmark_slot_patterns(group, dow_bucket, daypart, from, to)`(닐슨 경쟁 자료 기준, IPTV는 보조 열) → 테이블 `benchmark_patterns`(주 1회 갱신) → `src/lib/benchmark/patterns.ts`·`patternText.ts` → `ChannelDeepDive` 경쟁 섹션 블록(D2 분할 후 별도 컴포넌트로) → `aiLine.ts` BENCHMARK 처방. 테스트 `test:benchmark-patterns`. `nielsen_group_slotmap`·`iptv_group_analysis` 함수를 재사용한다.

#### B3. 제언 성적표 — 채택/기각과 4주 후 결과 (M, 2단계)

- **왜**: `action_reviews`에 PD 결정이 쌓이지만 결과와 대조되지 않는다. 제언이 맞았는지 자동으로 보여야 PD가 믿고, 틀린 유형을 고칠 수 있다.
- **무엇을**: 제언별로 "채택 → 4주 후 실적 vs 예측", "기각 → 그대로 뒀을 때 실적". 유형별 적중률을 홈 "데이터 상태" 옆 카드와 월간 보고서에. 틀린 제언 상위 5건은 관리자 화면에 원인 후보와 함께.
- **구현 지시**: `action_reviews`에 `outcome_checked_at`·`outcome` 열 추가(신규 마이그레이션) → 크론이 4주 지난 건을 채움 → `/api/actions/scorecard` → 카드 컴포넌트. B1의 효과 분포 함수를 재사용.

#### B4. 약한 자리 4주 재판단 (S, 11/20 예정 — 기존 일정)

- 2026-10-23 적용한 채널별 헛경보 기준선을 4주 실적으로 재점검(`docs/weak-slot-verdict/WEAK_SLOT_VERDICT.md` §2 갱신). 결과에 따라 기준선만 조정, 공식은 유지.

### C. 구매 후보 (벤치마킹)

#### C1. 벤치마크 채널 구매 리스트 (L, 1단계 핵심)

- **왜**: 사용자 요청("비슷한 장르와 순위의 채널에서 벤치마킹하여 구매할 컨텐츠 리스트"). 지금 `purchase_recommendations`는 "비교 케이블 몇 곳에서 평소 대비 몇 배"만 보고, **어느 채널을 벤치마크로 삼는지**가 명시되지 않는다.
- **무엇을**:
  1. **벤치마크 채널 자동 선정** `benchmark_channels(own_channel)`: 같은 군 + 연간 누적 순위(216채널)가 우리 ±15위 안 + KPI 타깃 같음(가구/2049). 예: ONCE(가구 63위) → 드라마군에서 50~80위 채널. 결과는 관리자 화면에서 채널별로 덮어쓸 수 있게(수동 추가·제외).
  2. **후보 추출**: 벤치마크 채널에서 최근 52주 상위 작품(평소 대비 1.1배 이상·20회 이상) 중 자사 미방영(ratings·Avail 이력 없음) 작품. 보유작(Avail)은 "내부 활용" 탭으로 분리.
  3. **근거 열**: 벤치마크 채널별 평소 대비 배수, 재방 내성(본방 대비 재방 배수, HIDDEN_TITLES 기준), 수명 곡선 폭, 장르, 원 방송사·방영 연도(네이버 크론), 자사 환산 예상치(A1의 환산 로직 공유), 근거 수준(충분/보통/약함 — `recoEvidence.ts` 기준 그대로), IPTV 보조 성적(`iptv_peer_record`, 별도 표기).
  4. **화면**: 구매 시뮬레이터에 "벤치마크 후보" 탭. 채널 선택 → 벤치마크 채널 목록(왜 선정됐는지 한 줄) → 후보 표(정렬: 보정 배수) → 행 클릭 시 채널별 실적 이력 그래프. 홈 "풀 밖 대안"은 이 리스트 상위 2건을 쓴다(현재 purchase_recommendations 상위 2건 대체).
- **채택 기준**: 백테스트 — 2025년에 벤치마크 채널에서 1.1배 이상이던 작품을 2026년에 자사가 실제로 방영한 사례에서, 예상치와 실적의 상대 오차가 기존 purchase_recommendations 예상치보다 크지 않아야 한다.
- **구현 지시**: 함수 `benchmark_channels`·`benchmark_purchase_candidates(own_channel, target, window)`(닐슨 기준) → `purchase_recommendations`에 `benchmark_channel_codes text[]`·`rerun_tolerance numeric` 열 추가(신규 마이그레이션) → 갱신 스크립트 `scripts/refresh-purchase-recommendations.ts` 확장(728일 창은 입력 RPC를 채널·분기 단위로 나눠 시간 초과 해결) → `src/app/ideal-schedule/purchase/` 탭 컴포넌트 분리. 테스트 `test:benchmark-purchase`. 가격·ROI는 다루지 않는다(PRD 범위 밖, 결정 §5-4).

#### C2. 권리 만료·소진 임박 연동 (M)

- **왜**: Avail 종료일과 방영 누적 횟수가 있는데 "권리 끝나기 전에 더 틀 작품", "방수 다 써가는 작품"을 알려주지 않는다.
- **무엇을**: 채널별 "만료 90일 안·평소 대비 1.0배 이상" 작품과 "방수 80% 이상 소진" 작품을 홈 결정 큐(D1)와 구매 시뮬레이터 보유작 탭에. 방수 정의가 미확정이라(ONCE 김탁구·옥중화 사례) 소진 경보는 `countEnforcement`가 warn_only인 동안 "참고"로만.

- 모든 과제 공통: 신규 마이그레이션만 추가(기존 파일 수정 금지), 삭제 파일은 `trash-can/`, `npx tsc --noEmit -p .` 통과 후 푸시, 커밋 메시지는 한국어, `.bkit` 제외.
