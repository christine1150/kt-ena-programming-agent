## 시안에 담은 것

### ① 홈 "오늘 결정할 것" 결정 큐
- 홈 상단에 목록 하나. 기존 타일은 그대로 두고 그 위에 추가(delta-only).
- 항목 유형 6종과 색 띠: 약한 자리(교체 색) · 이동/교체 제언(이동 색) · 신작 첫 주 신호(유지 색) · 권리 만료·소진(관찰 색) · 예측 적중(강화 색) · 데이터 상태(테스트 색).
- 항목마다 현황·원인·조치 3줄(홈 문구 기준 유지), 접힌 "비슷한 사례 3건·비교군 사례"(B1·B2 연결).
- 버튼: **3개(채택/보류/기각)** 와 **2개(채택/기각)** 를 전환해 비교. 기각·보류는 사유 선택지(근거 약함·편성 제약·이미 조치·다음 주 다시·기타). 처리한 항목은 흐려지고 건수가 줄어든다. 결정은 `action_reviews`에 기록 → 4주 뒤 결과 대조(B3).
- 담당 채널 칩(로그인별 기억).

### ② 채널 심층 — A안 5탭 vs B안 섹션 접기
- A안: 진단 / 콘텐츠 / 편성 / 경쟁·비교군 / IPTV 보조. 첫 화면은 진단만 그리고 나머지 탭은 열 때 불러온다. IPTV 종료 후 탭 자체를 숨긴다. 공유 링크가 탭을 가리킨다.
- B안: 지금 구조 그대로 두고 섹션마다 접힘 + 접힌 상태에 요약 한 줄(건수). 열 때 불러온다. 접힘 상태는 브라우저가 기억.
- 두 안 모두 "열 때 불러오는 블록"을 회색 빗금으로 표시했다. 어느 쪽이든 D2/E2(분할·지연 로딩)의 목표(첫 화면 2초)는 같다.

## 결과(2026-11-14)

사용자 결정: **D1 결정 큐와 D2 탭/접기 모두 보류.** 지금은 1페이지가 복잡해지는 내용이라는 판단. 시안은 보관하고 구현하지 않는다. 속도 작업(E2 지연 로딩·코드 분할)은 레이아웃 변경 없이 진행한다. 아래 질문 4건은 나중에 다시 본다.

## 사용자가 정할 것(보류)

1. 결정 큐 버튼: 3개(채택/보류/기각 + 사유) / 2개(채택/기각) / 다른 구성.
2. 결정 큐 항목 유형 6종 중 빼거나 더할 것.
3. 채널 심층: A안 5탭 / B안 섹션 접기 / 섞기(예: 상단 탭은 두되 진단 탭 안은 접기).
4. 첫 탭(또는 첫 섹션)이 "진단"이 맞는지.

결정이 오면 D1·D2 구현 명세(S-5·S-6)를 그 안으로 고정하고 Fable 구간을 마친다.
