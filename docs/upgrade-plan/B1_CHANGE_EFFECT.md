# B1. 편성 변경 사후검증 — 결과와 구현 명세 (F-1)

- 작성: 2026-11-13 (고도화 계획 F-1, 설계: Claude Fable)
- 스크립트: `scripts/upgrade-plan/b1-change-effect.mts` (읽기 전용) → `docs/upgrade-plan/b1-change-effect.json`
- 자료: 자사 닐슨 6채널(2025-01~2026-11-09, KPI 타깃), 경쟁 닐슨 30채널(`competitor_program_target_ratings`, 2025-01~), IPTV 셋톱 46채널(2024-08~). 공휴일 78일, 잡음 폭 `iptv_noise_by_level` 2026-11-v0.
- 추출 규칙: `src/lib/dashboard/changeHistory.ts`의 `detectPastChanges`를 그대로 썼다(이동 = 한 프로그램의 주간 자리 하나가 사라지고 하나 생겨 3주 이상 유지, 교체 = 같은 요일·시 자리에서 프로그램이 바뀌고 전후 각 4회 이상). 새 규칙은 만들지 않았다.

## 0. 결론 한 장

1. **기존 추출 규칙은 세 출처 모두에 그대로 쓸 수 있다.** 회귀 대조(2026-10-15 기준 400일 자사 이동)는 77건(상승 40·비슷 8·하락 29)으로, 당시 73건(37·9·27)과 ±5% 안에서 맞는다. 차이는 10/15 이후 적재분과 26시 경계 합치기(11/02) 때문이다.
2. **편성을 바꾼다고 해서 평균적으로 시청률이 오르지 않는다.** 교체의 변화율 중앙값은 자사 −8.5%, 경쟁 −7%, IPTV −5%이고, 상승 비율은 38~50%다. 이동도 자리 기준으로 보면 새 자리 중앙값 +2~3%(IPTV·경쟁), 비운 자리 −3~−10%다. **"교체·이동하면 +3~30%"는 근거가 없다는 것이 숫자로 확정됐다.** 홈 조치의 기대 효과는 수치 범위가 아니라 "같은 유형 N건 중 상승 M건" 분포로만 쓴다.
3. **잡음 폭으로 보면 변화의 절반 이상은 "비슷"이다.** 닐슨 자사 교체 337건 중 잡음 범위를 넘어 오른 건 73건(22%), 내린 건 98건(29%), 나머지 166건(49%)은 잡음 범위 안이다. IPTV(표본 큼)에서는 이동의 90%, 교체의 79%가 잡음 범위 안이다. ±10% 띠 하나로 "올랐다/내렸다"를 세던 지금 문구는 잡음을 실제 변화로 세고 있다.
4. **측정 기준을 두 가지로 나눠야 한다.** 지금 함수는 이동을 "프로그램 기준"(옮긴 프로그램의 전후), 교체를 "자리 기준"(그 자리의 전후)으로 잰다. 프로그램 기준 이동은 "좋은 시간대로 옮기면 오른다"는 당연한 결과(드라마군 20~23시로 +41%, 새벽으로 −43~−63%)라 PD 판단에 쓸 수 없다. PD가 묻는 것은 **자리**("이 자리를 이 프로그램으로 채우면 자리가 좋아지나")와 **비운 자리**("빼면 그 자리는 어떻게 되나")다.
5. **교체는 "편성상의 교체"와 "작품 종료 후 교체"를 나눠야 한다.** 앞 프로그램이 28일 안에 다른 자리에서 계속 방영된 건(편성상의 교체)만 PD의 결정이다. 자사 교체 337건 중 편성상의 교체는 167건(중앙값 +3%, 상승 80·하락 72·비슷 15)이고, 종료 후 교체 170건은 중앙값 −17%다. 둘을 섞으면 "교체는 손해"처럼 읽힌다.
6. **사례 수는 군×유형 단위까지는 충분하고, 시간대까지 나누면 자사만으로는 부족하다.** 자사 군×유형은 37~215건, 경쟁을 합치면 시간대 단위가 20~320건이다. 라이프군은 자사·경쟁 합쳐도 이동 52건·교체 166건이라 시간대 단위는 보이지 않는다.

## 1. 결과

### 1.1 출처 × 유형 (±10% 띠 / 잡음 띠)

|---|---|---|---|---|---|---|

| 자사 닐슨 | 교체(자리 기준) | 337 | 138·35·164 | 73·166·98 | −8.5% [−47%, +70%] | −13% |

- 잡음 띠 = 두 회 평균 시청률 구간의 80% 분위(`iptv_noise_by_level`) ÷ √(비교 방영 수). 닐슨 자사 교체에서 ±10% 띠는 35건만 "비슷"으로 두지만 잡음 띠는 166건을 "비슷"으로 둔다.
- IPTV의 p25~p75 폭(±20%)이 닐슨(±45~60%)의 절반 이하다. 닐슨 전후 비교의 흔들림 대부분이 패널 잡음이라는 IPTV A1 결론과 같다.
- 공휴일(±1일) 방영을 빼고 전후 28일로 다시 재도 방향은 같다(자사 이동만 +26%로 커지는데, 이동 직후 1~2회의 특집·첫 회 효과가 28일 창에서 희석되지 않은 것으로 본다).

읽는 법:

- **자사 이동의 새 자리 +58~72%는 선택 효과다.** 우리가 프로그램을 옮겨 넣는 자리는 직전에 약한 재방이 있던 자리인 경우가 많다. "옮기면 그 자리가 1.7배 된다"가 아니라 "약한 자리를 강한 프로그램으로 채우면 그 자리는 오른다"는 뜻이며, 비운 자리(예능 −48%)의 손실과 함께 봐야 채널 합계가 보인다. 경쟁·IPTV에서는 새 자리 효과가 0 근처다.
- **편성상의 교체는 자사 드라마·예능에서 상승 쪽(+14%·+59%), 경쟁 드라마군에서는 하락 쪽(−20%)이다.** 자사 예능 42건 중 25건 상승은 ENA Play의 타사 예능 재방 교체가 많이 들어간 결과로 보이며(사례 내역은 json `ownEvents`), 개별 확인이 필요하다.
- **종료 후 교체는 대체로 손해(−5~−27%)다.** 인기작이 끝난 자리는 후속작이 못 채운다. 이것은 편성 결정이 아니라 콘텐츠 소진의 결과이므로 처방 근거로 쓰지 않는다.

### 1.3 시간대·시청률 구간(닐슨 자사+경쟁, 프로그램 기준 이동·자리 기준 교체)

- 드라마군 이동: 20~23시로 31건 중 20건 상승(+41%), 08~11시 +41%, 17~20시 +21%. 02~08시로는 25/38·16/23 하락(−43%·−63%). 시간대 효과가 프로그램 효과를 압도한다 — **프로그램 기준 이동 효과는 시간대를 고정하지 않으면 의미가 없다.**
- 예능군 교체: 20~23시 177건 중 98건 상승(+22%), 11~14시 +35%, 23~02시 +21%. 드라마군 교체: 17~20시 223건 중 130건 하락(−21%). 지상파·종편 교체: 20~23시 212건 중 117건 하락(−16%).
- 시청률 구간별로는 잡음 띠 "비슷" 비율이 낮은 구간(0.05% 미만)에서 55~65%, 높은 구간(1% 이상)에서 11%다. 낮은 시청률 자리의 전후 비교는 거의 잡음이다.

### 1.4 한계

- 변경의 **원인**(시즌 종료, 신작 투입, 경쟁 대응, 공휴일 편성)은 가르지 못한다. "편성상의 교체 vs 종료 후 교체"가 지금 가능한 유일한 구분이다.
- 본방·재방은 구분하지 않았다(`ratings.is_first_run` 거의 null, 경쟁 자료 표기 없음). 재방 자리 변경이 많이 섞여 있다.
- 경쟁 닐슨의 2049는 회차 단위 잡음이 커서(IPTV A1) 경쟁 이동·교체의 개별 사례는 믿기 어렵고 분포만 쓴다.
- IPTV 2049는 추정값이라 자사 A군 IPTV 결과는 방향 참고용이다.
- 변경 직후 28일은 수명 곡선(1~2회 → 3~10회 0.70~1.41배)의 초반이 섞인다.

## 3. 구현 명세 (Sonnet 구간 S-2)

### 3.1 DB

**신규 마이그레이션 1 — 이벤트 테이블** `schedule_change_events`

```
source            text   not null  -- 'own' | 'comp' | 'iptv'
channel_key       text   not null  -- own: channels.code / comp: competitor_name / iptv: iptv channel_name
channel_group     text   not null  -- terrestrial | drama | variety | life | uhd
target_kind       text   not null  -- 'p2049' | 'household'
kind              text   not null  -- 'move' | 'replace'
event_date        date   not null  -- 바뀐 뒤 첫 주 월요일(이동) 또는 첫 방영일(교체)
program_key       text   not null  -- 옮긴 프로그램 / 새 프로그램
prev_program_key  text              -- 교체의 이전 프로그램
from_slot         text   not null  -- '요일|시' (이동 전 자리 / 교체 자리)
to_slot           text   not null
daypart           text   not null  -- 8대 시간대(to_slot 기준)
before_median     numeric, after_median numeric, before_n int, after_n int   -- 기존 함수 그대로(최대 6회)
change            numeric           -- after/before − 1
w4_before numeric, w4_after numeric, w4_before_n int, w4_after_n int, w4_change numeric  -- 전후 28일·공휴일 ±1일 제외
to_slot_change    numeric           -- 이동만: 새 자리 직전 28일 → 옮겨온 프로그램 28일
from_slot_change  numeric           -- 이동만: 비운 자리
prev_continues    boolean           -- 교체만: 이전 프로그램이 28일 안에 다른 자리에서 계속 방영됐나
noise_step        numeric           -- 두 회 평균 구간의 80% 분위 ÷ √min(before_n, after_n)
verdict_noise     text              -- 'up' | 'flat' | 'down' (잡음 띠)
verdict_band10    text              -- 'up' | 'flat' | 'down' (±10%, 비교용)
computed_at       timestamptz, version text
primary key (source, channel_key, target_kind, kind, event_date, program_key, from_slot, to_slot)
```

- 계산은 **서버 순수 함수**가 한다(`detectPastChanges`는 이미 순수 함수). DB 함수로 옮기지 않는다 — 추출 규칙이 TypeScript에 있고 테스트가 붙어 있으므로, 주 1회 크론이 세 출처의 방영 행을 읽어 계산해 테이블에 upsert한다(content-fit과 같은 "원칙 1의 명시적 예외", 근거는 이 문서).
- 잡음 폭 계수는 `iptv_noise_by_level` 최신 버전을 읽되, IPTV 마감 후에는 고정 버전(F1)을 쓴다. 테이블이 비어 있으면 ±10% 띠로 폴백하고 `verdict_noise`를 null로 둔다.

**신규 마이그레이션 2 — 집계 함수** `schedule_change_effect(p_source text[], p_group text, p_kind text, p_daypart text default null, p_target_kind text default null, p_only_swap boolean default true)`

- 반환: n, up, flat, down(잡음 띠), up_band10, down_band10, change_median, change_p25, change_p75, to_slot_median, from_slot_median, period_from, period_to.
- `p_only_swap = true`면 교체는 `prev_continues = true`만 센다.
- 셀이 20건 미만이면 n만 돌려주고 나머지는 null(화면이 숨김).

### 3.2 서버·순수 함수

- `src/lib/dashboard/changeHistory.ts`에 다음을 추가(기존 export 유지, 기존 테스트 통과):
  - `measureChange(all, change, opts: { holidays: Set<string>; noise: NoiseTable | null; targetKind })` → w4·to_slot·from_slot·prev_continues·noise_step·verdict_noise. 스크립트 `b1-change-effect.mts`의 `measure()`를 옮긴다.
  - `evidenceLine`을 잡음 띠 기준으로 바꾼다: "이 채널이 {기간} {유형} {n}건 중 {up}건은 잡음 범위를 넘어 올랐고 {down}건은 내렸습니다(나머지 {flat}건은 잡음 범위 안)". `MIN_EVIDENCE_N`은 3 → **10**으로(10건 미만은 근거로 내지 않음).
- `src/lib/dashboard/changeEffect.ts`(신규, 읽기): `schedule_change_effect` 호출 + 1시간 캐시. 비교군 한 줄: "비교군(드라마군 경쟁 N건)에서는 상승 M건·하락 K건".
- 크론 `src/app/api/cron/change-events/route.ts`(신규, 주 1회 월요일 04:00 KST, `cronAuth`): 자사 6채널 × KPI 타깃, 경쟁 30채널(`competitor_program_target_ratings`), IPTV 46채널(자료 마지막 날짜까지) → 최근 460일 창으로 재계산해 upsert. 한 번에 한 출처씩, 실패해도 다른 출처는 진행. `vercel.json`에 추가.
- 데이터 모델: `src/lib/dashboard/homeCopy.ts`의 조치 근거 문구만 교체한다. **판정 로직(`judgeWeakSlot`·`evidenceGate`)과 제안 로직은 바꾸지 않는다.** 제안 캐시 버전을 올린다.

### 3.3 화면

- **홈 조치 근거 한 줄**(`aiLine.ts` 경유): 자사 분포 + (있으면) 비교군 한 줄. 예: "이 채널이 최근 1년 같은 자리 프로그램을 바꾼 42건 중 잡음 범위를 넘어 오른 건 12건, 내린 건 9건입니다(비교군 예능 440건: 상승 220·하락 192)".
- **제언 상세(채널 심층 '무엇을 편성할까요?')**: "비슷한 사례 3건" — 같은 군·같은 시간대의 편성상의 교체 중 최근 3건(작품·자리·전후 값·잡음 판정). 자사 우선, 없으면 비교군(출처 표기).
- **주간 보고서 편성 제언 앞 단락**: "이 유형의 과거 효과" — 군×유형(×시간대, 20건 이상일 때) 분포 한 문장. 스냅샷 `extras.changeEffect`에 저장해 웹·Word·PPT가 같은 값.
- 모든 문구에서 **기대 효과 수치(+x%)를 쓰지 않는다.** 중앙값은 보고서에만, "변화율 중앙값 −8%(사례 N건, 원인은 가리지 않은 단순 비교)"처럼 한계와 함께.
