## 2. 공통 지표 정의(기능 1, `program-performance-v1`)

| 항목 | 정의 | 표시 제한 |
|---|---|---|
| 작품 평균 | 선택 채널·타깃·기간·본재 조건의 유효한 **방영별 시청률 산술평균**. 같은 방영(프로그램·방송일·시작)의 중복 행은 1회(최근 적재 값) | "방영별 평균". 방송시간 가중은 제공하지 않음 |
| 채널 일평균 | 같은 채널·타깃(랭킹 시트 표기)·조회 기간의 **채널 하루 행(순위 있는 행)** 을 날짜당 1값으로 산술평균. 같은 날 값이 다르면 최근 적재 값 + 충돌 일수 보고. NULL은 유효 일수에서 제외 | 유효 일수/조회 일수 표시. 공식 주간 값과 다름 |
| 채널 일평균 대비 | 작품 평균 ÷ 채널 일평균. 배율·상대 차이(%)·절대 차이(%p) | 규모 참고 지표. 시간대 효과를 뺀 효율·순증·비용 효율 아님 |
| 동슬롯 대비 | 콘텐츠 적합도와 같은 기대치(같은 칸 다른 프로그램, 작품의 모든 program_id 제외)와 같은 수축 κ=2. 비교 창 = 그 채널에서 작품이 관측된 첫~마지막 방송일. 비교군은 본재 구분 없음 | 편성 효율 지표. 인과 아님. 비교군 건수·수축 전 배율 제공 |
| 기존 "시청 규모" | 콘텐츠 적합도의 채널 **방영평균** 대비(엔진 내부) | 이번 화면의 "채널 일평균 대비"와 다른 지표 — 섞지 않음 |
| 방향(높음/비슷/낮음) | 배율을 화면 표시 자릿수(소수 2자리)로 반올림한 값이 1보다 큰지·같은지·작은지 | 임의의 "유의 차이" 임계값 없음. 강화·교체 권고로 바꾸지 않음 |
| 산출 불가 | 기준값 0 → 배율 없음·절대 차이만, 기준값 NULL/자료 없음 → 산출 불가, 실적 0은 유효한 0배 | epsilon으로 숨기지 않음 |
| 표본 상태 | 방송일 3일 미만 = 판단 보류, 8일 미만 = 표본 적음(콘텐츠 적합도 기준과 같음) | 수치는 보여 주되 보류 병기 |
| 현재 판정 | 콘텐츠 적합도(최근 12주, 기준일·창 시작일 함께) | KPI 타깃 모드에서만. 조회 기간과 다름을 명시 |

채널 행 상태: 실적 확인 / 해당 기간 관측 없음 / 프로그램 자료 없음(ENA Story 등) / 이번 비교 제외(skyUHD — 수기 파일·타깃 없음) / 타깃 자료 없음. 기록 없음을 미방영·0으로 확정하지 않는다.

날짜 구분: DB 첫 관측일 · 작품 첫 관측일 · 확인된 첫 본방일(<본> 표시) · 최신 자료일. 종료일이 최신 자료일보다 늦으면 최신 자료일까지만 본다.

## 5. 기능 2 설계(편성표 예측·리뷰)

### 5-1. 동작 분리
| 동작 | 구현 위치(예정) |
|---|---|
| 현재 편성으로 예측 계산 | 편성 비교 화면의 "사전 예측" 탭 → 서버가 업로드 편성표 칸을 기존 엔진 Scorer로 평가(최적화 없음) |
| 수정 편성의 예측 갱신 | 같은 평가를 수정된 칸으로 다시 — 새 예측 행(`PLAN_UPDATE`, parent 연결) |
| 새 편성안 제안 | 기존 AI 편성(`/ideal-schedule`) 그대로 |
| 예측 고정 저장 | `schedule_forecast_runs/values`(추가 전용) |

### 5-2. 구현된 순수 기반(`src/lib/scheduleForecast/core.ts`)
- `aggregatePeriod/aggregateDays`: 편성시간 가중 예상, 예측 없는 분·덮이지 않은 분 분리, `complete` 아니면 부분 예측, 범위는 검증 전이라 없음.
- `forecastKeys`: 멱등 키(편성표 버전·모델·파라미터·마감·목적) + 입력 스냅샷 지문.
- `matchSlots`: 같은 방송일 + 시간 겹침 + 같은 작품으로만 MATCHED, 다른 작품 = CHANGED, 후보 중복·재사용 = AMBIGUOUS, 실적 없음·NULL = NO_ACTUAL. 한 방영은 한 칸에만.
- `reviewMetrics`: 모델 성적(MATCHED만), 포함·제외 건수·분, 계획 단계 일별 MAE(부분 예측일 분리).

### 5-3. 저장 스키마 초안

## 6. 더 나은 방법 제안(Claude 검토)

1. **예측 기록을 사람 손 없이 쌓기**: 편성표는 이미 매주 업로드되고 있다. 승인 후 업로드 시점에 자동으로 "계획 단계 예측"을 고정 저장하면 PD가 버튼을 누르지 않아도 8~12주 뒤 실제 검증 표본이 생긴다. 이것이 "학습"의 전제 조건이므로 화면보다 먼저 켜는 것을 권한다.
2. **과거 주 의사(擬似) 예측으로 바로 검증 시작**: 과거 편성표(program_schedule_grid에 남은 주)와 마감 7·14일 데이터로 예측을 재현하면 기다리지 않고 현재 모델의 실제 오차를 볼 수 있다. 단, 당시 계획표가 재업로드로 바뀌었을 수 있어 "실방영 조건 검증" 또는 "재구성 계획 검증"으로 이름 붙인다.
3. **작품 식별 갱신 자동화**: `program_identity`가 10/01 이후 갱신되지 않아 신작이 검색에서 빠진다. 주 1회 `refresh_program_identity()`를 기존 예약 실행(구매 추천 주간 갱신)과 묶는 것을 제안(운영 DB 쓰기 — 승인 필요).
4. **오리지널 분류 보강**: 주요 콘텐츠 목록에 오리지널 드라마 6·예능 5만 있어 과거 오리지널(예: 신병2·3)은 "분류 미확인"이다. 관리 화면에서 과거 작품 분류를 채우면 기능 1의 오리지널 필터가 완전해진다(데이터 입력 — 사용자).
5. **회차 정보 보강으로 재방 유지율 열기**: 닐슨 행에 회차가 거의 없다(실측: 신병4·나는SOLO 모두 회차 0). AI 편성이 이미 쓰는 편성표 회차 보강(`enrichAiringsWithPlan`)을 성과 화면에도 쓰면 "같은 회차 본방 대비 재방 유지율"을 근거 있게 계산할 수 있다.
6. **두 기능 잇기(후속)**: 프로그램 성과 표에 "최근 예측 대비 실적" 열을 붙이면 기능 1이 기능 2 리뷰의 작품별 창이 된다.
