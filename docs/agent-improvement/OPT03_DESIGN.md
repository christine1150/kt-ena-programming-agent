# OPT03 — 주간 전체 목적함수와 제약 최적화 설계

작성: 2026-10-07 · 코드: `exactSolver.ts`(소형 문제 정답기·검증기), `outputValidator.ts`(엔진 산출물 검증기), `horizon.ts`(평가 범위), `changeBudget.ts`(변경량 경계), `robustness.ts`(선택 불확실성), 테스트 `npm run test:opt03`.
OPT05 이후 확정 권고(모델 QA)에 따라 **예측기·탐색기 자체는 바꾸지 않았다.** 이번 단계는 (a) 목적함수·제약·가정을 코드와 문서에서 일치시키고, (b) 정답을 아는 작은 문제와 독립 검증기를 만들고, (c) T01~T12를 통합 테스트에 연결하는 것까지다.

## 1. 목적함수 (코드와 일치)

**주 목표:** 주간 핵심 타깃 기대 시청률
`R̂(편성안) = Σ(편성 분 × 기대 시청률) ÷ 계획 horizon` — 모든 편성안을 *같은 horizon 분모*로 비교한다(`horizon.ts`, `exactSolver.objectiveOf`).

| 구분 | 정의 | 코드 |
|---|---|---|
| ① 예상 주간 시청률(%) | 편성 분 가중 산술평균(기대값이 있는 시간의 평균 + 평가 범위 coverage 표시) | `engine.ts` `summary.expectedAvgRating`, `summary.horizon` |
| ② 최적화(선택) 점수 | `value = fitness × (1+전략) × baseline × 분 × (1−패널티)`, fitness는 6성분 가중 평균 — **시청률 단위가 아니다** | `scoring.ts` |
| ③ 실무 채택 판단 | 권리·소재·브랜드·확인 조건 — 사람이 판단. 엔진은 `validation`·권리 상태·변경 규모를 보여 줄 뿐 | 화면 상태 띠 |

- **Fit Score·가중치 합산 점수를 예상 시청률로 출력하지 않는다.** 화면의 주간 기대값은 `expected`(예측)의 평균이다. 선택 점수에 시청률 외 성분(타깃 구성비·요일×시·추세·안정성·연결)이 섞여 있으면(`summary.objectiveInfo.selectionScoreMixed`) 상태 띠가 "이 안이 기대 시청률 최대안이 아닐 수 있다"고 알린다(기본 가중치 KPI 35% → 시청률 외 비중 65%). "시청률 우선(KPI 100%)"은 `value = expected × 분 × (1−패널티)`가 되어 두 값이 거의 같아진다.
- 광고·프로모·미관측 구간: 기대값이 없는 구간은 평균에서 **조용히 빠지지 않는다**. `summary.horizon`이 평가된 분·평가 못 한 분·coverage·"평가 안 된 시간을 0으로 둔 하한"을 돌려주고, coverage < 98%이면 상태 띠가 안내한다(T06). 예측 불가를 0이나 평균으로 채우지 않는다(`exactSolver`: 기대값 null 후보는 배치 불가).
- 불확실성·변경 비용을 시청률 %에 더하지 않는다 — 별도 다목적 순서/제약으로 둔다(§6, §4).

계약에 없는 규칙을 법정·필수로 임의 지정하지 않는다 — 위 "엔진 미구현" 항목은 자료가 확인될 때 추가한다. 엔진 산출물 검증은 매 실행 끝에 돌며 `summary.validation`에 기록되고 위반은 경고(`[제약 검증 실패]`)로 남는다(편성안을 조용히 고치지 않는다).

**검증기가 보지 못하는 것(정직하게):** 수동 교체 블록의 권리(수동 교체 경로 자체에 권리 판정이 없음, OPT06 첫 작업), 길이 불일치(패널티일 뿐), 공유 풀·회차 순서·소재(엔진 미구현), 권리 자료가 없을 때의 실행 가능 여부.

## 3. 모드와 시간 격자

- **기존 틀 유지**: 알려진 슬롯 길이·고정 구간 안에서 후보 선택(골격 슬롯 배정 + 교체·맞교환 국소탐색). **시간 최적화**: 요일별 빈 구간을 5분 격자 DP(블록 길이 = 프로그램 실측 중앙값)로 채우고 반복 한도는 DP 밖에서 후처리.
- 5분 격자는 *탐색용 거친 격자*다: 시작·길이가 5분 단위로 반올림되어 원본 분·초 대비 최대 ±2.5분의 오차가 있을 수 있다. 최종 평가(`evaluateSchedule`)는 블록의 실제 분 단위 길이로 하지만 **격자에 맞지 않는 가장 좋은 배치는 탐색 범위 밖**이다. 정확한 시각 검증은 `validation`(겹침·경계)에 한정되고 DP 최적성은 증명하지 않는다 → 결과는 항상 **"탐색된 최선안"**이다(`summary.searchKind = SEARCHED_BEST`, 최적 증명 없음).
- 원본 초 단위는 방영 기록(`startMin` 소수 보존)에 있으나 후보 길이는 중앙값(분 반올림)이다. 칸 길이와 후보 길이가 다르면 `runtime_mismatch` 패널티가 점수에만 반영된다.

## 4. 변경량 제약과 3종 안 (같은 예측기·같은 하드 제약, 변경량만 다름)

사용자 결정(2026-10-07): **편성 칸 수정 개수는 제한하지 않는다.** 변경 규모는 *제한이 아니라 정보*다. `changeBudget.ts`는 기준안에서 목표안으로 가는 변경을 이득이 큰 순서로 채택하는 효율 경계를 만들고(각 점: 변경 칸 수·방송분·모델상 목적값), 변경 예산이 필요할 때 `pickWithinBudget`으로 고른다.
- **최소변경안**: 전체 모델상 개선분의 50%를 처음 달성하는 가장 적은 변경. **균형안**: 80%. **성과우선안**: 100%(전체 변경, 항상 성과 최대). 이 비율은 *제시 기준*일 뿐 제한이 아니며 조정 가능하다.
- 유효하지 않은 변경(권리·필수 제약 위반)은 어떤 경계 점에도 들어가지 않는다 — 제약을 푸는 안은 만들지 않는다. 작은 문제에서 탐욕 경로가 정확한 경계와 일치함을 테스트로 확인했다(상호작용이 큰 문제에서는 다를 수 있음).
- **통합 상태:** 순수 모듈과 테스트까지. 엔진·화면에 연결(KEEP 모드의 기준안 슬롯 대응, 비교 카드)은 OPT06에서 한다.

## 5. 기회비용·반복 노출·공유 풀·가족 채널

- 같은 콘텐츠를 모든 최고 슬롯에 재사용하지 않는다: 프로그램 일·주 한도, 본방 후보 주간 한도(관측 최대), 같은 시 반복·연속 패널티, 오리지널 드라마·예능은 최근 91일 관측 최대 이내로만 허용(이를 넘는 반복은 기대값 외삽 근거가 없어 막음). 소형 정답기는 한도 때문에 *좋은 에피소드를 어디에 쓸지*가 정답을 바꾸는 사례를 보여 준다(T02: A는 1회만 → 두 번째 슬롯에 A).
- 채널 간 공유 풀: 엔진 미구현(권리 자료 해석 확인 후). 소형 정답기에서 풀 한도가 정답을 바꾸는 사례를 시험한다.
- **가족 채널 전체 최적화:** 서로 다른 타깃(2049 vs 가구)의 시청률을 단순 합산하지 않는다. 그룹 지표는 채널 추세의 단순평균(가중 없음, 단계 09)이며, 가족 채널 전체 목표를 만들려면 채널별 목표·정책 가중치를 *명시적으로 정의*해야 한다(정책 수치, 사용자 결정 대상). 지금은 채널별로 따로 최적화한다.

## 6. 선택 불확실성

점추정의 최고값만 고르는 편향은 OPT01 실험에서 작게(+1.6%p) 관측됐다. `robustness.ts`는 검증 잔차(실측÷예측)를 근거 등급 A/B/C별 분포로 쓰고 **프로그램 단위로 오차를 공유**시켜(반복 편성한 한 프로그램을 과대평가하면 그 블록 전부가 같이 빗나감) 개선율의 분포(양수일 확률·하위 10%·중앙·상위 90%)와 후보안의 근거 등급별 비중·후보안에만 있는 프로그램 비중을 낸다. 임의의 risk coefficient를 시청률에 더하지 않는다. 시드 고정(재현 가능). 화면 연결은 OPT05/06.
