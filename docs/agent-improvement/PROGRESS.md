### 편성표 뽑기 핵심 결론 (근거 `IDEAL_SCHEDULE_AUDIT.md`)
1. "+80%"는 `이번 안 기대 ÷ 비교 기준 주(CURRENT) 같은 모델 기대 − 1`로 정의상 후보 예측 ÷ 과거 실적이 아니다(T04 요구와 일치). 다만 분모·분자 커버리지와 표본 내 평가 때문에 숫자의 의미가 보장되지 않는다.
2. 최적화 목적함수는 기대 시청률이 아니라 fitness 가중 `value`(기본 가중치 35/20/20/10/5/10). "시청률 우선안(KPI 100%)"은 예측 특징을 약화하지 않고 목적함수만 바꾸며 패널티는 남는다.
3. 탐색은 결정적이지만 요일 순차·국소탐색 중심이며 최적성·시간예산·취소가 없다.
4. 검증은 "방송된 배치의 다음 방영 예측"만 있고 탐색기가 새로 만든 배치·AI 모드·기준모델 비교는 없다.

## 단계 01 기록 — 닐슨 수집·파서·데이터 버전 체계 (상세 `INGEST_DESIGN.md`)

### 달라진 동작
- **일간 날짜**: 시트 "분석기간"이 1차 근거. 파일명 날짜와 다르면 적재 거부(예전엔 파일명만 보고 다른 날을 덮어쓸 수 있었음). 시트에 날짜가 없으면 파일명 폴백+경고. 파일명에 날짜가 없어도 시트로 적재 가능.
- **동일 파일 재업로드**: 해시·파서 버전이 같으면 아무것도 지우지·넣지 않고 "변경 없음". 수정본은 개정 번호와 달라진 채널×타깃 건수를 표시. A→B→A 되돌리기는 정상 변경 처리.
- **삭제 후 삽입 안전장치(F07)**: 삭제 전 해당 날짜 백업, 백업 실패 시 중단, ratings 삽입 실패 시 이전 데이터로 복구. 경쟁채널 테이블 실패는 숨기지 않고 부분 성공(`partial`)+경고로 표시.
- **검증 경고(적재는 막지 않음)**: 타깃상세↔경쟁시트 같은 방송 시청률 교차 검증(F: 타깃 열 매핑 오류 탐지), 채널 KPI 타깃 누락, 주간이 월~일 7일이 아닌 경우, 월간 잠정 어댑터 표시.
- **주간·월간**: nielsen_period_rank에만 쓰며 programs·ratings 불변(테스트로 확인), 순수 함수 `buildPeriodRecords`로 분리.
- **메일**: 수집 경로(source·message_id)를 원장에 남기고, error 메일 재시도(30분 간격, 3회 상한 후 dead-letter 표시, 선점은 조건부 UPDATE).
- **관리자 업로드 화면**: "변경 없음", 개정 번호, 경고, 일부 실패를 표시.

**산출물:** `docs/agent-improvement/OPT_PIPELINE.md`(실제 식·분기·경로, 기준선 재현 결과와 불일치 원인, 위험 우선순위), `scripts/opt01-trace.ts`(합성 세계 실험, `npm run opt01:trace`), `scripts/opt01-run-audit.mts`(저장 run 분자·분모 분해 — 사용자 실행용 읽기 전용, 이 작업에서는 실행하지 않음), `src/lib/idealSchedule/comparison.ts`+`scripts/test-opt01.ts`(`test:opt01` 20).

**핵심 발견**
1. 개선율은 같은 모델의 기대값끼리의 비율이다(실적 대비 아님). 분자·분모는 서로 **다른 시간 범위의 평균**일 수 있다 — 기준 주의 방영 기록·시청률 공백은 분모에서 빠지고 이번 안은 일주일이 채워진다. 합성 실험: 기준 주 프라임 50% 공백 시 같은 시간 기준 +1.7%가 보고 +13.5%로, 80% 공백은 +24.3%로 부풀었다.
2. 모델의 낙관 편향(고르면서 부풀림)은 합성 세계에서 **작았다**(차이 없는 세계 보고 +1.6%·정답 0%, 차이 있는 세계에서는 보고가 정답보다 오히려 작음 — 수축 효과). 단, 모델이 맞는 구조의 세계라 실제 채널 결과가 아니다.
3. 최적화 목적함수는 `value`(점수), 보고 지표는 `expected`. 기본 가중치(KPI 35%)는 합성 세계에서 시청률 우선보다 정답 개선율이 1.3~2.0%p 낮았다. 요일×시·추세 성분 중복 반영의 가시적 손해는 못 찾음(실제 데이터 재측정 필요).
4. 수동 교체는 권리 판정을 거치지 않는다(코드 확인). 기존 모델 검증 버튼은 엔진 전체를 실행하고 *새 편성안을 저장*하며 기준 모델 비교가 없다. 장르맵·설정·제약·업로드 편성표는 현재 값(available_at 없음).
5. 저장된 ENA Play 10/5~10/11 사례(0.047/+80.2%, 0.048/+82.0%)는 **복원하지 못했다**(원시 값은 운영 DB에만 있음). 기준 9/14는 추석·개천절 때문에 `pickCurrentWeek`가 3주 전을 고른 것으로 보이며(공휴일 목록 확인 필요), 0.047/0.048은 수동 교체 재계산 전 재합산과 저장 요약의 차이 또는 재계산 새 run일 가능성 — 가설로만 기록하고 확인 방법(`opt01-run-audit.mts`)을 남겼다.

**수정한 것(명백한 집계·표기 오류, 회귀 테스트 포함)**
- 개선율을 두 편성 모두 평가값이 있는 **같은 요일·분**만으로 계산(`compareOnCommonSupport`)해 기본 표시("같은 시간 기준 {기준 주} 대비 +x%")로 쓰고, 평가 시간이 다르면 상태 띠에 분 수와 영향(%p)을 안내. 수동 교체 후에도 저장 블록에서 같은 값. 변이 8종 검출.

**남은 제한·다음:** 실제 데이터로 검증하지 못했다(운영 DB 미접근). 장르맵·설정·제약의 버전 관리(available_at)는 OPT02, 시간순 검증·기준모델 비교·합격선은 OPT05, KEEP 모드 31~44초(합성) 탐색 시간은 OPT04. **다음: OPT02.**
