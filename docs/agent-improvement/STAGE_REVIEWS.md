# 페르소나 에이전트 검토 결과 (2026-10-06)

사용자 지시: "적절한 Agent 페르소나들을 불러서 지금 지시한 07단계가 더 좋아지는 게 맞는지 확인하고, 앞으로의 단계도 계속 진행 시 개선되는 것이 맞는지 확인". 에이전트는 읽기 전용으로 검토했고 보고는 모델 출력이므로 아래는 **제가 코드·지시서로 확인한 뒤 옮긴 것**이다(확인 못 한 것은 '추측'으로 표시).

## 2. 앞으로의 단계 검토 (UX 리서처·통계학자·모델 QA)

### 사용자 확인이 필요한 항목(에이전트 판정 + 제가 코드로 확인한 충돌)

- **08 채널 분석**: 지시서 1번(요약/시간대/콘텐츠/시청타깃/편성제안/데이터·방법 6분할)이 현재의 '8대 질문' 구성(2026-08-20~09-23 사용자 지시)을 바꾼다 → 퇴보 위험. 권고: 8대 질문 틀 유지, 하단 표 접기·차트 라벨·접근 가능한 수치표를 그 안에서 적용.
- **10 주간 편성 비교**: 기본 '왼쪽=지난주/오른쪽=이번주'(2026-09-22), 스크롤 없는 한 화면(09-20), 사용자가 다듬은 색 체계와 충돌. 권고: 라벨에 실제 날짜 병기, 새 색 모드는 선택 토글.
- **13 구매 검토**: '경제성(최대구매가·ROI)'은 CLAUDE.md 범위 밖(ROI 직접 계산 금지). 권고: 해당 항목 제외.
- **15 일괄 마감**: '시청률 자판기' 이름·아이콘은 사용자 지정, '도달율'·'컨텐츠'는 사용자 표기, 전역 폰트 통일은 매거진 디자인을 흔듦. 권고: 병기·감사 보고 위주.
- **OPT05/OPT06**: 승격 허용치·변경 허용 슬롯 수·확정 준비 권한은 정책 수치라 사용자 결정 필요.

### 수정 후 진행(지시서 보완 제안)

- **09**: '채널별 TOP3 ACTIONS'의 priorityScore 정렬(2026-09-18) 유지, 임원 핵심 결정 3건은 기존 Action에서 파생, Avail 공유풀은 계약 해석 확인 전 '조건부'.
- **14**: 새 ReportSnapshot을 만들지 말고 기존 FlatReport(웹·Word·PPT 단일 원본)에 불변 ID·cutoff만 추가, 빈 항목 숨김 규칙 유지, 8~10장 PPT는 별도 '임원 요약본' 옵션.
- **11/OPT02/OPT05(통계)**: 평가 단위는 방영일·프로그램 군집, 쌍체 차이 CI와 최소 유의 차이·최종 holdout 1회 사전 고정, 최대값 선택 편향 측정, `certaintyOf`가 재방을 독립 표본으로 세는 문제, 장르맵·설정·planRows의 available_at 버전관리, 개선율은 '모델상 개선율'로만 표기.
- **OPT03/OPT04/OPT06/16(모델 QA)**: OPT03은 OPT05 이후 확정(그 전엔 T01~T12·완전탐색 검증기만), 수동 교체(`swapBlock`·`addManualCandidate`)에 **권리 검사가 없어 Avail을 우회** → OPT06 첫 작업으로 수정, seed·반복 예산을 지문에 포함, 16단계 수용 기준에 '수동 경로의 권리·잠금·필수 위반 0'·T01~T12·기존 138+개 회귀·취소·timeout 시 이전 안 보존·지문에 모델·데이터·권리·정책 revision 포함 추가.
- **12**: OPT로 대체(중복 구현 금지).

한계: 에이전트는 DB·브라우저 없이 코드만 읽었다. 모바일·데이터 분포·실제 사용 빈도는 추측이다.

## 3. 단계 10 검토 (UX 리서처·코드 리뷰어) — 모두 "수정 후 진행"

에이전트는 읽기 전용으로 검토했고 보고는 모델 출력이므로 코드로 확인한 뒤 반영했다.

| 지적 | 조치 |
|---|---|
| 포커스 링이 인라인 윤곽선에 가려져 방향키 이동 중 위치가 안 보임 | 윤곽선을 모두 클래스로(선택·포커스·기본), 테스트·변이 검출 |
| 첫 조회가 실패하면 "불러오는 중"에서 영구 정지(모달·관리자 경로) | 주 정보 없이도 실패 화면과 다시 시도 |
| 수동 교체 뒤 상태 띠의 교체 건수·권리 경고가 저장 요약(생성 시점) 기준이라 틀림 | 현재 블록에서 직접 센다(`countManualOverrides`), 필수·잠금도 상태 기준 |
| 엑셀이 교체 이전 값·고정 '지난주' 사용 | 교체 반영 합산·작업 상태 행·기준 주 표기 |
| 채널 전환 직후 이전 선택이 URL에 써짐 / 늦은 응답이 새 선택을 덮음(업로드 갱신 포함) | `forChannel` 가드, 좌우 요청 순번, 업로드 갱신 채널 가드 |
| 오류 화면에 이전 주·채널 통계 잔존 | 재조회 시작 시 비움 |
| 범례: 경쟁채널은 계산식이 다름 / 타깃 다름 / 차이 모드는 거울 / 도움말 중복 | 문구 분기·경고·한 번만 표시, 설정 막대 고정, 대비 상향 |
| 인쇄에 색 기준·보기 조건이 빠짐, 선택 윤곽 인쇄 | 인쇄 전용 한 줄, 인쇄 시 선택 윤곽 끔 |
| 경쟁채널 코드 검증이 한글 긴 이름을 버리고 깨진 %를 통과 | 길이 상한 확대 + 디코딩 확인, 서버 디코딩을 try 안으로 |
| 잘못된 날짜가 화면 전체를 죽일 수 있음 / 기본 주가 UTC | 날짜 검증 후 원문 반환, KST 기준 기본 주 |
| 같은 주·다른 구성이 '같은 편성표'로 안내됨 / 차이 0이 거짓 안내 | 별도 모드·"차이 없음" 문구 |
| 큰 변경 경고가 가장 눈에 띄는 숫자 옆·인쇄에 없음 / 칸 비율만 사용 | 요약·제목·출력 머리글 배지, 칸 또는 방송분 기준 |
| 로빙 tabindex 없음, 패널이 이동한 칸을 따라가지 않음, 가장자리 방향키가 가로 스크롤 차단 | 로빙 tabindex, 패널 따라가기, 이동할 칸이 있을 때만 차단 |

미반영(후속): 지시서 5·6번의 undo/redo·변경 이유·revision 분리·권리 위반 건수(DB 필요 — OPT06), 오른쪽 "없음" 주의 URL 복원, `weekly` 라우트의 임시 타깃 라벨 공유, 이전 편성안 목록이 다른 편성안의 저장값을 쓰는 점(현재 편성안만 교체 반영).
