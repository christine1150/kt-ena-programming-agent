# Avail(권리) 표준 모델과 실제 파일 어댑터 노트 (단계 06)

소스: `src/lib/avail/*`, 테스트 `scripts/test-avail.ts`(`npm run test:avail`), 마이그레이션 `supabase/migrations/20261013010000_avail_rights.sql`(작성만, **미적용**).
설계 요구는 패키지의 `05_Avail_설계명세.txt`(A01~A19)이며, 실제 계약 조건·가격은 어느 파일에도 넣지 않았습니다.

## 1. 현재 검증 상태(화면의 '검증 상태'와 같은 문구)

| 영역 | 상태 | 내용 |
|---|---|---|
| 표준 모델·판정 엔진 | 검증됨 | 합성 사례 A01~A19 + 경계·해석·원장 규칙 테스트 |
| 콘텐츠별 Avail(260930 형식, '소재' 시트) | **일부 검증** | 실제 파일 1건으로 열 이름·값 형식을 확인. 계약 해석은 권리 담당자 확인 전 |
| 채널별 Avail | **미검증** | 실제 파일을 받지 못함. 표준 양식으로만 입력 가능 |
| 사용 원장 DB 처리 | 일부 검증 | 규칙은 메모리 저장소로 검증. SQL 함수(advisory lock)는 로컬 Postgres가 없어 실행 못 함 |
| 편성표 뽑기 연결 | 일부 검증 | 엔진 게이트·selector 구현. Avail 미입력이면 현재 동작 그대로 |

## 2. 표준 모델

| 개념 | 구현 | 비고 |
|---|---|---|
| Content | `ContentRef`(제목·정규화 키·소재코드·별칭·제작년도·오리지널 표시·회차당 분·편수) | 별칭은 검색 보조. 시즌·편집판·제작년도가 다르면 자동 병합 안 함 |
| Grant | `Grant`(grantId=원본 행의 안정 ID, revisionId=grantId#원본 열 해시) | 같은 행 재업로드 = 같은 revision. 내용이 바뀌면 새 revision이 이전 것을 대체하고 이전 것은 남음 |
| Scope | 회차 범위·허용 채널·시즌·편집판·territory | 회차를 못 읽으면 unknown(원문 보존) |
| Rules | 방수·요일·시간대·금지기간·재방 간격·회차 순서·방영범위·1st window 순서 | 값 없음은 `value / unbounded / not_applicable / unknown`으로 구별. 빈칸 ≠ 무제한 |
| UsageLedger | reserve / consume / release / cancel 이벤트(삭제·수정 없음) | 멱등 키·실적 이벤트 ID 중복 방지 |
| EligibilityResult | 상태·사유 코드·사유 문장·충족 규칙·없는 필드·근거 revision·원본 행·가정·잔여·만료일·권리 목록 버전 | |
| 시간 | 권리 유효기간(window) / 반영 시점(enteredAt) / 당시 알던 시점(knownAt) 분리 | A16·A19 |
| 비용 | `OptionalCommercial`(선택). 비어 있으면 가격 미확인 | 0원으로 보지 않음 |

판정 상태는 `available / unavailable / conditional / unknown` 네 가지이며 하나의 boolean으로 줄이지 않습니다.
권리 행에 붙은 메모·홀드백·승인 조건은 **확인 기록(Confirmation)** 이 있어야 풀립니다. 확인은 확인한 시점의 원본 행 해시에 묶여, 행이 바뀌면 효력을 잃습니다.

## 3. 실제 파일(Contents Availlist_260930)에서 확인한 사실

- 시트 3개: `소재`(24열, 1,164행, 소재코드·ID 있음)와 `9월시작`·`10월종료`(같은 행을 다시 보여 주는 보기 시트, 소재코드 없음). 어댑터는 **헤더로 시트를 판정**하고, 보기 시트는 본 시트의 같은 행이면 가져오지 않습니다(이중 반영·횟수 합산 방지, 명세 A10).
- 열: ID, ID_거래처, 장르, 소재코드, 소재명, 국가, 화질, 년수, 방수, 편수, 편분, 방영 시작일, 방영 종료일, 방영권 적용, 방영채널1~3, 홀드백 해제, 회차, 방영범위, 계약번호, 메모, 총분, 총시간. `국가`는 국내/해외(콘텐츠 원산지)이지 방영 지역(territory)이 아닙니다.
- 날짜는 엑셀 일련번호. 종료일 `2958434`·`2958465`(9999년)는 "영구/무제한" 표지이며 년수 "영구" 231건과 일치합니다.
- 종료일 규칙: 종료일이 있는 행 중 **시작일 + 기간 − 1일(종료일 당일 포함)** 과 일치하는 비율이 약 97%입니다. 그래서 새로 구매한 작품의 종료일은 이 규칙으로 계산했고, 파일에 이미 있는 값과 같았습니다(시작일이 서로 다른 2건을 뺀 21건 일치).
- 방수: `4방` 같은 횟수 841건, `제한없음` 323건. **단위(회차당 합산인지 채널별인지)는 파일만으로 알 수 없습니다.**
- 방영권 적용: 편성일기준/각회차별 401, 시작일지정/회차일괄 327, 제한없음 231, 편성일기준/회차일괄 155, 시작일지정/회차그룹별 23, 시작일지정/각회차별 18, 제공일기준/회차일괄 7, 편성일기준/회차그룹별 2.
- 회차 표기: `#1~12`, `#320~350, #337제외`, `#412~453 #419~424, 435~440제외`, `#62~65, 66, 67, 72~125`, `#회차선택`(114), `#회차셀렉`(9), `#브랜디드 블록`, `#Regular` 등. 읽을 수 없는 조각이 하나라도 있으면 범위 전체를 unknown으로 둡니다(**152건이 회차 unknown**).
- 방영채널: ENA, ENA DRAMA, ENA PLAY, ENA STORY, OLIFE, ONCE, skyUHD, CHING, ONT, 헬스메디, sky A&C, SKYHD, SkyHealing, ALL, `-`. 첫 칸이 비어 있는 9건은 채널 unknown입니다.
- 방영범위 약어: `위/케/IP`, `위/케/IP/모N`, `위/케/IPTV/N`, `Basic+Premium TV`, `지/위/케/인/모` 등. 약어 풀이는 **제안**일 뿐이며, 케이블·위성·IPTV를 모두 포함한다고 풀리지 않으면 '확인 필요'입니다.
- 메모 386건(예: "총 7개 채널", "SBS 종영 후 1개 채널", "10년 후/방영횟수 추가 시 양사 협의")과 홀드백 329건은 구조화하지 못해 **확인 조건**으로 남깁니다. 조건이 없는 행은 616건입니다.
- 같은 계약참조·같은 회차 범위의 중복 의심: 8쌍(`걸어서세계속으로` 4행, `삼국지`·`장군재상` 시리즈 등). 합산하지 않고 확인 대기에 올립니다.
- 원본 이상값(어댑터가 경고로 남김, 197건): 종료일이 시작일보다 빠른 행 3, 회차 범위와 편수가 다른 행 33, 읽을 수 없는 회차 표기 다수. **원본을 고치지 않고** 해당 값을 '미확인'으로 둡니다.
- 자체 제작(오리지널) 드라마(신병4·연애박사 등)도 이 파일에 있으며(10년·50방, 메모 "10년 후/방영횟수 추가 시 양사 협의"), **Avail 행이 있으면 오리지널이어도 항상 행이 우선**입니다. 행이 없을 때만 오리지널 설정(예능: 제한 없음, 드라마: 판권 기간이 있어 Avail 확인 필요 — 운영자 진술)이 쓰이고 결과에 가정이 표시됩니다.

## 4. 권리 담당자에게 확인받아야 하는 해석(화면 '계약 해석 확인')

확인 전에는 가능한 해석을 **모두** 적용해 평가하고, 결과가 모두 같을 때만 단정합니다. 갈리면 `conditional`이며 어떤 해석 때문인지 사유에 표시됩니다.

1. 종료일 당일 포함 여부(파일 통계는 포함 쪽)
2. 기간 검사 기준: 달력 시각 / 닐슨 방송일(25:30 편성의 날짜)
3. 자정을 넘어 만료되는 방송: 시작만 기간 안이면 되는가 / 끝까지 안이어야 하는가
4. 방수 단위: 회차당 전 채널 합산 / 채널별
5. 1st window 최초 방송 이후 허용: 회차마다 / 작품 첫 방송 한 번

그 밖에 확인이 필요한 항목: `편성일기준`이 회차별 최초 방영일부터 기간을 센다는 뜻인지, `ALL`/"총 7개 채널"/"후방채널" 메모의 의미, 방영범위 약어, 홀드백 문구의 효력 시점, ID_거래처(예: 15가 자체 제작인지)의 의미.

## 5. 영미 드라마 1st window 신규 구매 23건(운영자 전달 2026-10-06)

원본 Avail 파일(소재코드 D26081201~23)에 **이미 있는 행**에 보충 속성을 붙였습니다: 1st window 채널 순서 규칙(1st window 채널이 최초 방송한 뒤 다른 채널 방영 가능), 영문 제품명 별칭, 제작년도(아마데우스 `2025/26`만 전달됨), 신규 구매(기소진 0)·전 채널 방영 가능 확인 기록. 원본 값은 덮어쓰지 않습니다("Avail list가 항상 우선").

원본과 전달 목록의 불일치(원본을 따르고 해당 4건은 확인 기록에서 제외):

| 작품 | 항목 | 원본 | 전달 목록 |
|---|---|---|---|
| 슈츠 LA 시즌1 | 편수 | 13편 | 6편 |
| 라브레아 시즌3 | 편수 | 6편 | 13편 |
| 유령마을 | 시작일 | 2026-11-01 | 2026-11-15 |
| 올 허 폴트 | 시작일 | 2026-08-31 | 2026-12-15(연도는 전달 문구에 없어 2026으로 추정) |

또한 전달 내용은 "자유롭게 방영"이지만 원본에는 방수 9방 제한이 있습니다. 순서 제한이 없다는 뜻인지 횟수 무제한인지 확인이 필요하며, 지금은 **원본(9방)을 따릅니다**. 제작년도 22건은 입력 전입니다(리메이크·다른 판을 가르는 데 중요).

## 6. 거래 경계(원장)

- 초안 생성·상세 조회·시뮬레이션·권리 평가 API는 원장을 읽기만 합니다 — 횟수를 소진하지 않습니다.
- `reserve`: 편성안이 '확정 대기'로 저장될 때만(편성안 revision 단위, 같은 키는 한 번만). `consume`: 실제 방송 실적(source_event_id)이 들어올 때. `release`: 편성 변경·취소로 예약을 풀 때. `cancel`: 방송불발·편성취소. `restore`: undo(잔여를 다시 검사).
- 마지막 1회 경쟁: "풀 잠금 → 잔여 계산 → 기록"을 하나의 원자 구간으로 둡니다(DB는 `avail_reserve_usage` SQL 함수 + advisory lock). 메모리 저장소로 두 편성자 동시 예약에서 한 건만 성공함을 테스트했고, 잠금을 없애면 중복 예약이 실제로 생김을 대조 테스트로 확인했습니다.
- 방송불발·부분방송의 카운트 정책은 아직 계약별 설정이 없어 불발은 취소 이벤트로 되돌리고, 실제 방송된 사실은 한도를 넘어도 기록하되 '초과'로 표시합니다.

## 7. 한계

- 마이그레이션 `20261013010000` 미적용: 적용 전에는 Avail 업로드·권리 판정·원장이 작동하지 않고(화면에 '미적용' 표시) 편성표 뽑기는 지금처럼 동작합니다. 적용 후 `docs/ops/avail-ledger-sql-check.sql`로 SQL 함수를 확인해야 합니다.
- 과거 방영 실적(닐슨)에서 기소진 횟수를 자동으로 채우지는 않았습니다. 새로 구매한 묶음은 '기소진 0' 확인으로, 그 밖의 권리는 확인 전까지 '잔여 횟수 단정 불가'(조건부)입니다.
- 시스템 프로그램 ↔ Avail 제목 연결은 이름이 정확히 같고 표지 충돌이 없을 때만 자동입니다. 실제 프로그램 마스터와의 연결률은 운영 DB를 읽지 않아 측정하지 못했습니다.
- 채널별 Avail 실제 양식 어댑터, 권리 갱신 영향 알림 화면, 편성안 화면의 '재검증 필요' 표시는 후속(10단계·OPT06·13단계)입니다. 엔진과 API는 준비되어 있습니다.
