작성 2026-10-07 · 도구: `scripts/opt05-bench.ts`(`npm run opt05:bench`, 빠른 확인은 `-- --quick`), `src/lib/idealSchedule/{adoption,promotion}.ts`, 시험 `npm run test:opt05`(46).

## 1. 검증 A — 실제 방송에 대한 예측 정확도

방법: 목표 주마다 그 시점에 알 수 있던 방영만으로 예측하는 rolling-origin(OPT02 하네스). 앞쪽 절반 목표 주는 튜닝, **뒤쪽 절반(최종 holdout)에서 한 번 보고**. 합성 세계 4개(프로그램 34개·40주·목표 주 24개/세계), 타깃 2개(수도권 2049, 전국 유료가구). 단위는 시청률 %p.

### 1-3. 극단값에 대한 강건성(OPT02 T05 발견 확인)

방영의 1%를 6배로 부풀린 세계에서 MAE(2049, 전날): 현재 모델 1.700 → 2.055(+21%), 같은 슬롯 8주 평균 2.132 → 2.458(+15%), **중앙값 2.185 → 2.405(+10%)**. 중앙값은 극단값에 덜 흔들리지만 현재 모델이 두 기준보다 계속 낫다. **슬롯 baseline을 중앙값·leave-one-out으로 바꾸는 변경은 채택하지 않는다**(깨끗한 세계에서 오히려 나쁘고, 이득은 극단값이 많은 경우에만 있다 — 실데이터에서 극단값 비중을 확인한 뒤 재검토).

## 2. 검증 B — 탐색 품질과 낙관 편향

같은 예측표(같은 합성 세계·같은 학습 자료)에서 기존 편성·탐욕 구성만·탐욕+국소탐색·AI 시간 최적화를 비교한다. "정답 개선율"은 합성 세계의 잡음 없는 값으로 센 것이다. 세계 4개 평균.

### 2-1. 편성안 비교 — 매주 편성이 바뀌는 세계(프로그램·슬롯 효과를 분리해 학습 가능)

| 편성안 | 보고 개선율 | 정답 개선율 | 낙관(보고−정답) | 선택 블록 예측 편향 | 제약 위반 | 바뀐 분 | 시간 |
|---|---|---|---|---|---|---|---|
| 기존 편성(지난주 실제) | 0% | 0% | — | −0.1% | 0 | 0% | — |
| 탐욕 구성만 | 28.3% | 22.3% | **+6.0%p** | +5.0% | 0 | 75% | 0.9초 |
| 탐욕 + 국소탐색(기존 틀 유지) | 27.3% | 20.5% | **+6.7%p** | +5.8% | 0 | 77% | 12초 |
| AI 시간 최적화 | 26.2% | 20.5% | **+5.8%p** | +5.1% | 0 | 94% | 1.8초 |

- 선택된 블록의 예측은 정답보다 평균 5% 높다(기존 편성은 −0.1%로 편향 없음) → **고르면서 생기는 낙관(승자의 저주)**.
- **더 오래 탐색해도 실제 개선은 늘지 않았다**(탐욕 22.3% → 국소탐색 20.5%). 국소탐색은 선택 점수(여러 성분의 혼합)를 올리지 기대 시청률을 올리지 않는다(OPT03: 선택 점수 ≠ 기대값).
- 제약 위반은 모든 실행에서 0.

### 2-2. 편성안 비교 — 한 슬롯에 같은 프로그램이 계속 놓이는 세계(두 효과가 섞여 구분 불가)

| 편성안 | 보고 개선율 | 정답 개선율 | 낙관 |
|---|---|---|---|
| 탐욕 구성만 | 3.2% | 12.4% | −9.2%p |
| 탐욕 + 국소탐색 | 3.3% | 13.1% | −9.8%p |
| AI 시간 최적화 | 4.3% | 20.7% | −16.4%p |

프로그램이 늘 같은 슬롯에만 있으면 모델이 "프로그램이 좋은지 슬롯이 좋은지"를 가르지 못해 개선을 **과소 보고**한다(보수적). 실제 채널은 두 세계의 중간이다 — 프로그램을 옮겨 본 이력이 많을수록 낙관 위험이, 적을수록 과소 보고 위험이 커진다.

### 2-3. 후보 수를 늘릴수록 근거 없는 개선율이 커지는가 (매주 바뀌는 세계, AI 최적화)

| 프로그램(후보) 수 | 진짜 차이 0인 세계: 보고 | 정답 | 낙관 | 진짜 차이 σ=0.2 세계: 보고 | 정답 | 낙관 |
|---|---|---|---|---|---|---|
| 5 | 17.5% | 9.7%(슬롯 효과) | +7.8%p | 19.5% | 13.8% | +5.7%p |
| 10 | 8.0% | **0%** | +8.0%p | 12.1% | 6.5% | +5.6%p |
| 20 | 11.8% | **0%** | **+11.8%p** | 25.6% | 20.0% | +5.6%p |
| 40 | 14.8% | **0%** | **+14.8%p** | 34.6% | 31.1% | +3.5%p |

진짜 차이가 없는데도(정답 0%) **후보를 늘릴수록 보고 개선율이 +8% → +14.8%로 커진다.** 기존 틀 유지 모드도 같다(20개, +11.3%). 진짜 차이가 큰 세계에서는 낙관이 3.5~5.7%p로 작다 — 근거 없는 개선율의 위험은 "프로그램 간 진짜 차이가 작은데 후보가 많은" 경우에 가장 크다.

### 2-4. 주간 불확실성: 슬롯 구간을 합산하지 않는다 — 시나리오 구간의 보정(몬테카를로)

엔진 없이 오차 모형을 우리가 아는 시뮬레이션이다. **프로그램 단위로 한 번 뽑은 오차를 그 프로그램의 모든 블록이 공유**(`robustnessCheck`)하는 시나리오로 개선율의 p10~p90을 만들고, 실제(정답) 개선율이 그 안에 든 비율을 본다(명목 80%). 예측 오차 σ는 프로그램 평균의 오차 크기다.

| 오차 σ | 후보 3 | 5 | 10 | 20 | 40 |
|---|---|---|---|---|---|
| 0.05 — 정답이 구간 안 | 79% | 75% | 77% | 79% | 75% |
| 0.10 — 정답이 구간 안 | 77% | 73% | 71% | 74% | 65% |
| 0.25 — 정답이 구간 안 | 75% | 66% | 61% | 53% | **34%** |
| 0.25 — 낙관(보고−정답) | 17.4%p | 25.3%p | 37.5%p | 46.7%p | 63.6%p |

- 오차가 작으면(σ≤0.1, 후보 ≤20) 포함률 71~79%로 명목에 가깝다. **오차가 크고 후보가 많으면 53% → 34%로 무너진다** — 시나리오의 오차 분포는 *선택과 무관한 검증 잔차*라서 "최고값만 골라서 생긴 편향"까지는 덮지 못한다.
- "개선이 양수일 확률 ≥ 80%"라고 말한 시행에서 실제로 양수였던 비율은 σ=0.25에서 84~95%, σ≤0.1에서 94~100%.
- **엔진에 연결했다**: 과거 주 검증 잔차(30건 이상)가 있고 기준(CURRENT) 편성이 있을 때만 `summary.robustness`를 만들고(없으면 만들지 않음, 임의 오차 가정 없음), 상태 띠에 "검증 오차 점검: 개선율 p10~p90, 양수 확률, 근거 부족(C) 비중, 기준에 없는 프로그램 비중"을 띄운다. 문구는 **"고르면서 생기는 낙관을 덜어내지 않은 값이라 보수적으로 읽으세요"**를 반드시 붙인다. 잔차 표본이 20건 미만인 근거 등급은 전체 분포로 대신하고 그 사실을 요약에 남긴다(`pooledGrades`).

## 3. 검증 C — 채택 후 실제 성과 (설계·도구, 실행은 방송 후)

방송 후에만 알 수 있으므로 **이 단계가 만든 것은 기록·대조 도구**(`adoption.ts`)이고 실제 성과는 만들지 않았다.
- **채택 전 고정(봉인):** 모델·특징·장르·제약·설정 버전, 권리 버전, 편성안 입력 지문, 블록별 예상값·근거 등급, 계획 horizon(분모), 비교 타깃, 채택·수정·보류 상태와 **이유(필수)**, 기존 주간 패턴·동요일 슬롯 직전 실제·공휴일·특집·프로모션·경쟁 메모. 봉인값이 달라지면(방송 뒤에 예상값이나 이유를 고치면) `verifyAdoption`이 거부한다.
- **방송 후 대조:** 같은 타깃·같은 분모(타깃이 다르면 거부). 예상·실적이 모두 있는 방송분만 맞추고 대조된 비율(coverage)을 함께 낸다. 직전 주 같은 슬롯 실제는 참고값일 뿐이다.
- **방송하지 않은 대체안(기준안·다른 후보)의 실제 시청률은 관측되지 않았다**고 결과에 명시한다. `causal.claim = "none"` — 단순 전후 차이를 AI의 인과효과로 단정하지 않으며, 채택 시점에 적어 둔 공휴일·특집 등을 "다른 설명 후보"로 같이 보여 준다.
- **저장소는 설계만(DB 변경이 필요해 미적용):** `ideal_schedule_adoptions`(스냅샷 JSON + seal, 불변), `ideal_schedule_adoption_outcomes`(방송 후 대조 결과, 스냅샷 id로 연결). 사용자 승인 없는 실제 편성 실험은 하지 않는다. 가능하면 작은 슬롯군에서의 단계적 시험을 별도로 설계해 승인을 받는다.

| A1 현재 모델 vs 최선 기준(전날) | 1.700 / 2.045 = 0.83배 | ≤ 1.0배 | 필수 | 통과 |
| A1b 같은 비교(마감 7일 전) | 1.829 / 2.189 = 0.84배 | ≤ 1.0배 | 필수 | 통과 |
| A2 |bias| ÷ MAE | 0.118 / 1.700 = 6.9% | ≤ 15% | 필수 | 통과 |

| A5 신규 프로그램 MAE ÷ 전체 | 3.1배 | 2.5배 이상이면 표시 의무 | 표시 의무 | **의무 발생** |

**판정: `UNVERIFIED_REAL_DATA`** — 합성 필수 기준 전부 통과, 그러나 실제 자료 미검증이라 승격하지 않고 현행 유지. 표시 의무 2건(A5·B3b)은 이미 화면의 근거 등급·범위·"탐색된 최선안"·시나리오 점검 경고로 충족하고, 실제 자료에서 σ를 재서 B4를 다시 판정한다.

## 5. 제안 합격선 (승인 대기)

기준선(현재 모델)을 먼저 재서 정한 값이다. **승인 또는 수정해 주세요.** 어떤 값도 "+20% 달성" 같은 실측 근거 없는 목표를 쓰지 않는다.

| 항목 | 제안 | 정한 근거 |
|---|---|---|
| 현재 모델 유지 | 최선 기준모델 MAE의 **1.0배 이하**(전날·7일 전, 모든 타깃) | 현재 0.83~0.88배 — 기준모델을 못 이기면 복잡도를 쓸 이유가 없다 |
| 모델 교체(도전 모델) | 현재 모델 대비 MAE **5% 이상 개선** + 세계 75% 이상에서 우세 + 집단 보호 통과 | OPT02 튜닝 변형 차이(≈0.7%)와 세계 간 편차보다 커야 한다 |
| bias | \|bias\| ≤ MAE의 15% | 현재 7% — 한쪽 쏠림은 선택을 왜곡 |
| 구간 보정 | 80% 구간의 이후 적중률 73~87% | 현재 79% (명목 ±7%p) |
| 집단 보호 | 평가 100건 이상 집단에서 기준모델의 1.1배 이하(어기면 그 집단만 적용 제한) | 현재 모든 집단 ≤ 1.0배 |
| 근거 부족 표시 | 신규·소표본 MAE가 전체의 2.5배 이상이면 근거 부족 표시·넓은 범위 의무 | 현재 3.1배 |
| 유효해율 | 100%(하드 제약 위반 0) | 점수가 높아도 위반 안은 거부 |
| 탐색 시간 | 시간 마감으로 멈춘 실행 ≤ 5%(실데이터 측정) | 마감으로 멈춰도 유효하나 잦으면 탐색을 손봐야 함 |
| 낙관 편향 | 보고−실제 개선율 ≤ 10%p(일반), 진짜 차이 0·후보 20+에서도 ≤ 10%p. 넘으면 단일 숫자 대신 범위·경고만 표시 | 일반 6.7%p, 스트레스 14.8%p(표시 의무) |
| 시나리오 구간 | 실제 개선율 포함률 ≥ 70%. 미달이면 "선택 편향 미반영 범위"로 표기 | σ=0.1에서 71% |
| 변경 부담 | **제한하지 않고 보고만**(사용자 결정) | OPT03 결정 |

`promotion.ts`의 `PROPOSED_THRESHOLDS`가 같은 값을 담고, `evaluatePromotion`이 위 표를 자동 판정한다(HOLD / LIMITED / UNVERIFIED_REAL_DATA / PASS, 시험 포함). 타깃별 성능이 불안정하면 해당 타깃만 적용 범위를 제한하고 현재 모델·기존 틀 유지로 되돌릴 수 있게 한다(집단 제한 규칙).

## 6. 실제 자료로 같은 표를 만드는 법 (사용자 PC)

1. 검증 A: `node --env-file=.env scripts/export-own-airings.mts` 로 내보낸 파일로 `npm run opt02:eval -- --input own-airings-….json --origins 20` (이번 단계의 새 집단·노출이 같은 하네스에 들어 있다). 결과의 MAE·bias·적중률을 `PromotionMeasure`에 넣어 `evaluatePromotion`(source "real")으로 판정.
2. 검증 B: 운영에서 편성표를 뽑을 때 저장되는 `summary`(탐색 보고서·검증·시나리오 점검)로 시간 마감 비율·유효해율을 집계. 정답 개선율은 방송 후에만 알 수 있어 검증 C로 모은다.
3. 검증 C: 채택 시 `buildAdoptionSnapshot`, 방송 후 `settleAdoption` — 저장소 마이그레이션 승인 후.

## 7. 남은 한계

- **모든 수치는 합성 세계 값이다.** 실제 채널의 프로그램 간 차이·오차 크기(σ)·편성 이동 이력은 다르다. 특히 낙관 편향은 "프로그램을 옮겨 본 이력"과 "프로그램 간 진짜 차이"에 따라 +0%p~+15%p로 달라진다.
- 시나리오 구간은 선택 편향을 덮지 못한다(σ가 크고 후보가 많을수록). 선택을 고려한 보정(후보 풀 전체로 선택을 다시 시뮬레이션)은 구현하지 않았다.
- 검증 C의 실제 성과·저장소·작은 슬롯군 단계 시험은 방송 후/승인 후 몫이다. 방송하지 않은 대체안의 실제 시청률은 어떤 방법으로도 관측되지 않는다.
- 합성 세계에는 다회차 시리즈·시즌·프로모션·경쟁 편성이 없어 이 효과를 가르는 검증은 하지 않았다(`회차 연결` 맥락도 시험 밖). 장르·설정·제약·권리의 시간 버전은 여전히 관리되지 않는다(OPT02의 UNVERSIONED_INPUTS).
- 마이그레이션 변경 없음. 승인 대기: 합격선 확정, 채택 기록 저장소 설계.
