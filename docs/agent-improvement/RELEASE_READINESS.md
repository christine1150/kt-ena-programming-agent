# 운영 전환 준비 (단계 16)

이 문서는 "예쁜 화면"이 아니라 **업무 단위로 출시해도 되는지** 판단하기 위한 자료다. 점검 항목은 [TRACEABILITY.md](TRACEABILITY.md), 방송 후 회고는 [RETROSPECTIVE.md](RETROSPECTIVE.md), 운영자 문서는 [../operations/README.md](../operations/README.md)에 있다.

## 1. 결론

- 코드는 이미 운영(Vercel)에 배포되어 있고, **읽기 전용 기능과 서버 쪽 방어는 지금 상태로 쓸 수 있다.** 이번 점검에서 원본과 저장값이 어긋난 곳은 없었다(2026-08-01~10-05 일간 원본 53개 파일, 채널 집계 2,968행 전부 일치, 읽기 전용 점검).
- **출시 보류로 남긴 항목은 8건(H1~H8)** 이다. 이 중 사용자 승인으로 풀 수 있는 것(H4·H5·H7·H8)과 실제 자료가 있어야 풀 수 있는 것(H2·H3), 코드 작업이 필요한 것(H1), 사용자 확인이 필요한 것(H6)을 구분했다.
- 새 기능 수보다 **잘못된 권고 감소·판단 추적·편성 실행 가능성**으로 본 완성도는 TRACEABILITY.md의 상태 표가 기준이다. 목표치를 정하지 않았고, 현재 baseline(아래 측정값)을 운영자와 보고 정한다.

## 4. 단계적 전환

이미 배포된 것은 **되돌리기 쉬운 순서**로 켜져 있다. 아래는 아직 켜지지 않은 것을 켤 때의 순서다(각 단계마다 이전 단계가 안정적일 때만 다음으로).

1. **보안 수정 20261015(H8)** — 멱등이고 서버 접근에는 영향이 없다. 적용 후 편성표 업로드·조회·내보내기를 1회씩 확인.
2. **수집 원장 20261011** — 적재 자체는 원장 없이도 동작한다(최선 노력 기록). 적용 후 다음 일간 파일 1건이 '반영' 상태로 기록되는지 확인. 재수신·수정본 차이가 쌓이기 시작한다.
3. **관리자 운영 20261012** — 수동 목표 잠금·이력·뉴스 이전 버전. 적용 후 잠긴 목표를 Channel Master 재업로드가 덮지 않는지 1건 확인.
4. **검토 기록 20261014** — 홈 결정 카드의 검토 상태 저장. 추가 전용(수정·삭제 불가). 적용 후 '검토 중'을 1건 저장·표시해 본다.
5. **채택 기록 저장소(새 마이그레이션 작성 필요)** — 채택 스냅샷(봉인 포함) 저장. 승인 후 설계대로 작성, 저장·재조회·봉인 검증 확인.
6. **편성안 DB 버전 열(H5)** — 동시 편집을 DB가 거부. 가장 마지막, 격리 DB에서 동시성 시험 후.

각 마이그레이션은 **적용 전에도 화면이 동작하도록** 만들어져 있어(저장만 '미적용' 안내) 적용 순서가 서로 막지 않는다.

## 5. 기존 안 보존

- 저장된 편성안(`ideal_schedule_runs` 29건, 이 중 사용자가 저장한 것 1건)은 어떤 마이그레이션도 수정하지 않는다. 새 열·테이블은 추가만 한다.
- 이미 만든 보고서 스냅샷(4건)은 불변이다. 재발행은 새 ID로 저장되고 옛 보고서는 그대로 남는다.
- 재계산·덮어쓰기는 이번 점검에서 실행하지 않았다. 필요해지면 `npm run dryrun:engine`(읽기 전용)로 영향 범위를 먼저 확인한다 — 아래 6절.

## 6. 읽기 전용 원본 대조와 backfill dry-run

`npm run dryrun:engine -- "Nielsen Data/2026/10"` (DB에는 SELECT만, 원본은 읽기만 한다). 결과(2026-10-08 실행):

| 기간 | 원본 파일 | 비교한 채널 집계 행 | 일치 | 다름 |
|---|---|---|---|---|
| 2026-08-01~08-31 | 31 | 1,736 | 1,736 | 0 |
| 2026-09-01~09-17 | 17 | 952 | 952 | 0 |
| 2026-10-01~10-05 | 5 | 280 | 280 | 0 |

- 영향 채널·기간: **없음**. 다시 반영(backfill)해도 쓸 행이 0개라 이력 갱신 범위도, 사전 계산(마트)·AI 문장 캐시 재생성 범위도 0이다.
- 보고서 재생성 범위: 스냅샷 4건은 불변이라 재생성 대상이 아니다.
- 이 점검이 보지 못하는 것: ① **채널 집계(순위·시청률·점유율·Reach·시청시간)만** 견줬다 — 프로그램 단위 행과 경쟁 채널 행은 이 점검 범위 밖이다. ② 단계 02·03에서 바뀐 **파생 계산**(시간대 배분, 주간 순위 정의)은 저장값이 아니라 조회할 때 계산되므로 '기존/새 엔진 차이'는 저장된 값의 차이로는 나타나지 않는다(정의 변경은 TRACEABILITY의 M·D 항목과 단계 02·03 기록에 있다). ③ 9월 17일 이후 9월 파일 2개(일간 아님)와 9월 18일~30일 일간 파일은 로컬 폴더에 없어 대조하지 못했다.
- rollback(적용이 필요해졌을 때): `src/lib/ops/dryRun.ts`의 `ROLLBACK_STEPS` — 날짜 단위 백업 → 날짜 단위 적용 → 실패한 날짜만 백업으로 → 마트 재계산 → 보고서 스냅샷은 건드리지 않음.

## 7. 기능 끄개(feature flag)

코드를 되돌리지 않고 환경 설정 한 줄로 이전 동작으로 돌아가는 스위치다(`src/lib/featureFlags.ts`). 기본은 켜짐이고, 값을 바꾼 뒤 다시 배포하면 적용된다(Vercel 환경 변수 변경은 새 배포가 필요하다).

| 환경 변수 | 끄면 | 들어온 단계 |
|---|---|---|
| `FEATURE_LLM_TEXT_CACHE=off` | AI 문장 캐시를 건너뛰고 요청마다 새로 생성한다(속도는 느려지지만 이전 동작). | 단계 15 이전(캐시)·15(채널 AI 설명) |
| `FEATURE_REPORT_SNAPSHOT_STORE=off` | 보고서를 저장하지 않고 만든다 — 다운로드는 파일을 만들 때 다시 계산하고 PDF(문서 보기) 버튼은 막힌다(단계 14 이전 동작). | 단계 14 |

더 큰 되돌림이 필요하면 **Vercel에서 직전 배포를 다시 승격(Promote)** 한다 — DB 변경이 없으므로 코드만 되돌아간다. 새 기능은 모두 마이그레이션 없이 들어왔기 때문에(단계 14·15·16) 이 방법이 항상 가능하다.

기능 끄개가 없는 것: 화면 문구·접근성·토큰 변경(단계 15)은 끄개를 두지 않았다. 되돌리려면 해당 커밋을 되돌린다(증감색은 `tokens.ts`·`globals.css`·`highlightNarrative.tsx` 한 곳씩).

## 8. 오류 모니터링과 알림 기준

지금 있는 관찰 수단과, 이상으로 볼 기준(제안 — 운영자와 정한다)이다. 외부 알림 서비스는 연결하지 않았다.

| 무엇을 | 어디서 | 이상 기준(제안) |
|---|---|---|
| 수집 지연·실패·미반영 | 관리자 › 데이터 상태 패널(미수신·실패·미반영·재계산 대기) | 일간 미수신 1일 이상 · 실패 1건 이상 · 재계산 대기 1일 이상 |
| 원본 대조 불일치 | `npm run dryrun:engine`(주 1회 또는 대량 업로드 직후) | 다름 1행 이상이면 원인 확인 전 보고서 재발행 보류 |

| AI 문장 폐기 | 보고서 '전제·한계'의 'AI 요약은 수치 대조를 통과하지 못했습니다' | 같은 채널에서 연속 3회 이상 |
| 보고서 저장 실패 | 보고서 화면 스냅샷 줄('원본 저장 실패' 안내) | 1건이라도 발생하면 저장 테이블 확인 |
| 권리 판정 | 편성 화면 '권리 미확인' 건수 · 확정 준비 검사 결과 | 확정 직전 검사에서 '불가' 1건 이상이면 확정 불가(자동 차단) |
| 구매 추천 낡음 | 구매 검토 화면 '오래된 추천' 표시 | 추천 기준일이 분석 종료일보다 9일 넘게 오래됨 |

## 9. 승인 요청 (한 번에 판단하기 위한 요약)

이미 완성된 배포 차이·검증 결과·영향·rollback을 한 곳에 모았다. **아래는 모두 승인 전에는 실행하지 않았다.**

| 요청 | 배포 차이 | 검증 결과 | 영향 | rollback |
