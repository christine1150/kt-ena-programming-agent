# D-3 — 업로드 편성표 기반 예측의 재구성 검증(마감 7·14일)

작성 2026-10-22 · 읽기 전용(select·읽기 RPC만) · 재실행: `npx tsx --env-file=.env scripts/d3-plan-forecast-backtest.mts <결과 JSON>` (결과 파일은 실제 시청률 포함 — 커밋·외부 전송 금지, 약 30초)

## 무엇을 했나
- 대상: `program_schedule_grid`에 편성표가 남아 있는 채널·주 중 실적이 있는 17개(완전한 주 15 + 실적 3일뿐인 주 2), **111일**. skyUHD 제외(수기 자료).
- 예측: 각 주를 데이터 마감 = 주 시작 − 1 − {7, 14}일(OPT02 규칙)의 자료만으로 `evaluatePlanOnly` 실행. 운영과 같은 설정·장르 맵·과거 검증 잔차(마감 이전 것만)를 읽는다.
- 정답: 같은 주 실제 방영(같은 읽기 RPC)으로 만든 **같은 정의의 집계**(D-2: 편성시간 가중 평균). 공식 채널 하루 값과는 비교하지 않았다(D-2에서 정의가 다름을 확인).
- 기준모델: 같은 마감에서 **같은 요일·시 최근 28일 방영 평균**(없으면 같은 시, 없으면 채널 평균, 공휴일 제외) — OPT02에서 가장 강했던 단순 기준. 같은 편성표 칸·같은 집계로 계산.
- 칸 대조: 같은 방송일 + 시간 겹침 + 같은 작품만 MATCHED(`matchSlots`). 칸별 오차는 MATCHED만.

### 이 검증의 성격 — "재구성 계획 검증"
- 편성표 17주 중 **주 시작 전에 올라온 것은 6주(41일)** 뿐이다. 나머지는 주 중·주 후에 올라와 실제 편성이 반영됐을 수 있다 → 표를 둘로 나눠 냈다.
- 편성표의 매칭 program_id(방송 후 실적으로 붙인 값)는 쓰지 않았다(이름으로만 후보 연결).
- 시리즈 연결·경쟁 자료·권리 조건은 넣지 않았다.
- 표본이 작다(채널당 3~45일). 아래 숫자로 모델 승격·교체를 판단하지 않는다.

### 덮인 시간
예측은 하루 평균 23.0시간을 덮고(그중 마지막 칸의 방송일 끝 가정 0.9시간), 실제 집계는 20.4시간이다. 편성표에는 광고·브릿지 구간이 없어 칸이 그 시간까지 이어지기 때문이다(D-2와 같은 원인). 월요일은 새벽 시간대가 앞 주 편성표 소관이라 덜 덮인다.

## 해석과 결정

1. **일 단위 예측은 지금 단순 기준(같은 요일·시 최근 4주 평균)보다 낫지 않다.** 일별 실제 집계 자체가 크게 출렁여(작은 채널은 하루 사이 몇 배) 상대 오차가 30% 안팎이다. 화면에서 일·주 예측을 보여 줄 때는 **기준모델 값을 함께 보여 주고, "검증 결과 단순 평균과 비슷한 수준"임을 적는다.** 모델 값만 단정적으로 보여 주지 않는다.
2. **칸 단위에서는 약간(약 4%) 낫고, 이득은 B 등급(프로그램 이력을 다른 시간대에서 가져오는 경우)에서 나온다** — 편성 이동·새 칸 배치를 판단할 때 쓸모가 있다는 OPT02 합성 결과와 방향이 같다. 크기는 합성(−17%)보다 훨씬 작다.
3. **가장 큰 개선 여지는 신규 작품(C)이다.** 이 기간 ENA는 신작이 많아 C 칸이 44%였고 높게 예측하는 쪽으로 치우쳤다. 개선 후보(검증 후 승인 대상, 지금 적용하지 않음):
   - 편성표 이름 ↔ 닐슨 이름 연결 보강(표기 차이로 C가 된 칸 줄이기) — 위험이 낮고 먼저 할 일.
   - 신작 C 칸의 기대값을 장르·채널 기준 대신 "그 칸의 최근 평균"쪽으로 더 당기는 방식 — 채널별로 결과가 엇갈려(ENA는 현행이 낫고 ONCE는 기준이 낫다) 표본이 더 쌓인 뒤 판단.
   - 시리즈 연결 목록 확대(지구마불4처럼 지난 시즌이 있는 신작).
4. **주 시작 전에 올린 편성표로만 본 성적(41일)이 진짜 "계획 단계" 성적에 가깝다.** 지금은 표본이 너무 작다 → 승인 항목 A2(편성표 업로드 시 예측 자동 고정 저장)를 켜야 정직한 사전 예측 표본이 쌓인다.
5. 마감 7일·14일 차이가 작으므로 예측은 1~2주 전에 해도 정확도 손해가 거의 없다(이 표본 기준).
