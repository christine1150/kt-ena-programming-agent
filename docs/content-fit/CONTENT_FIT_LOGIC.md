# 콘텐츠 적합도(CONTENT FITS) 논리 재설계

작성 2026-10-14. 모델 버전 `content-fit-v1`.
코드 `src/lib/contentFit/`, 단위 테스트 `npm run test:content-fit`, 연구·재현 스크립트 `scripts/content-fit-research/`(README 참고).

## 요약
- **계기**: ENA Drama 화면에서 `<벌거벗은세계사>`(57일 방영, 2049 시청률 상위)가 `<ENA케이팝업차트쇼>`(5일 방영, 시청률 약 1/4)보다 낮은 종합 점수를 받았다. "시청률이 나쁜 채로 쏠림 없이 안정적이라는 것이 그 콘텐츠를 계속 트는 이유가 되면 안 된다"는 지적이었다.
- **원인(검증됨)**: 종합 점수의 한 축인 "타깃 선호도"가 타깃 적합도가 아니라 **30대 시청 비중의 역수**였다. 여기에 ① 점수끼리 서로 보상하는 평균 구조, ② 슬롯(자리) 품질이 성과 점수에 섞이는 문제, ③ 데이터가 없을 때 중립(50)으로 채우는 처리, ④ 5개 태그가 정식 판정 대상의 97%를 이동·교체 검토로 몰아 변별하지 못하는 문제가 겹쳤다.
- **새 논리**: "같은 요일·시간대의 다른 프로그램 평균과 비교해 얼마나 잘했나(슬롯 대비 성과)"와 "채널 평균 방영 시청률과 비교해 규모가 얼마나 되나(시청 규모)"를 같은 비중으로 합치고, 표본이 적으면 평균 쪽으로 보정하며, 몰입도·최근 추세는 제한된 폭으로만 반영한다. 연령 구성은 점수에서 뺐다.
- **결과**: 사용자 사례가 바로잡혔고(벌거벗은세계사 64점 5위 · 케이팝업차트쇼 34점 12위), 우세 쌍 역전이 줄었고, 편성 유지 판별력이 기존 종합(0.631)보다 높다(0.713). 개선의 핵심은 판별력 상승 자체보다 **해로운 요소(선호도)를 없애고, 표본 부족을 따로 다루고, 결과를 "몇 배"로 설명할 수 있게 한 것**이다(§3-5).

## 1. 기존 논리와 재검증 결과

기존: 프로그램마다 **타깃 성과 / 타깃 선호도 / 시청 몰입도**를 "채널 내 프로그램끼리의 순위(percentile 0~100)"로 만들어 단순 평균(`contentFitsHelpScore`)해 정렬했다. 세 값은 SQL `refresh_fit_score_mart`(20260902010000)가 계산한다.
별도로 DB `fit_score`(6항 가중합 30/20/15/15/10/10)와 `tag`(STRENGTHEN≥80, KEEP≥65, MOVE≥50, REPLACE)가 홈·보고서·질의응답·채널 화면 전체에서 쓰였다.

검증 데이터: ENA·ENA Drama·ENA Play(수도권 2049 KPI) + ENA Story·OLIFE·ONCE(전국 유료가구 KPI), 2026-01-01~10-13 ratings 행 약 12.9만 건(수도권 채널은 연령 타깃 행 포함). 읽기 전용 덤프이며 운영 DB는 바꾸지 않았다. 아래 숫자는 `diagnose-legacy.mjs`·`retention.mjs`로 다시 만들 수 있다.

## 2. 새 논리

두 개의 질문에 같은 비중으로 답하고, 표본 신뢰도로 보정하고, 보조 지표는 제한된 폭으로만 반영한다.

```
기대 e_i  = 같은 요일×시(칸) 안 "다른 프로그램"의 방영 평균 시청률
            (칸에 다른 프로그램 방영이 15건 미만이면 요일×시간대 → 시간대 → 채널 전체로 확대; 프로그램 자신은 제외)
슬롯 대비 성과 L = (Σ실제 + m0) / (Σ기대 + m0)         ← 1.0배 = 같은 자리 평균 수준
시청 규모    A = (Σ실제 + m0) / (방영수×채널평균 + m0)   ← 1.0배 = 채널 평균 방영 시청률 수준
m0 = κ × 채널 평균 방영 시청률 (κ=2)                      ← 표본이 적으면 1.0배 쪽으로 보정(경험적 베이즈식 수축)

점수 변환  S(x) = clamp(50 + 25·log2 x, 0, 100)           ← 1.0배=50, 2배=75, 절반=25
핵심 점수  core = 0.5·S(L) + 0.5·S(A)
보정       adj = clamp(0.2·(몰입도점수−50) + 0.2·(추세점수−50), −15, +10)
적합도     = clamp(core + adj, 0, 100)
```

- **시청 몰입도**: 도달률·시청시간 비율을 시청률과 같은 방식(같은 칸의 다른 프로그램 대비, 같은 κ 보정)으로 지수화해 기하평균 → 점수.
- **최근 추세**: 최근 28일 지수 ÷ 이전 56일 지수의 log2(추세 점수 = 50 + 25·clamp(log2, −2, 2)). 양쪽에 방영 3일 이상 있을 때만 계산한다.
- **연령 구성(타깃 선호도)은 점수에서 제외**. 누가 보는가는 설명 정보이지 "자리에 맞는가"의 근거가 아니다. 올바른 정의가 마련되면 설명 정보로 되살릴 수 있다(§5).
- 경쟁 기회·시청 흐름(리드인)도 점수에서 빠졌다. 둘 다 이번 검증 범위 밖이라 근거 없이 판정에 쓰지 않는다.

### 판정(태그)
신뢰 구간부터 정하고, 정식 구간에서만 **슬롯 대비 성과 L**로 판정한다(규모·몰입도는 설명, 추세는 한 단계 강등).

| 구간 | 조건 | 표시 |
|---|---|---|
| 판단 보류 | 방영 3일 미만 | 점수 없음 |
| 참고(표본 적음) | 방영 3~7일, 또는 데이터가 지수에 반영된 비중 < 50% | 점수는 보이되 판정은 `TEST`(표본 적음). 방향(높음/비슷/낮음 — L ≥ 1.2 / ≤ 0.8 기준)만 표시 |
| 정식 | 방영 8일 이상 & 반영 비중 ≥ 50% | 아래 판정 |

정식 판정: L ≥ 1.5 **강화(STRENGTHEN)** / 0.85~1.5 **유지(KEEP)** / 0.55~0.85 **관찰(WATCH)** / < 0.55 **교체 검토(REPLACE)**. 최근 4주가 이전보다 약 30% 이상 하락(log2 ≤ -0.5)하면 한 단계 낮춘다(강화→유지, 유지→관찰). 교체 검토인 프로그램이 **더 좋은 시간대**(기대 시청률이 현재의 1.2배 이상)에서 3회 이상 방영돼 슬롯 평균 이상(L ≥ 1.0)을 냈으면 **이동 검토(MOVE)**와 도착 시간대를 준다. 조건이 엄격해 평가 표본(791건)과 2026-10-13 현황(편성 중 120개)에서 모두 0건이었다.

### 상수와 근거 (`src/lib/contentFit/config.ts`, 재현: `calibrate.mjs`·`sensitivity.mjs`)
| 값 | 근거 |
|---|---|
| κ = 2 | 과거 시점 백테스트에서 이후 28일 실제 슬롯 대비 지수와의 평균제곱오차(MSE)가 κ=1·2에서 최소다(칸 최소 표본 15건 기준 κ1 0.1998 / κ2 0.2000, 보정 없음 κ0 0.2083, κ6 0.2078). 같은 오차라면 표본이 적을 때 평균 쪽으로 더 보정하는 κ=2를 택했다 |
| 칸 최소 표본 15건 | κ=2 기준 M=6 0.2414 → 10 0.2087 → 15 0.2000 → 20 0.2003 → 30 0.2034로 15~20에서 평탄하다. 다른 기준 구조는 각자의 최소 오차도 모두 더 컸다(평일/주말×시 0.2254, 요일×시+평일/주말×시 0.2268, 시각만 0.2334) |
| 종합 50:50, 보정 0.2/0.2, 상한 +10/−15 | "두 질문(자리에 맞는 성과 / 채널에 도움이 되는 규모)에 같은 비중". 규모 비중 0.3~0.7, 몰입도 0~0.4, 추세 0~0.4로 흔들어도 예측ρ 0.589~0.622, 상하위차 0.705~0.738, 우세 역전 1.0~1.3% 범위에 머문다. 가장 나쁜 조합(규모 0.7, 예측ρ 0.589)도 기존 종합(0.547)보다 높다 |
| 정식 판정 8일 | 기존 `TEST` 규칙(표본 신뢰도 50% = 16일의 절반)과 같다 |
| 판정선 0.55 / 0.85 / 1.5 | 아래 §3-2의 실제 편성 유지율이 꺾이는 지점. 강화선 1.3~1.7, 유지선 0.80~0.90, 관찰선 0.50~0.60으로 흔들어도 "강화 ≥ 유지 ≥ 관찰 ≥ 교체 검토"의 이후 28일 편성 유지율 서열이 그대로다(7개 변형 모두) |

## 3. 검증

과거 시점 T(마트에 기준일이 있는 날 중 4~9월 14일 간격: 수도권 3채널 7개씩, 전국 3채널 10개씩, 모두 51개)에서 **그날까지의 데이터만**으로 점수를 만들고, 이후 28일 실적·편성과 비교했다(미래 누수 없음). 재현: `evaluate.mjs`, `retention.mjs`.

|---|---|---|---|

### 3-5. 결과를 읽는 법 — 개선폭의 크기
- 편성 유지 판별력(AUC)은 기존 최고 요소(몰입도 0.700)와 신규(0.713) 차이가 작다. 이 숫자만으로 "훨씬 정확해졌다"고 말하면 과장이다.
- 달라진 것은 ① 이후 실적과 역방향인 요소(선호도)가 사라져 편성 유지 판별력이 기존 종합 0.631 → 신규 0.713으로 올라가고, 선호도가 작동하던 구간의 우세 쌍 역전이 6.0% → 1.0%로 줄었다는 점, ② 표본이 적은 프로그램이 높은 점수로 올라오지 않도록 따로 다룬다는 점(표본일수 상관 0.498 → 0.424, 방영 3~7일은 정식 판정 없이 "표본 적음"), ③ 점수와 판정이 "같은 시간대 평균의 몇 배"라는 한 가지 의미로 설명된다는 점, ④ 정식 판정이 강화·유지·관찰·교체 검토로 고르게 나뉘어 PD가 쓸 수 있는 구분이 된다는 점이다.
- 현재 편성 중 120개(6개 채널, 2026-10-13): 강화 5 · 유지 26 · 관찰 25 · 교체 검토 22 · 테스트(표본 적음) 30 · 판단 보류 12 · 이동 검토 0.

## 4. 바뀐 범위

- **엔진/조회**: `src/lib/contentFit/{types,config,engine,explain,sourceCore,source,tagCache,index}.ts`. 서버 조회는 채널 KPI 타깃의 방영 행(12주)만 읽는다(채널당 0.4~1초). 기존 마트 재계산 RPC(채널당 5~20초, 타임아웃 수정이 반복됐음)에 의존하지 않는다.
- **계산 위치(CLAUDE.md 원칙 1의 예외)**: 원칙 1은 공식 KPI 계산을 DB(SQL 마트)가 전담하도록 한다. 적합도는 DB 원본 행(`ratings`)을 읽어 **서버의 결정적 순수 함수**가 계산하고, LLM·프런트는 계산하지 않는다(원칙의 핵심인 "LLM이 수치를 만들지 않는다"는 지킨다). SQL 마트로 두지 않은 이유: ① 프로그램 자신을 뺀 슬롯 기대치·계층 폴백·표본 보정을 SQL로 옮기면 기존 재계산 RPC처럼 느려지고(채널당 5~20초) 타임아웃 문제가 되살아난다, ② 단위 테스트 55건과 독립 JS 레퍼런스 대조(§3-4)로 검증하기가 SQL보다 쉽다. 나중에 SQL 마트로 옮기게 되면 `parity.mts`와 `test:content-fit`을 그대로 회귀 검증에 쓰면 된다.
- **API**: `/api/scheduling/fit-score`가 새 엔진 값으로 응답한다(`fit_score`=적합도, `tag`=판정, `content_fit`=엔진 원본). 옛 하위지표 6종은 null이다.
- **태그**: 기존 5태그에 `WATCH(관찰)`을 추가했다(`actionTags.ts`). 인사이트 계층에서는 추적 점검(MONITOR)과 같은 의미다.
- **소비처 교체**: 채널 화면 전체(CONTENT FITS 표, 무엇을 편성할까요?, 사분면·포트폴리오 차트, 기회·임원 요약 문장), 홈 액션 배지(채널·기준일별 캐시), 리포트 수집·건강도, 질의응답 슬롯 진단.
- **LLM 해석**: 입력이 슬롯 대비 성과·시청 규모·몰입도·추세로 바뀌었다. 문장 검증기(`narrativeGuard`)가 "N배" 수치도 입력과 대조하도록 보강했다.
- **함께 고친 것**: `koreanizeFitText`의 단어 경계 정규식이 백스페이스 문자로 깨져 영문 태그 치환이 동작하지 않던 오류.
- **DB 마이그레이션 없음.** `mart_scheduling_fit_score`와 `refresh_fit_score_mart`는 그대로 두었다. 이 화면들의 근거는 아니지만, 개편 전 점수와의 비교(§3) 재현에는 이 테이블의 과거 기준일 행이 필요하다.

## 5. 한계와 후속 과제

1. **편성 유지율은 PD의 판단을 완전히 반영하지 않는다.** 시즌 종영·계약 만료·재편성도 '유지 안 됨'으로 잡힌다. 그래서 판정선을 이 값에만 맞추지 않고 슬롯 대비 성과의 의미(평균의 0.55/0.85/1.5배)로 읽히게 했으며, 선을 바꿔도 서열이 유지됨을 확인했다. 운영하면서 실제 결과로 계속 점검할 것.
2. **한 슬롯을 한 프로그램이 독점하면 슬롯 효과와 콘텐츠 효과가 섞인다.** 이때는 기대치가 더 넓은 수준(요일×시간대→시간대→채널)으로 올라가며, 화면에서 "비교 기준 구성"과 "같은 시간대 비교 표본이 적어 채널 전체와 견줬다"를 알린다.
3. **검증 기간이 2026-01~10(약 9개월)뿐**이고 계절·명절·특집은 분리하지 않았다. 개편 전 점수와의 비교는 기존 점수에 유리하게 잡혀 있고(§3-1), 선호도가 작동한 구간은 6개 시점이라 표본이 작다.
4. **연령 구성(타깃 선호도)은 점수에서 뺐다.** WHO IS WATCHING?의 연령 분석은 그대로이며, 프로그램 단위 "핵심 타깃 쏠림"은 올바른 정의(비교 기준 대비 구성비 지수, 표본·분모 조건)가 마련되면 설명 정보로 되살릴 수 있다.
5. **skyUHD**는 타깃 구분이 없어 기존처럼 별도 대체 지표를 쓴다(이번 변경 범위 밖).
6. 리드인 유지율·경쟁 압력은 이 화면의 근거에서 빠졌다(검증되지 않은 지표). 필요하면 같은 방식(이후 실적 예측력 + 안정성)으로 검증한 뒤 다시 넣는다.
7. 에피소드 단위(회차별) 분석은 하지 않았다. 방영 건은 프로그램 단위 행이다.
8. 마트 `mart_scheduling_fit_score`의 과거 행과 `fit_score_config`(가중치)는 더 이상 쓰이지 않는다. 정리(삭제)는 별도 승인 후 신규 마이그레이션으로 하되, §3 재현 근거가 사라지므로 비교 결과를 보존한 뒤에 한다.
